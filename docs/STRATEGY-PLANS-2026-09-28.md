# 战略计划与命令一致性验收 · 2026-09-28

本轮完成三项：统一组合命令校验、结构化跨季计划、固定场景低成本验证。
版本为 pack **2.3.0**、prompt **1.17.0**、save **10**。旧存档需重开。

## 1. 命令校验统一

`OrderBudget` 由玩家选择预览、模型准入、各类规则机器人和真实结算共用。

- 同一兵源或目标不能重复征伐，同一武将不能同季调往多个地点；撤围与向同一目标增兵互斥。
- 调兵不能和同源出征、集结同时占用兵力；调兵预分配与结算共用 `allocateTransfers`，当季收到的兵不能继续转运。
- 国库、建筑槽位、势力令数、郡令数和免费次数累计预留。未发生的收入不会提前拿来消费。
- 模型按照所选顺序优先采纳合法命令，逐条记录丢弃原因；结算仍按规范顺序执行。页面以中文显示原因。

这里保证的是命令合法、资源不被重复承诺。敌方同时行动仍可能使战果落空，合法命令不等于保证成功。

## 2. 跨季计划落地

新计划保存 `objective / target / stance / preparation / abortWhen / status / review`：目标、目标郡、攻守倾向、准备条件、撤退或调整条件、状态与复核依据。

下一季请求收到上一季计划、实际战报、上季丢令与 `planFeedback`。反馈包含己方疆域和国库；有目标郡时补充公开归属、己方驻军或行军状态，不读取敌方隐藏兵力。坏计划不覆盖旧计划，页面显示警告。旧文字方略仍可用于历史记录回放。

计划在控制者面板、最近决策、存档和日志中可读。页面把模型自述标为“AI 判断”，并另外显示当前事实，不将模型声称完成当作引擎判定。

## 3. 固定场景实测

从 `strategy-cases-0` 的自然机器人对局取局面，不人工加兵或加钱：吕布开局国库紧张、吕布第 3 季围城、公孙度第 4 季多线受敌。每个场景分别运行机器人、GPT-5 nano、Gemini 2.5 Flash-Lite 两季，其余势力均为免费机器人。同一场景各控制者使用相同起始状态，状态哈希已留档。

可核查例子：Gemini 在多线场景攻下北海国，下一季输入的 `planFeedback.ownership` 为 `own`，驻军 1999；它的复核提及夺取北海和丢失东海，随后将目标改为辽东属国。Nano 在围城场景两季复核文字完全相同，说明接通记忆仍不足以保证它正确复盘。

### 提供方兼容与费用

Gemini 初次请求遭遇 400。隔离诊断返回的原因是 JSON Schema 的约束状态数过多；去掉字符串长度约束仍失败，进一步移除 `picks.maxItems` 后相同自然场景成功。候选 `enum` 保留，应用仍硬限 16 条命令及计划字段长度。这个处理也符合 [Gemini 结构化输出文档](https://ai.google.dev/gemini-api/docs/structured-output) 关于复杂 schema 可能被拒绝的说明。

场景脚本固定低价提供方 OpenAI / Google，每次最多 2 次尝试、8000 输出 token、90 秒超时，总计最多 14 次决策调用（包含两次失败）、28 次尝试，并设 **$0.20** 保守费用闸门。每次执行前检查当前价格与载荷大小。

- 场景成功响应上报费用合计 **$0.02218085**。
- 两次小 schema 诊断合计 **$0.0003236**；另一次完整诊断失败，未返回费用。
- 真实页面另跑 Nano 两季，页面累计显示约 **$0.0034**。
- 本轮已回报费用约 **$0.026**。失败及部分降档请求没有费用回报，不能当作确定的零费用；这不是账户账单总额。

最后一季曾被累计预留挡住。脚本现仅释放“已成功并有费用回报的最后一次请求”的未用余量，失败和其他尝试继续保留全额预留。最终累计预留 $0.213036、释放 $0.06685255，保守占用 **$0.14618345 < $0.20**。上限没有提高。续跑重放已经成功的第一季并核对战报、疆域与采纳命令，只为未完成的第二季发新请求。

最初两次 Nano 决策复用了 schema 简化前的结果，其全局 `planFeedback` 尚未加入。其余 10 次来自修复后的协议；因此这组结果用于链路验收，不能作为同版本模型排名。原始失败和复用过程均保留。

## 工程与页面证据

- 整套 195 项测试通过；最后补充解析上限与全局反馈断言后，相关 7 项通过，共覆盖 196 个不同测试。类型检查、Lint、构建通过。
- 333 席·季观测均不超过 10000 估算 token，峰值 9798。
- 100 局免费评测基线 4/4 通过；郡国易主中位 61，曹操出局 25/100，开局郡数与得分相关系数 0.13。这里沿用 16 季评测口径。
- 另跑统一模式 6 个种子：32、21、52、28、30、34 季自然结束，均为袁绍获胜。引擎与 runtime 哈希和场景验证一致。
- 实际浏览器 `/play`：只有袁绍分配 Nano，手动推进两季，共采纳 12 条、丢弃 3 条；刷新后恢复第 3 季、暂停状态、2/4 已用额度和结构化计划。核对目标、准备、调整条件、复核、事实及中文丢令说明；控制台无错误。

正常对局仍以统一条件结束。脚本的外置季数预算只暂停验证，不将游戏标为结束。

## 尚不能据此下的结论

两季场景只能验证连续请求、约束和反馈，不能证明长期棋力提升或给模型排名。计划可能误读归属、把意图写成已发生战果、使用模糊撤退条件；长字段会被应用截断。六局统一均由袁绍获胜，也未证明势力平衡。下一轮若继续优化，应分别针对复盘准确性与开局势力平衡设置可量化对照，不需要先扩大昂贵的全 AI 长局。
