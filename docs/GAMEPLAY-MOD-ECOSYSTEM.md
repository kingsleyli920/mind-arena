| 类别 | 本文中的例子 | 在本项目中的地位 |

### 0.2 可借鉴 vs 绝对不可复制

- **可借鉴（设计模式，不受著作权保护）**：把 AI 的战略意图建模成「方针 + 对象 + 中期目标 + 中期目标对象」这种结构；把委任权限做成位掩码；把观战做成「自动推进 + 授予视野 + 回合断点」；把 AI 的难度加成拿掉靠战术取胜。
- **绝对不可复制**：
  - SIRE 的**机器码补丁与内存地址表**（那是对 KOEI 二进制的逆向产物）；
  - `311MemoryResearch` 里的**结构体偏移表**（虽为 Apache-2.0，但它描述的是 KOEI 的程序结构，不能据此重建其算法）；
  - 血色衣冠 / 逐鹿天地 / 群英荟萃的**特技表、武将能力表、剧本文本**；
  - 全战三国的 **db 表、Lua 脚本、美术资源**。
  - 本文引用逆向数据**只作为"一个 SLG 的战略状态到底有多大、由哪些字段构成"的经验证据**，不作为实现参考。

- **直接实测的数字**（可复现）：Steam 评测数（Steam appreviews API）、Steam 创意工坊订阅数与榜单排名（抓取 workshop browse 页）、GitHub 仓库 star 数与文件树、逆向文档里的结构体尺寸与数组长度。

## 一、方法论：为什么读 MOD 生态

一个 MOD 生态是**玩家用工时投票的结果**。它比评论区更可信，因为：

1. **改动需要成本**。逆向一个函数、重画一张地图、平衡一套特技表，都要几十上百小时。愿意付出的地方，就是痛得最深的地方。
2. **改动的分布暴露了两件不同的事**：
   - **改得多的**：既痛，又**改得动**。
   - **抱怨极多但几乎没人改的**：痛，但**改不动**——这往往是引擎级/算法级的东西。
3. 对本项目而言，第二类比第一类更重要。**「所有人都想改但改不动的那一块，正是我们要重造的东西」**。

先给结论，后面用证据支撑：

> **三国志 11 的 MOD 生态里，95% 的工作量花在数值、特技、剧本、美术、地图贴图上；AI 相关的改动屈指可数，而且每一次都被当作"里程碑事件"由自媒体专门报道。**
> 这说明：数值和内容是「痛且能改」，**AI 是「痛且改不动」**。

## 二、三国志 11 的 MOD 生态全景

### 2.1 生态的技术底座：没有官方接口，全是内存补丁

这是理解整个生态的关键，也是最容易被外行忽略的一点。

**光荣从未给三国志 11 提供 MOD 接口。**可直接实测：

- Steam 上《三國志11 with 威力加強版》（appid `628070`）的 `categories` 只有 `Single-player / Steam Cloud / Family Sharing`，**没有创意工坊**；直接请求其 workshop browse URL 返回的是社区中心页面，条目数为 0。
- 《ROMANCE OF THE THREE KINGDOMS XIV》（appid `872410`）同样**没有创意工坊**。
- 对照组：《Total War: THREE KINGDOMS》（appid `779340`）有活跃创意工坊，榜首条目订阅数 41 万。
  （以上均为 2026-08-31 通过 `store.steampowered.com/api/appdetails` 与 `steamcommunity.com/workshop/browse` 实测）

威力加强版官方**只提供了编辑功能**：可以改武将、城池、势力、部队，可以做自定义剧本。**规则本身一个字都改不了。** 于是社区走了另一条路。

#### SIRE 的工作原理：改运行中进程的机器码

`San11 SIRE`（全称 Strategy Innovator and Rules Editor，作者 `ryan_knight_12`）是这个生态的地基。据其[百度百科词条](https://baike.baidu.com/en/item/SAN11%20SIRE/3408864)，v1.00 发布于 2010-03-24，最新 v2.28 发布于 2026-02-12——**16 年持续维护**。

它的原理，社区教程写得很直白（[sean2077/311SireCustomizedPackageDev](https://github.com/sean2077/311SireCustomizedPackageDev)，`tutorial/1. Sire 自定义包的原理.md`）：

> SIRE 的工作原理本质是对 SAN11PK 进程的内存中的机械码和数据进行修改。

自定义包（`.scp`）是 XML，核心是 `<Codes>` 标签，每个 `<Code>` 包含：
- `<Address>` — 内存地址
- `<EnableCode>` — 启用该功能时写入的机器码
- `<DisableCode>` — 关闭时还原的机器码

**换句话说：三国志 11 的整个 MOD 生态，是建立在对一个 2006 年 x86 二进制的汇编级热补丁之上的。**

配套的逆向工程仓库 [`sjn4048/311MemoryResearch`](https://github.com/sjn4048/311MemoryResearch)（179 star，Apache-2.0，2026-07 仍在更新）自述：

> This project has lasted for 10 years (2009 - now), and is still active.

主要贡献者 `ryan_knight_12` / `txz_mk` / `sjn4048`，联络方式是百度贴吧 `ryan_knight_12` 吧。仓库里甚至带了 `san11pk.zip` 的 IDA 数据库。

**这一节的意义**：不是技术猎奇。它解释了后面所有现象——
- 为什么 MOD 大多只改数值和内容？因为**改数值只要改一个数组，改 AI 要改一个函数**。
- 为什么 AI 增强被当大新闻？因为它要在汇编层重写决策逻辑。
- 为什么 AI 增强包**几乎无法在 MOD 之间移植**？因为它硬编码了特定 MOD 的数值环境。

### 2.3 生态规模

- 百度贴吧「三国志11吧」自 2005 年运营至今；「三国志11威力加强版吧」为其姊妹吧。⚠ 具体关注数（32.5 万 / 15.6 万）与帖子数来自搜索引擎抓取的贴吧页面数据，**我未能直接复核**（贴吧对爬取返回空页）。
- Steam 版《三國志11 with 威力加強版》总评测 **4,103** 条（好评 3,795 / 差评 308，"特别好评"）——实测于 Steam appreviews API。这个数字很小，因为**中文圈绝大多数玩家玩的是 2006 年的光盘/硬盘版，不在 Steam 上**。Steam 评测数在这里不能代表玩家规模。

### 2.4 MOD 流派分类

我把见到的作品归成六类。**注意每一类的技术难度**——难度决定了作品数量。

#### 类型 A｜换朝代 / 换世界观（数量最多，技术难度最低）

只改武将表、剧本、头像、势力，不动规则。

| 作品 | 内容 |
| --- | --- |
| **血色衣冠**（4.0 / 5.0 / 6.0） | 生态里最有分量的一支。上溯春秋、下迄明末，跨度两千余年；[忆三国](https://www.esanguo.com/sanguozhi/7634.html)称 4.0 收 40 个政权、732 名文臣武将 |
| **逐鹿天地** | 华夏通史向，黄帝至清 |
| **五代十国传** | 8 个剧本，公元 875–1050 年，596 名武将，40 余势力 |
| **吴楚七国之乱** | 汉景帝七国之乱，各势力科技做了差异化 |
| **精忠岳飞 / 炎黄乱世 / 炎黄三国 / 华夏风云 / 江山如画 / 明末风云 / 隋唐演义** | 各断代史 |
| **挥决战云** | 日本战国：全势力替换，旗帜换家纹 |
| **萌战无双**（2.1 / 3.0 / 4.0）、**华夏萌战录** | 动漫向；[百度百科词条](https://baike.baidu.com/item/%E4%B8%89%E5%9B%BD%E5%BF%9711%EF%BC%9A%E8%90%8C%E6%88%98%E6%97%A0%E5%8F%8C/16276174)称其把历史武将与 NPC 全部替换为动漫角色，重做画面、BGM、对话、城池、兵种 |
| **海贼王 2.0 / 极限圣战 / 侠骨留香** | 动漫、武侠 |

**信号**：光荣给了 42 城 + 一套五维 + 一套特技，玩家立刻拿它当**通用历史模拟器**用。他们真正想要的不是"三国"，是**"一套能跑任何群雄割据局面的引擎"**。

#### 类型 B｜数值与系统重制（数量次多，需要 SIRE）

这类才是"改玩法"。以血色衣冠为例，[网易的介绍文](https://www.163.com/dy/article/K470CDMM052688E2.html)列出的改动：

- **攻防判定从「武力」改为「统帅」**——诸葛亮统帅 95，带兵比吕布（统帅 85）稳。这是把"单挑英雄"改成"统兵将领"。
- **光环系统**：统帅 >90 解锁范围 buff。（SIRE 的 Aura System 从 v1.21 起提供：可按统/武/智/政/魅任一属性触发，范围 1–2 格并按阈值扩张，可附加战法成功率/暴击、计略成功率/暴击、援护攻击、气力恢复等。）
- **废柴特技翻新**：「辅佐」从 30% 触发改成 100% 且对副将生效。
- **攻城重做**：设施耐久大增、自愈、主动反击，且要求先拆补给建筑才能攻墙。

⚠ 具体触发率数字来自单一自媒体，未能与 MOD 内文档交叉验证。

**信号**：玩家自发地把游戏从「武将个体秀」推向「体系与阵地」。而**"攻城太容易、城防没有意义"正是原作被点名的三大缺陷之一**（[腾讯新闻](https://news.qq.com/rain/a/20240111A08QA900)：三国志 11 取消了城防机制，"即使你拥有强大的防御设施和兵力，也无法阻止敌人的进攻"）。

#### 类型 C｜跨版本系统移植（韩版路线）

**三国志11 PK 2.2 MOD**（基于韩国玩家 MOD 二次开发，中文社区长期维护，build 号形如 `2.9.0.241107`）：

- **引入「支城」**——这是三国志 9 的概念，11 代原作没有。支城可以使用完整的「太守自治」功能。
- 特技上限扩到 250，移植 SIRE 全部新特技并支持自定义组合。
- 更新日志里明确写「**优化 AI 派遣能力，提高后方城市派遣主动性**」。

**信号**：`后方城市不派兵` 是原作最被诟病的 AI 行为之一，连韩版分支都要专门写在更新日志里。见第六节。

#### 类型 D｜地图改造（数量最少，技术难度最高）

- **《战国七雄》**（作者「云间碧落」）被[搜狐报道](https://www.sohu.com/a/354794137_120015190)称为「首个对城池进行重大修改的 MOD 作品」，用 `bin 修改器` 把南方城市搬到北方，改名雕阴、安邑、上党、灵寿等，并改了港口与水军航线。报道特别提到，难点不在挪城，而在**"解决相关的 AI 运算问题"**。
- **群英荟萃**（在血色衣冠、逐鹿天地基础上二次开发）把「贴合实际的地图修改」当作版本特色。
- **黄祸诛天**等作品自带地图编辑。

**为什么这么难？** 逆向文档给出了硬证据。三国志 11 的核心对象**全是定长数组**：

| 结构体 | 单条尺寸 | 数组长度 |
| --- | --- | --- |
| 城市 `struct_city` | `0x248`（584 B） | **42** |
| 关隘 | `0x90` | **10** |
| 港口 | `0x90` | **35** |
| 势力 `struct_force` | `0x12c`（300 B） | **47** |
| 军团 `struct_corp` | `0x50`（80 B） | **47** |
| 武将 `struct_person` | `0x190`（400 B） | **1100** |
| 部队 `struct_troop` | `0xf4`（244 B） | **1000** |
| 建筑 | `0x38` | 16384 |
| 地图网格 | `0x14`（20 B） | **40000**（即 200×200 格） |
| 宝物 | `0x54` | 100 |
| 州 | `0x48` | 12 |
| 地区 | `0x1c` | 6 |

（来源：[`311SireCustomizedPackageDev/material/结构体汇总.md`](https://github.com/sean2077/311SireCustomizedPackageDev)，2024-07 更新）

城池数写死在 42 这个数组长度里。**你可以挪城、改名、改地形贴图，但要加第 43 座城，就得重排整个数组和所有引用它的代码。** 这就是为什么二十年只出了寥寥几个真正改地图的作品。

> **对本项目的直接教训**：我们的地图是数据驱动的（`commanderies.json` 105 条 + `strategic-nodes.json` 61 条），天然没有这个约束。但反过来要警惕：**规模一旦写进平衡数值和 prompt 模板，改起来同样贵。105 郡国这个数要在第一版就定对**，不要留"以后再加"的幻想。

#### 类型 E｜AI 增强（数量极少，被当作事件）

见第六节，这里先给名单：

- **《如梦似幻》MOD 的「AI 智商增强计划」**（作者 `歧路先知sci`，v0.8）——网易与搜狐都发了专稿，标题就叫「三国志11 AI 智商终于得到改善　从游戏内部破解 AI 提升的秘密」。
- **SIRE 自身的 AI 相关条目**：v1.11「显著增强 AI」、v1.24「加强 AI 资源管理」、v2.28「为 5 个特定港口（下阳、西河、解县、鄱阳、庐陵）启用智能控制」。
- **自定义包「出兵规则修改」**：解决「AI 总是一队一队的出来送」。
- **韩版 PK2.2**：「优化 AI 派遣能力，提高后方城市派遣主动性」。

对比一下：类型 A 有几十个作品，类型 E 全生态**不超过十个可点名的成果，且高度集中在两三个人手上**。

#### 类型 F｜脚本 / 事件

- [`tosmaller/san11-script`](https://github.com/tosmaller/san11-script)（GitHub，5 star）：「三国志11 2.2版本 自定义脚本」。规模很小，README 只有两行。
- 更多的自定义脚本以贴吧帖子形式流通，未沉淀到可检索的平台。

### 2.5 一个被忽视的宝藏：光荣自己就把「意图层」建好了

这是本次调研**最有价值的单条发现**，来自 `struct_corp`（军团，仅 80 字节）：

```
+0x00  int  CorpsFuncAddr       军团相关函数地址
+0x04  int  PowerID             势力 ID
+0x08  int  CorpsDesignation    军团番号
+0x0C  int  CorpsLeaderID       军团长 ID
+0x10  int  Policy              政策
+0x14  int  Target              对象
+0x18  int  MidTermGoal         中期目标
+0x1C  int  MidTermGoalTarget   中期目标对象
+0x20  int  TransportCity       输送城市
+0x28  int  DelegationPolicy    委任方针（前 12 位为权限位，第 29 位 = 是否委任）
+0x2C  int  ActionPoints        行动力
+0x30  ...  PersonList          武将链表
```

同时，`struct_city` 里有 `CityPolicy`（都市方针）与 `CityTarget`（都市目标）；`struct_force` 里有 `ForcePolicy`（势力方针）。

**读出来的东西**：光荣在 2006 年就用**三层意图**（势力方针 → 军团政策+对象+中期目标+对象 → 都市方针+目标）驱动全部 AI 势力，每层都是几个整数。**这就是一个可枚举、可序列化、可解释的战略动作空间的完整原型。**

而它的失败之处同样清楚（第六节展开）：这套意图层**只用来喂 AI，没有开放给玩家**。玩家能碰到的委任接口只有那 12 个权限位（允许/禁止 征兵、建设、攻击、内政……），**给不了"中期目标"**。于是玩家永远觉得委任军团很蠢——他们没法告诉它要打哪。

### 2.7 逆向出来的一个关键事实：三国志 11 的随机数是**全局单流**的

这是本轮新查到的东西，前面几篇文档都没有覆盖，但它直接打在约束 ⑤ 上，所以单列一节。

社区的逆向合集里有一篇专门讲 311 随机数实现的笔记（`内存资料/杂谈/关于311的随机.md`，GBK 编码）。它还原出全游戏只有两个随机原语，都是同一个线性同余发生器：

```c
// 以 percentage% 的概率返回真
BOOL Random_100(int percentage) {
    if (percentage <= 0) return 0;
    random_value = 1812433253 * random_value + 12345;
    return (random_value >> 16) % 100 < percentage;
}

// 返回 0 ~ X-1 之间的一个数
int Random_Smallerthan(signed int X) {
    if (X < 2 || !X) return 0;
    random_value = 1812433253 * random_value + 12345;
    return (random_value >> 16) % X;
}
```

关键不在于这个 LCG 弱（它确实弱），而在于 **`random_value` 是一个全局变量，整局游戏所有势力、所有事件共用这一条序列**。社区从中推出的几条结论（原文第 5 节）：

1. **序列是预先确定的**。种子定了以后，后面每一个数都定了。所以修改器能**提前把成功率显示出来**——它只要读出当前 `random_value`，代入公式往前算就行。
2. **每一次判定都把指针推进一格**，不管这次判定是谁发起的。假设序列是 `50 90 0 30 40...`，那么第一个动作面对的阈值是 50，第二个是 90，第三个是 0（成功率不为 0 的操作必成功）。
3. **只是"看"成功率不推进指针**，但「评定」这个不耗行动力的指令**会**推进。于是玩家用连续评定来"洗"随机数，把好数留给关键操作。
4. 因此 SL（存档读档）大法有效。RK 的「真随机模式」用**开局至今的游戏内时间**重新播种来破解 SL。

⚠ 口径：以上出自社区逆向笔记与其反编译还原的 C 代码，**非光荣官方公开信息**；我核对的是文件内容本身，没有独立复现反编译。

**为什么这一条对我们是重要的负面教材**：

- **全局单流 = 裁决顺序在暗中分配运气。** 谁先被求解器遍历到，谁就吃掉序列里那个 50。这个优势与决策质量毫无关系，纯粹是循环顺序的副产物。对一个要比较模型强弱的竞技场，这是致命的：它把噪声塞进了本该由推理决定的差距里，直接违反约束 ⑤，也违反 M6（绝对对称）。
- **对 WEGO 尤其致命。** 我们的方案是同时密封下令 + 同时裁决。如果底层是单流 RNG，那么"同时"就是假的——求解器内部总要有一个遍历次序，而那个次序静悄悄地决定了谁走运。更糟的是，**重构一次循环顺序就会改变对局结果**，回放对不上，复现无从谈起。
- **"评定洗随机数"是一个精确的警告**：任何**免费的、看似只读的动作，只要碰了随机流，就会变成策略通道**。LLM 选手完全有能力发现并利用这种通道——它就是在做模式发现。所以观测与探查动作必须是**严格无副作用**的。

**对应的做法**（展开为 M18）：随机数不要"抽"，要"派生"。每一次判定用一个确定性的键去 hash 出它自己的流：

```
draw = H(match_seed, year, season, faction_id, event_kind, event_seq)
```

这样一来：裁决顺序怎么排都不影响任何一次判定的结果；回放逐位一致；某一方的运气不会因为另一方多做了一个动作而改变。**这是"同时裁决"能够名副其实的前提条件。**

顺带一提，它还封掉了模型侧的重试漏洞：如果模型调用失败要重试，随机数必须在**裁决时**按键派生，而不是在**请求时**抽取，否则一次网络抖动导致的重试就等于免费重摇一次骰子。

## 三、MOD 到底在改什么：改动集中区 = 原作痛点

把上面所有作品的改动项归类统计（按"有多少作品动了这一项"粗略排序）：

| 改动类别 | 出现频率 | 技术难度 | 反映的原作痛点 | 对本项目的含义 |
| --- | --- | --- | --- | --- |
| **武将表 / 剧本 / 势力归属** | 几乎 100% | 低（官方编辑器） | 内容量不够，"三国"这个盘子装不下玩家的想象 | 我们的 578 武将 + 194 剧本要**数据外置、可换代**，但不要为"可换朝代"付设计代价 |
| **特技 / 技能体系** | 约 80% | 中（SIRE） | 原作特技"设计单调"、大量废柴技能；强弱极端不平衡 | **警告**：技能表是平衡黑洞。约束 5（推理要能稳定转化为结果）要求技能效应必须少、正交、可解释 |
| **五维与成长** | 约 70% | 中 | 数值区分度不足；武力独大 | 血色衣冠把"攻防由武力改统帅"是把**个体英雄改成体系指挥**——与我们的定位一致 |
| **经济与内政数值** | 约 60% | 中 | 内政繁琐且后期失真；武将工资太低导致人才不稀缺 | 内政必须**极度精简**，见第六节 6.3 |
| **兵种 / 战法平衡** | 约 60% | 中 | 相克三角不够、特种兵没差异 | 兵种数要少，相克关系要**能一句话说清** |
| **美术（头像/暴击图/宝物图）** | 约 50% | 低 | — | 与本项目无关 |
| **地图（挪城 / 地形 / 航线）** | **< 10%** | **高（bin 逆向）** | 42 城的盘子太小、地理不贴合 | 我们数据驱动，但**规模要一次定死** |
| **AI 行为** | **< 5%** | **极高（汇编重写）** | **AI 蠢**——被反复点名为"最大的弊端" | **这就是本项目的立身之本** |

### 三条一眼可见的结论

1. **改动量与技术难度严格负相关**，与痛感几乎无关。玩家改能改的，不是最想改的。
2. **AI 是痛感最高、改动量最低的那一格**。所有关于"三国志 11 最大缺陷"的讨论，最后都落到 AI 上（[网易：三国志11最大的弊端](https://www.163.com/dy/article/K06F2N970546O9E5.html) 直接把"AI 弱"列为第一；[腾讯：三大缺陷](https://news.qq.com/rain/a/20240111A08QA900) 把"AI 死板"列为第一），但二十年只有个位数的人真正动手改过。
3. **玩家自发的改动方向，与"给 AI 玩的游戏"该有的方向高度一致**：削个体英雄、强体系、强阵地、强补给、简化内政的重复劳动。这不是巧合——**微操的乐趣消退后，剩下的正是战略**。

## 四、三国志 9 / 13 / 14 的 MOD 情况

### 4.1 三国志 9：文件级 MOD，工具早，生态小

- 制作方式是**直接改数据文件**：剧本文件 `D_Sce0Xx.S9`、小兵文件 `G_FacTPK.s9` 等（[轩辕春秋：从三国志9内部的各种文件看 Mod 的制作方法](https://www.xycq.org.cn/forum/thread-136570-1-1.html)）。**不需要汇编逆向**，门槛远低于 11 代。
- 工具：`RangZH` 的 **ME 剧本编辑器**；「天地玄黄」的剧本修改器；威力加强版本体自带**剧本制作器 + 存档修改器**。
- 生态形态是**自制剧本**为主，轩辕春秋文化论坛是主发布地。有玩家把「让电脑更强」当作剧本设计目标（如"从风"的汉中剧本因电脑攻击力强而受欢迎）——**注意：这是靠给 AI 加数值，不是改 AI 逻辑。**
- 一份社区整理提到威力加强版含「AI 智能增强」「势力统合」「城市兵法技能」「年表机能」等新系统。⚠ 单一来源，未与官方手册核对。

**三国志 9 的 AI 口碑**：整体比 11 好一档，但同样的病。[腾讯新闻的两篇评论](https://news.qq.com/rain/a/20231212A097N200)与[网易](https://www.163.com/dy/article/IRE087K30526CHNR.html)指出：AI **只根据玩家的发展状态调整策略，不会主动进攻**；连锁战法过强导致"某些势力单位强过一堆名将"；后期一旦玩家做大就彻底失去挑战。

> 与首轮结论呼应：`GAMEPLAY-RTK-SERIES.md` 判定 9 代的"战略阶段 / 进行阶段"两段式是全系列最接近 WEGO 的一代。**MOD 生态没有推翻这个判断——9 代的 MOD 抱怨集中在数值与连锁，不在回合结构。回合结构是 9 代唯一没人想改的东西。** 这是一个很强的正面信号。

### 4.2 三国志 13：官方给了事件编辑器，生态跟着变形

- 13 代**自带事件编辑器**，社区据此产出大量剧情 MOD。有玩家（"诸葛宿"）做出含 57 个剧情文件、5 个番外历史剧情、34 个女性剧情的作品集（[游民星空](https://www.gamersky.com/handbook/201808/1081554.shtml)）。
- 另有 `San13Editor` 等第三方编辑器，做剧本、武将、头像修改（[游民星空 MOD 大全](https://www.gamersky.com/handbook/201604/745613.shtml)、[虚构剧本合集](https://www.gamersky.com/handbook/201602/714306.shtml)）。
- **形态差异很明显**：11 代的 MOD 是"改规则"，13 代的 MOD 是"写故事"。**官方开放了什么，社区就做什么。**

> **对本项目的启示**：我们开放给外部的接口，会直接决定别人拿它做什么。如果 mind-arena 要被别人复用做模型评测，**该开放的是"势力/剧本/规则参数"三件套，不是美术和文本。**

### 4.3 三国志 14：没有创意工坊，AI 口碑更差

- 实测：appid `872410` 无 Steam 创意工坊。民间 MOD 走 3DM / 游侠 / 游民路线，以剧本、武将、模型、汉化为主。
- **AI 评价比 11 代还低**。贴吧上的典型说法是"三国志 14 的 ai 太弱，三国志 13 是必须速推，打晚了 AI 会滚成大势力；14 代最高难度也能平推"（[三国志14吧](https://tieba.baidu.com/p/7171278900)）、"AI 进攻欲望不强"（[同上](https://tieba.baidu.com/p/7771279526)）。
- **但 14 代留下了一份罕见的公开 AI 逻辑分析**：[游民星空《三国志14》各主义与 AI 逻辑分析](https://www.gamersky.com/handbook/202002/1264662.shtml) 指出 AI 的攻击欲望由「主义」决定，并给出明确排序：

  **霸道 > 王道 > 割据 > 我道 > 名利 > 礼教**

  霸道（曹操）攻击欲极高、扩张最快；礼教/名利防御优先、疯狂修工事；**我道**则被评为"有点蠢"——实力弱却攻击欲高，容易过度出击。

> **这是一个非常干净的设计样本**：AI 的宏观行为由**一个离散的性格枚举**驱动，而不是由一个连续的评估函数。它带来的好处是**可解释、可预期、可平衡**；带来的坏处是**可被玩家背下来**（约束 5 的反面：一旦策略可枚举，推理质量就不再是胜负关键）。
>
> **对本项目**：我们不能用固定性格枚举来驱动席位，因为席位就是被测的模型本身。但**中立势力/在野武将的行为**可以用这种枚举，成本极低且可解释。★4

### 5.5 全战三国 AI 的公认毛病

综合 Steam 讨论区与上述 MOD 的动机描述：

- **AI 作弊而不是变强**：高难度靠 +属性、+士气、+金钱（讨论区有玩家称 AI 每回合 +100,000 金、+200% 属性 ⚠ 单一来源，数字未核实）。
- **AI 针对玩家**：外交上对玩家有隐藏敌意偏置，导致高难度"所有人都对你宣战"。
- **AI 配兵愚蠢**：把民兵和精锐当同级；把轻骑射当得比重骑射好。
- **AI 花不出钱**：预算上限限制导致后期钱堆着不用（这与三国志 11 的"AI 浪费 70% 资源"是同一个病）。
- **剧情固化**：190 剧本永远是袁绍/孙坚/公孙瓒/曹操/董卓称帝——**AI 的强弱由开局参数决定，不由局中表现决定**。

## 六、民间对 AI 的抱怨集中在哪里（本项目最关键的一节）

把中文圈二十年的抱怨与几个 AI 增强 MOD 的修复清单交叉，可以整理出一张**传统 SLG AI 的失败模式表**。每一条我都标了它对本项目的意义。

### 6.1 第一手材料：AI 增强 MOD 修复了什么

**《如梦似幻》的「AI 智商增强计划」v0.8**（作者 `歧路先知sci`）——据[网易专稿](https://www.163.com/dy/article/HBAD05UC054650WD.html)，原作 AI 的五大缺陷与对应修复：

| # | 原作 AI 的行为 | 修复 |
| --- | --- | --- |
| 1 | **出兵时把玩家实力算进去**，玩家强就不敢来 | 强势 AI 无视对手体量，全力出兵 |
| 2 | **后方城市每年才检查一次补给线** | 改为持续向前线跑运输队 |
| 3 | **军团长会贪污资源**，造成补给瓶颈 | 直接删除该机制 |
| 4 | 前线兵力受常规上限卡住 | 允许通过城市输送**溢出**前线兵力上限 |
| 5 | **无法多线并进** | 资源允许时多个军团同时发起进攻 |

以及一个惊人的数字：

> AI 原本浪费了 70% 的资源，改动后城池的经济将被 AI 充分利用。测试显示改进后的 AI 只用**原来 30% 的资源**就能打得更好。

（同一说法在[搜狐转载](https://www.sohu.com/a/565707396_120015190)与[网易另一篇](https://www.163.com/dy/article/HBS8FN4F054650WD.html)出现，⚠ 但三处同源，均出自作者自述，非独立验证。）

作者还说明了**自动编队**的一个根本性缺陷：

> AI 先决定出什么兵种，再选用哪个武将。所以它决定要骑兵时会派出最好的骑将，后续编队就只剩弱的可选，看起来很不合理。

**这是一个纯粹的贪心序列决策病：先固定类型再选人，没有全局匹配。**

### 6.2 抱怨清单：十二种「AI 显得蠢」

按层次组织。每条给出出处，并标注**它在本项目里对应什么**。

#### 战略层

**A1｜死宅：后方城市不出兵。**
最集中的抱怨。韩版 PK2.2 的更新日志专门写「优化 AI 派遣能力，提高后方城市派遣主动性」；自定义包生态里有专门的「出兵规则修改」包，用来治「AI 总是一队一队的出来送」以及洛阳/晋阳/柴桑一带的"死宅"（[搜狐](https://www.sohu.com/a/373741121_120015190)）。
→ **本项目**：任何"势力"都必须**每季产出一个非空的意图**。不允许"什么都不做"成为默认行为。空转要有可见成本。

**A2｜添油：排队送人头。**
[网易盘点电脑 AI](https://www.163.com/dy/article/H1I4ABHK055224VQ.html)：在有路口可堵的城池，AI"排队送死"，且不会有效使用攻城器械，让远程单位在隘口卡住整支部队。
→ **本项目**：**兵力必须能被承诺到一个"战役"对象上，而不是逐部队独立出发。** 这直接支持首轮方案的"意图层 + 确定性求解器"：求解器一次性解算整场会战，不给 AI 逐个添油的机会。

**A3｜短视且盲目开战。**
[网易](https://www.163.com/dy/article/K06F2N970546O9E5.html)：AI "不看实力差距就盲目进攻"，而且"同时与多方交战、兵力分散"，不像玩家那样先灭弱者。
→ **本项目**：这是**缺少跨回合规划**的表现。我们的"旬/季两层时钟 + 每年一次全量模型调用"天然要求模型给出多季度计划——**这恰恰是 LLM 相对规则 AI 的最大优势区**，必须让它转化为可测量的分数。

**A4｜行为被开局参数写死。**
三国志 14 的主义排序（霸道 > 王道 > 割据 > 我道 > 名利 > 礼教）决定了全局攻击欲；全战三国的 190 剧本永远是那几家称帝，以至于要靠 Give Everyone A Chance 这种 MOD 硬提小势力的"潜力值"。
→ **本项目**：**绝对禁止任何"势力潜力/剧本护航"参数。** 开局差异只能来自地理与户口（`commanderies.json` 已提供），局中差异只能来自决策。这是竞技场合法性的底线。

**A5｜⚠ 被故意做弱以保历史走向。**
[网易](https://www.163.com/dy/article/H1I4ABHK055224VQ.html)称，设计师为了让局面尽量走向魏蜀吴三分，给御三家之外的 AI 加了"反向设计"。**这是自媒体的动机推断，无任何官方证实。**
→ **本项目**：无论真假，它描述的是一个真实存在的诱惑——**为了"好看的历史"牺牲"公平的竞赛"**。我们要在文档里写死：mind-arena 不做历史护航，194 年剧本只提供起点，不提供结局倾向。

#### 战役/战斗层

**A6｜寻路愚蠢，不用水路。**
[网易](https://www.163.com/dy/article/H1I4ABHK055224VQ.html)：寿春打下邳时 AI 走陆路，导致与小沛发生不必要的冲突，尽管有水路可走。
→ **本项目**：**空间必须给关系图，不给坐标。** 我们的 61 个 `strategic-nodes`（关隘/港口/渡口）应该是**显式的边**，路径由确定性求解器算，模型只选目标与走向（如"取江东，经濡须口"）。★5

**A7｜不会用攻城器械与地形。**
同上。同时玩家攻略反过来利用这点：卡隘口（"一夫当关"）、熊手兵种卡位、神火计诱 AI 放无意义的火烧光气力（[游民星空攻略](https://www.gamersky.com/handbook/200603/21652.shtml)、社区攻略）。
→ **本项目**：**任何"玩家能背下来的固定破绽"都是约束 5 的敌人。** 战斗结算必须是确定的、无破绽的求解器，而不是逐单位的启发式行为树。

**A8｜配兵/编队算法拙劣。**
如梦似幻作者的"先定兵种再选将"分析；全战三国的 Better AI Templates 修正"AI 认为轻骑射优于重骑射"。
→ **本项目**：**编队不该是模型的决策。** 模型声明"编成偏好"（如"重步为主、以骑兵为侧翼"），求解器做全局最优匹配。这既省 token 又消除这类蠢相。★5

#### 内政/后勤层

**A9｜内政规划反人类。**
[网易](https://www.163.com/dy/article/H1I4ABHK055224VQ.html)：委任的 AI 会**拆掉三级设施重建一级设施**，因为它遵循"三市场、三农田、一兵营、一锻冶厂"的固定模板。
→ **本项目**：**内政不能有"布局"这个维度。** 一旦内政有空间布局，就必然产生模板，而模板必然与局势脱节。我们的内政应该是**几个离散的方针槽位**，不是格子里摆建筑。

**A10｜补给检查频率与实际节奏脱节。**
如梦似幻修复项 #2：后方城市**每年才检查一次补给线**。
→ **本项目**：这条最有意思。它说明**AI 的"思考频率"如果远低于世界的变化频率，再好的逻辑也会失效**。我们的设计正好相反：模型每年一次全量决策，但**求解器每旬持续执行并在触发条件时中断**。中断阈值的设计（什么算"值得重新叫醒模型"）是核心工程问题，不能省。★5

**A11｜资源大量闲置。**
如梦似幻的"浪费 70% 资源"；全战三国 Better AI Templates 放开 AI 每回合招募/维护/建设的预算上限。
→ **本项目**：**不要给模型设"每回合最多花多少"的隐藏上限。** 合法动作集要如实反映可用资源；如果模型选择囤积，那应该是它的判断，而不是引擎替它做的。

#### 外交层

**A12｜外交是可被套路的开关。**
[网易](https://www.163.com/dy/article/H9S4VPI3055224VQ.html)总结的"破盟"套路：先和结盟双方之一停战，另一家因为没人可打，过一段时间自然解盟。三国志 11 的"驱虎吞狼"被玩家评为"鸡肋"，条件苛刻到几乎用不出来（[网易](https://m.163.com/dy/article_cambrian/GRMMK1KS055224VQ.html)）。全战三国则相反：高难度下 AI 对玩家有隐藏敌意，导致"没法维持同盟"。
→ **本项目**：呼应 `GAMEPLAY-AI-FRIENDLY.md` 原则 9——**谈判与下令必须是两条独立通道，承诺要格式化到可被机器校验。** AI 的外交之所以蠢，是因为它的"关系度"是一个可被单调推动的标量。**关系必须是结构化的承诺集合，不是一个数。** ★5

### 6.3 委任军团：一个失败的抽象层，值得逐条解剖

这是全文对本项目最贴近的案例。**委任军团就是光荣版的"让 AI 代打"**，而玩家对它的态度极其一致：

> "我委任的军团从来都是不可攻击，发展内政为主，前线一直都是我自己带队，后面给我输送物资就好"
> "永远不要高估了 AI 的军事能力，也永远不要低估了 AI 的内政能力"
> "电脑出兵是一点不看兵种适应，它敢让关二爷拉大车"
> —— [网易：委任军团 AI 太弱](https://www.163.com/dy/article/GE0JTQM20546741U.html)

**为什么会这样？** 拆开看（[腾讯：如何委任军团](https://syzs.qq.com/blog/news/20210508A08NK600)）：

| 环节 | 机制 | 问题 |
| --- | --- | --- |
| **军团长选谁** | 玩家**不能选**。按固定优先级自动定：带兵最多 → 官职最高 → 统率最高 → 武力最高 | 玩家失去对最重要变量的控制 |
| **行动力** | 由军团长的魅力与统率决定 | 不透明 |
| **战略取向** | **隐藏**。孙策当军团长就特别想打江东，曹操想打中原 | **玩家看不见，也改不了** |
| **玩家能给的指令** | 委任方针的 12 个权限位（允许/禁止 征兵、建设、攻击、内政……）+ 辖区城市 + 兵装配额 | **只有否定权，没有指向权** |
| **失效条件** | 辖区城市太多则行动力摊薄；内政建筑不合 AI 预期；军需不足 | 玩家难以诊断 |

**核心病灶**：`struct_corp` 里明明有 `MidTermGoal` 和 `MidTermGoalTarget`，**但玩家碰不到它们**。玩家能做的只有"禁止它做某事"，不能说"去打这里"。

> **这是本项目最重要的反面教材。**
>
> mind-arena 的整个设计就是"让模型只下高层意图"。委任军团证明了这个抽象层**能不能被接受，取决于三件事**：
> 1. **意图必须能指向**（"去取南阳"），不能只有权限开关。
> 2. **执行必须可解释**（为什么派了他、为什么走这条路、为什么没打）。
> 3. **失败必须可归因**（是我的意图错了，还是执行层判断错了）。
>
> 缺任何一条，使用者（人或模型）都会退回微操，或者干脆不信任这个层。**约束 1（只做高层战略）能否成立，取决于我们在这三点上做得比光荣好。**

### 6.4 一句话总结：传统 SLG 的 AI 为什么蠢

不是程序员水平问题。是**结构性**的：

1. **AI 和玩家共用同一套微操接口。** AI 必须逐部队、逐建筑、逐回合做几十上百个局部决策。规则引擎在这个粒度上只能用贪心启发式，而贪心必然在全局上露怯（A2 添油、A8 配兵、A9 拆楼）。
2. **计算预算的错配。** AI 的"思考"必须在玩家点"结束回合"后的一两秒内完成，还要同时跑几十个势力。于是像"每年才检查一次补给线"（A10）这种降频妥协就出现了。
3. **平衡要求 AI 不能太强。** 单机 SLG 的商业目标是让玩家赢。于是难度做成"给 AI 加属性"而不是"让 AI 更会打"——Fairplay AI 存在的全部理由就是把这层加成拿掉。
4. **AI 的目标函数是静态的。** 三国志 14 的主义、全战三国的 faction personality，都是开局定死的枚举。它们不会因为局势变化而改变自身的战略取向。

**mind-arena 的价值主张正好落在这四条的反面：**

| 传统 SLG 的结构性限制 | mind-arena 的对策 | 对应约束 |
| --- | --- | --- |
| AI 与玩家共用微操接口 | 只有意图层，无微操通道；执行交给确定性求解器 | 1 |
| 计算预算被实时性挤压 | 决策频率与调用成本解耦；每年一次全量调用 + 中断驱动 | 3、6 |
| 难度靠给 AI 加成 | **完全对称**：同规则、同观测结构、同 token 预算、同动作集 | 5 |
| 目标函数静态 | 模型每次全量决策都可以重写自己的战略 | 5 |

## 七、玩家自制的「AI 对战 / 观战」玩法与工具

### 7.1 三国志 11：没有原生观战，委任是唯一近似

- **原作没有观战模式**。可以把全部城市交给军团委任、自己不动，但玩家势力仍然存在、仍会被针对，且行动力体系不同。这不是真正的 AI vs AI。
- 修改器层面，社区提到可以配置 **CVC（Computer vs Computer）** 让电脑互相打。⚠ 这条来自搜索结果对修改器功能的概括，**我没有找到具体工具名与操作说明**，标为未证实。
- 一个可确认的能力：`311SireCustomizedPackageDev` 的示例自定义包里有 **`后台可运行.scp`**（让游戏在后台不暂停），以及 **`敌军移动范围可视化`**、**`显示地格实际归属`**、**`显示真实忠诚`**、**`浮动情报窗显示战力`**、**`记忆组队`** 等。

  > 注意这一批包的性质：**它们全都在做"把引擎内部状态暴露给观察者"**。这正是观战系统的需求：真实忠诚、真实归属、真实战力、敌军可达范围。**社区花力气做的"可视化包"，就是一份现成的观测字段清单。** ★5

### 7.2 全面战争系列：有两个直接可抄的东西

**① Spectator Mode（三国，1,710 订阅）**

> After positioning your army just start the battle and use SHIFT + F9 to let the AI control your army.
> Shift+F9 观众模式（全自动）／Shift+F10 只控主将／Shift+F11 控援军／Shift+F12 全关

作者已标注 ABANDONED。功能是**战斗层的托管与观察**，可在"全托管 / 部分托管 / 手动"之间循环切换。

**② Auto-Run & Spectate AI（Total War: WARHAMMER III，295 订阅）**

注意：**这个 MOD 属于 WH3 不是三国**（我核对了其 apphub 名称）。但它的设计说明是本节最有价值的材料，作者自述这是**他用来自动测试自己 MOD、观察 AI 行为的工具**：

> **Auto-Run**: Automatically ends your turn each round, so AI factions play uninterrupted. The AI will not declare war on you or attempt diplomacy with your faction during an auto-run.
>
> **Spectate**: Grant yourself vision over specific factions or cultures (or the whole map) while auto-running. This includes their regions, characters, foreign slots, army compositions, and **goals (defend here, attack there)**.
>
> **Breaks**: Pause the auto-run on specific turn numbers, or periodically (every X turns) … Or break on the next turn by pressing Esc … Modders can also send a script message to trigger a break:
> `sm:trigger_message("pause_auto_run", { turn_number = cm:turn_number() + 1 })`

**这是一份完整的 AI 竞技场观察器需求文档**，四个能力：

1. **自动推进**（无人介入地跑完整局）
2. **中立观察者**（观察者不参战、不被外交、不被宣战）
3. **任意视野授予**（可看任意势力的领地、人物、军队编成，**以及它的目标：守这里、打那里**）
4. **可编程断点**（按回合号 / 周期 / 手动 / 脚本消息暂停）

> **对本项目 ★5，见第八节 M11。** 特别注意第 3 点里的 "goals (defend here, attack there)"——**观战者最想看的不是数值，是意图。** 这直接决定了我们回放系统该记什么：每季每方的**意图声明**必须是一等公民，与结果并排展示。

**结论**：Total War 系列**从来没有原生的 AI vs AI 战役观战**；战斗层的观众模式是 MOD 做的，战役层的自动推进也是 MOD 做的，而且是**模组作者的调试工具**，不是玩家玩法。

### 7.3 LLM 时代：已经有人做过和我们同类的东西

这是本次调研的意外收获，也是必须正视的先行者。

#### ①「赛博斗蛐蛐：9 大模型决战三国志」

[腾讯云开发者社区文章](https://cloud.tencent.com/developer/article/2652512)。作者自建引擎（**不是改造现成游戏**），让 LLM 各执一方对局。

**规则骨架**（与我们高度相似，值得逐条对比）：

| 维度 | 该项目 | mind-arena 首轮方案 |
| --- | --- | --- |
| 势力数 | 3 方，各 5 城 | 31 势力（194 剧本） |
| 局长 | **24 回合**，平局进加时（加速产兵） | 60 季（15 年） |
| 胜负 | 24 回合后控城最多 | 多轨胜利条件 |
| 行动预算 | **行动点数按控城数分配** | 类似 |
| 资源 | 金、粮、人口；**士气作为经济产出的隐藏乘数** | 待定 |
| 动作 | 出击、撤退、侦察、外交（信使）、征募训练、调税（影响士气） | 意图层动作集 |
| 回合流程 | 命令处理 → 部队移动 → 战斗结算 → 回合末经济 → 胜负判定 | WEGO 同时裁决 |
| 分组 | A 组国产模型 / B 组 Claude 对手 / C 组西方模型，**分组赛 + 决赛** | 席位轮换 + TrueSkill |
| 成本 | 作者自述开发期 API 花费 100 美元以上（OpenRouter） | — |

**他们踩到的坑（这部分最有价值）**：

1. **模型按史实结盟**。模型一开局就倾向复刻历史同盟，直到作者在 prompt 里明确禁止历史角色扮演。
   → **我们必须在观测里剥离"历史身份的暗示"，或者反过来显式随机化势力名与地理的对应关系做对照实验。**
2. **模型拒战**。部分模型出于伦理考虑回避战争，需要提示这是实验性游戏。
   → **需要在系统提示里把"这是抽象策略博弈"说清楚，并在评测协议里记录拒答率。**
3. **后勤是最大的失败点**。文中记载 Claude 战略文档写得最好（27 次战略修订）、外交最守信，但**反复因补给短缺导致攻势崩溃**。
   → **这是对我们的直接警告：如果补给建模得当，它会成为区分模型的主要维度；但如果补给的因果链在观测里不可见，它就只是噪声。** 补给状态必须在观测里显式、量化、带趋势。
4. **外交一致性难以维持**。多数模型在压力下无法维持外交承诺。
   → 呼应 `GAMEPLAY-AI-FRIENDLY.md` 原则 9：承诺必须**格式化且可被机器校验**，违约必须**可测量**。
5. **决赛出现 2v1 围殴**。Gemini 被 Claude + Kimi 联手围攻，靠"坚壁清野"（弃城、撤走武将与资源、拉长对方补给线）在加时翻盘。
   → 这**同时验证了两件事**：(a) 围殴是必然出现的（呼应原则 11）；(b) **如果地图有纵深、补给有代价，围殴就不是必胜的**——这是"围殴有成本"最好的机制化例子。

⚠ 注意：文中的模型名（Kimi K2.5、MiMo V2 Pro、MiniMax M2.7、Claude 4.6 Opus、GLM-5、Grok 4.20 Beta、Gemini 3.1 Pro、GPT-5.4、Qwen 3.5）我未独立核实其真实性与版本号。文章未提供公开仓库链接。

#### ②《三國志略》HiStrategy

[`emergencescience/histrategy`](https://github.com/emergencescience/histrategy)（GitHub，开源）。定位与我们**不同但相邻**：用 LLM 作为游戏的"物理引擎"与模拟引擎，玩家输入真实的政治命令，模型负责模拟因果。史料优先级：《三国志》含注 >《资治通鉴》>《后汉书》>《三国演义》。

> **和我们的区别要说清楚**：HiStrategy 把 LLM 放在**裁判位**（世界模拟），我们把 LLM 放在**选手位**（势力决策），裁判是确定性求解器。
> **HiStrategy 的路线对我们是明确的反面参照**：LLM 当裁判会引入不可复现的裁决，直接违反约束 5（推理质量要能稳定转化为结果——如果裁判本身有方差，选手的优劣就被淹没了）。**我们必须坚持"确定性裁决"。**

## 八、可借鉴机制清单与适配度评级

评级标准是六条硬约束：① 高层战略非微操 ② 状态可序列化（观测 ≤6000 token）③ 决策频率与成本解耦 ④ 合法动作可枚举 O(10)–O(10²) ⑤ 推理质量稳定转化为结果 ⑥ 一局可控（~15 年 / 60 季 / 每方 ~15 次全量决策）

### M1｜三层意图结构（势力方针 → 军团政策+对象+中期目标+对象 → 都市方针+目标）★★★★★

**来源**：三国志 11 的 `struct_force.ForcePolicy` / `struct_corp.{Policy,Target,MidTermGoal,MidTermGoalTarget}` / `struct_city.{CityPolicy,CityTarget}`（借鉴**结构思路**，不复制任何取值表）

**理由**：
- 约束 ①：三层全部是"意图"，没有一个字段是微操。✓
- 约束 ②：一个军团 80 字节，一个城市的意图部分 8 字节。**整个战略层意图 = 几十个整数**，序列化后不到 200 token。✓✓
- 约束 ④：每层的取值都是小枚举，笛卡尔积后仍在 O(10²)。✓
- 约束 ⑤：意图明确 → 执行确定 → 结果可归因。✓

**改造点**：光荣的致命错误是**不把中期目标开放给使用者**（见 6.3）。我们必须把 `MidTermGoal + Target` 做成一等公民的动作。

### M2｜委任权限位掩码（12 位允许/禁止）★★★☆☆

**理由**：作为**约束条件**很好（约束 ④：把不想要的动作从合法集里剪掉），但**不能作为主要表达手段**。它只有否定权没有指向权，这正是委任军团被玩家嫌弃的原因。
**用法**：留作"给下属势力/附庸的约束"，不作为主决策通道。

### M3｜输送城市 / 补给线显式建模（`TransportCity`）★★★★★

**理由**：
- 「赛博斗蛐蛐」的实测里，**补给是分出模型高下的主要维度**（Claude 战略最好却输在补给）。
- 三国志 11 的 AI 因为"每年才查一次补给"而显蠢；`GAMEPLAY-RTK-SERIES.md` 已确认 14 代的"兵站 = 图上的连通路径"是系列里最好的补给设计。
- 约束 ②：补给线是**图上的一条路径**，用节点序列表达，token 极省。
- 约束 ⑤：补给是**确定性的图连通性问题**，无随机，推理好就一定算得对。✓✓

**做法**：以 `strategic-nodes.json` 的 61 个关隘/港口/渡口为边，补给 = 从后方郡国到前线的**连通路径 + 容量**。观测里给"当前补给路径 + 剩余天数 + 断点风险"。

### M4｜编成偏好而非编队指令 ★★★★★

**来源**：反向借鉴三国志 11 的自动编队缺陷（先定兵种再选将的贪心匹配）+ 全战三国 Better AI Templates（AI 的单位质量评估表）

**做法**：模型声明**编成偏好**（如"以重步为主、骑兵置于侧翼、优先带擅守将"），求解器做**全局最优匹配**。
**理由**：约束 ①（不是微操）、②（一句话）、⑤（求解器最优 = 无破绽 = 推理差异不被执行噪声掩盖）。

### M5｜出兵判据阈值化（求解器内部，不暴露给模型）★★★★☆

**来源**：自定义包「出兵规则修改」、如梦似幻修复项 #1/#5

**做法**：什么条件下一支部队才算"可以出发"（兵力/补给/气力阈值），由**引擎规则**决定，不由模型逐次判断。
**理由**：约束 ③（省调用）、⑤（消除 A2 添油这类执行层噪声）。**但阈值必须公开在规则文档里**，否则模型无法规划。

### M6｜绝对对称，禁止任何难度加成与针对性偏置 ★★★★★

**来源**：Fairplay AI（"The AI and the Player now play equally across all difficulties"；"Removed the AI Bias towards the Player"）

**理由**：这是**竞技场的合法性底线**，直接决定约束 ⑤ 成立与否。
**清单**（写进规格）：
- 所有席位同一套规则、同一套观测 schema、同一个 token 预算、同一个动作集生成器。
- 引擎不得知道哪个席位是哪个模型。
- 不得有"势力潜力""剧本护航""历史修正"之类的参数。
- 席位轮换（同一模型在不同局坐不同势力），呼应 `GAMEPLAY-AI-FRIENDLY.md` 原则 12。

### M7｜开局多样性靠随机化性格/潜力 ★★☆☆☆（受限采用）

**来源**：Fairplay AI 的 "AI Potential streamlined/randomised … random minor faction personalities"、Give Everyone A Chance

**理由**：它确实解决"每局剧情都一样"的问题，但**与约束 ⑤ 冲突**——开局随机化会给结果引入与推理无关的方差。
**受限用法**：只随机化**中立/在野势力**的行为倾向，**不随机化被测席位的起始条件**。而且要**在观测里公开**（模型能查到某中立势力是"好战"还是"守成"），否则就是纯噪声。

### M8｜中立势力用离散性格枚举驱动 ★★★★☆

**来源**：三国志 14 的主义（霸道/王道/割据/我道/名利/礼教）与其明确的攻击欲排序

**理由**：约束 ②（一个枚举值）、③（引擎侧零成本）、⑤（行为可预期，模型可以据此规划——**可预期的对手是特性，不可预测的对手才是噪声**）。
**警告**：绝不能用于被测席位。

### M9｜观战器四件套：自动推进 / 中立观察者 / 视野授予 / 可编程断点 ★★★★★

**来源**：Auto-Run & Spectate AI（WH3）

**做法**：
- **自动推进**：无人介入跑完整局，观察者不参战、不接受外交、不被宣战。
- **视野授予**：可查看任意势力的领地、人物、编成，**以及它当季声明的意图**。
- **断点**：按季号 / 周期 / 手动 / 事件消息暂停。
- **回放**：每季每方的**意图声明**与**执行结果**并排存档。

**理由**：约束 ⑥ 的工程前提。没有这套东西，60 季 × N 局的实验根本没法调试和分析。**而且"意图与结果并排"是过程指标（原则 12）的数据源。**

### M10｜战斗层托管的多档切换 ★★★★☆

**来源**：Spectator Mode（三国）的 Shift+F9/F10/F11/F12 四档

**理由**：对我们不是玩法而是**调试能力**——能在"全自动 / 只看某一方 / 人工接管"之间切换，是排查求解器 bug 的必需品。约束 ⑥。

### M11｜内部状态可视化包 = 观测字段清单 ★★★★★

**来源**：`311SireCustomizedPackageDev/big-guy-examples/` 里的一批包：`显示真实忠诚`、`显示地格实际归属`、`敌军移动范围可视化`、`浮动情报窗显示战力`、`显示相性、与君主相性差、喜好武将和厌恶武将`、`势力外交界面交情显示实数`

**理由**：这是**玩家用二十年投票选出来的"最想知道的状态"**。翻译成我们的观测 schema：
| 社区想看的 | 我们的观测字段 |
| --- | --- |
| 真实忠诚 | 武将的实际留任风险（分档，不给原始数） |
| 地格实际归属 | 郡国控制归属（含争议状态） |
| 敌军移动范围 | **可达性**：敌方兵团下一季能到达哪些郡国（分档距离） |
| 浮动情报窗显示战力 | 兵团战力摘要（不给逐项数值） |
| 交情显示实数 | 势力关系——但**我们要给结构化承诺，不给标量**（见 A12） |

**注意最后一行的分歧**：社区想要"交情的实数"，因为原作把它藏起来了。**但我们不该给一个标量**——标量关系正是外交可被套路的根源。给**承诺清单 + 到期时间 + 违约记录**。

### M12｜郡国人口与地理特性作为势力差异之源 ★★★★★

**来源**：分久必合 UAD（按 190 年史料还原各郡国人口 + 郡国特性 buff/debuff + 人头税 + 战马资源限制高级骑兵）

**理由**：
- 我们的 `commanderies.json` 已含 105 郡国的户口，**这条路的数据基础已经就位**。
- 约束 ⑤：地理与户口是**确定的、可推理的、静态的**信息。模型能通过分析地图得出"南阳的户口值得优先取"这种结论——**这正是我们想测的推理**。
- 约束 ②：郡国属性是稀疏的（大多数郡国无特性），观测里只列有特性的。
- **它把势力强弱的来源从"武将数值表"转移到"地理与人口"**，这在设计上远更健康：武将表是平衡黑洞，地理是史实。

**边界**：UAD 的具体 buff 名称与数值一律不可复制，只借鉴"郡国有特性"这个思路。

### M13｜支城 / 分级据点 ★★★☆☆

**来源**：三国志 11 PK2.2 从 9 代移植的「支城」（可用完整太守自治）

**理由**：分级据点能让地图有纵深而不增加决策点（支城不需要独立决策）。但**我们已有 105 郡国 + 61 节点**，再加一层可能过载。
**建议**：不新增层级，而是把 61 个 `strategic-nodes` 当作"不产出但控通行"的次级据点——效果相同，不增加动作集规模。

### M14｜规则即数据、带版本号（自定义包思路）★★★★☆

**来源**：SIRE 的 `.scp` 自定义包 + 配置文件里可保存加载顺序；AI 增强包"无法跨 MOD 移植"的教训

**理由**：
- 正面：把规则参数**外置成数据 + 版本号**，一局对局要记录用的是哪个规则版本。这对评测的**可复现性**是硬要求。
- 反面警示：如梦似幻的 AI 包与其他 MOD 不兼容，因为"人口系统不同、特技定义不同、粮食系统不同"。**这警告我们：规则参数之间有强耦合，不要幻想"参数任意组合"。要提供的是少数几个经过完整平衡的规则套件（preset），不是一堆可自由拼装的旋钮。**

### M15｜攻城要打补给建筑（血色衣冠）★★★☆☆

**来源**：血色衣冠的攻城重做——设施耐久大增、自愈、主动反击，且须先拆补给建筑

**理由**：把"攻城"从一次判定变成**有前置条件的多阶段过程**，天然拉长决策链，利好长程规划（约束 ⑤）。
**风险**：阶段太多会拖长局长（约束 ⑥）。建议最多两阶段：**围（切断补给）→ 攻**。

### M16｜光环 / 邻接增益 ★★☆☆☆

**来源**：SIRE 的 Aura System（按属性触发、1–2 格范围按阈值扩张）+ 血色衣冠"统帅 >90 解锁光环"

**理由**：约束 ② 与 ⑤ 双重不利。光环意味着**结果依赖精确的空间相邻关系**，而我们的观测**不给坐标只给关系图**（`GAMEPLAY-AI-FRIENDLY.md` 原则 6）。要么放弃光环，要么把它降级成"同一兵团内的将领组合加成"（不依赖地图坐标）——后者可用，★3。

### M17｜"统帅定攻防"而非"武力定攻防" ★★★★☆

**来源**：血色衣冠的核心改动

**理由**：这是把游戏从**个体英雄叙事**推向**统兵能力叙事**。与本项目定位完全一致：我们测的是指挥与规划，不是单挑。
**做法**：`officers.json` 的能力设计（见 `OFFICER-STATS-DESIGN.md`）应确保**统兵向属性主导兵团战力**，个人武勇只影响小概率的风味事件，不影响主线结算。

### M18｜按键派生的随机流，取代全局单一随机序列 ★★★★★

**来源**：三国志 11 的**反面教材**（见 2.7）。全局 `random_value` 单流 + LCG，导致裁决顺序在暗中分配运气、「评定」可洗随机数、SL 大法有效。

**思路**：随机数不是从一条流里"抽"出来的，而是用确定性的键"派生"出来的：

```
draw = H(match_seed, year, season, faction_id, event_kind, event_seq)
```

**理由**（逐条对照约束）：
- **约束 ⑤（稳定转化）**：这是让"更强的推理稳定赢"的前提。全局单流会把与决策无关的顺序噪声算进胜负；派生流把每一次判定的随机性钉死在它自己的坐标上，与别人做了什么无关。
- **约束 ⑥（一局可控）+ 可复现**：回放逐位一致。换句话说，**结果可以被审计**——对一个要发布模型排名的竞技场，这是合法性问题，不是工程洁癖。
- **与 M6（绝对对称）是同一件事的两面**：M6 说不给任何一方加成，M18 说不给任何一方"先手运气"。少了 M18，M6 只是纸面对称。
- **封掉重试漏洞**：随机数在**裁决时**按键派生，不在**请求时**抽取，模型调用重试就不等于重摇骰子。

**副产物**：观测与探查动作必须严格无副作用（不碰随机流）。三国志 11 的「评定洗随机数」证明了，只要免费动作能推进随机流，玩家（以及善于发现模式的 LLM）就一定会把它变成策略通道。

## 九、结论：从 MOD 生态能读出哪些对本项目的设计启示

### 启示 1｜AI 是「所有人都想改、几乎没人改得动」的那一格——这就是本项目的立身之本

**证据**：三国志 11 生态里，换朝代/换皮 MOD 有几十个，数值重制 MOD 有十几个，改地图的不到十个，**动过 AI 的不超过五个可点名的成果，且集中在两三个人手上**。每一次 AI 改动都会被自媒体当作事件报道（"AI 智商终于得到改善"）。全战三国有官方 Lua 接口、单个 MOD 41 万订阅，但**所有 AI 类 MOD 改的都是权重表和预算上限，没有一个改了决策算法**。

**行动**：把"AI 决策质量"作为产品的**唯一核心指标**，其余系统一律为它服务。任何"这个系统很好玩但对区分模型没帮助"的机制，一律砍掉。

### 启示 2｜光荣自己写好了意图层的 API，只是没开放给使用者——我们要把它开放出来

**证据**：`struct_corp` 的 `Policy / Target / MidTermGoal / MidTermGoalTarget / TransportCity`，加上 `CityPolicy / CityTarget` 与 `ForcePolicy`，是一套完整的三层战略意图模型，总共几十个整数。而玩家能碰到的只有 12 个权限位。

**行动**：动作集设计直接采用**"方针 + 对象 + 中期目标 + 中期目标对象"**的四元组形态（自研取值），并确保：意图能指向、执行可解释、失败可归因（6.3 的三条）。这三条做不到，约束 ① 就不成立。

### 启示 3｜AI 的两大失败模式是「死宅」和「添油」，二者都是缺少跨回合承诺

**证据**：韩版 PK2.2 专门优化"后方城市派遣主动性"；自定义包专治"AI 一队一队出来送"；如梦似幻的五项修复里有三项是"敢出兵、能多线、补给跟上"；全战三国 Give Everyone A Chance 存在的理由是小势力不动。

**行动**：
- **每季每方必须产出非空意图**，空转要有可见成本。
- **兵力承诺到"战役对象"**，由求解器一次性解算整场会战，物理上消除逐部队添油的可能。
- 中断驱动的重决策阈值要设计好（什么变化值得叫醒模型），这是约束 ③ 的核心工程。

### 启示 4｜「委任军团」是最有价值的反面教材：抽象层的成败取决于能否被信任

**证据**：玩家一致的做法是"军团只做内政，前线我自己带"。原因是玩家不能选军团长、看不见军团的隐藏战略取向、只能给否定权不能给指向权、失败了无法诊断。

**行动**：mind-arena 的求解器必须交付**执行摘要**：派了谁、走了哪条路、为什么没打成、下一季会怎样。**这份摘要既是给人看的可观测性，也是给模型看的下一轮观测的一部分。** 没有它，模型会像玩家一样"不信任委任"，然后把 token 全花在质疑执行上。

### 启示 5｜绝对对称是竞技场的合法性底线，写进规格

**证据**：Fairplay AI 的存在本身就是控诉——难度靠给 AI 加属性和加隐藏敌意，而不是让 AI 更会打。三国志 14 的势力潜力、全战三国的 faction potential，都让"谁能赢"在开局就基本定死。

**行动**：写进规格文档并做成断言测试：同规则、同观测 schema、同 token 预算、同动作集生成器；引擎不知道席位背后是哪个模型；无任何护航参数；席位轮换。

### 启示 6｜势力强弱的来源要从「武将数值表」搬到「地理与户口」

**证据**：分久必合 UAD 把 190 年郡国人口按史料还原并做成郡国特性，是几十万订阅量级 MOD 的核心卖点；血色衣冠把攻防从武力改统帅，也是同一方向（去个体化）。而三国志 11 生态里 80% 的 MOD 都在改特技表，**说明特技表永远平衡不好**。

**行动**：`commanderies.json` 的 105 郡国户口就是势力差异的主来源。武将能力表要**窄而正交**（见 `OFFICER-STATS-DESIGN.md`），技能效应要少到能在观测里一句话说清。**特技表是平衡黑洞，二十年的 MOD 史已经证明了。**

### 启示 7｜社区做的「状态可视化包」是一份现成的观测字段需求清单

**证据**：真实忠诚、地格实际归属、敌军移动范围、浮动战力、相性/喜好厌恶、交情实数——这是玩家自己动手挖出来的六项。

**行动**：观测 schema 直接对照这份清单（见 M11 的映射表）。**唯一要背离的是"交情实数"**：不要给关系标量，给结构化承诺 + 到期 + 违约记录。标量关系是外交能被套路的根源。

### 启示 8｜观战器的需求已经被一个模组作者写清楚了，照抄即可

**证据**：Auto-Run & Spectate AI（WH3）的四件套：自动推进、中立观察者、任意视野授予（含**目标**）、可编程断点。

**行动**：这是约束 ⑥ 的工程前提，应作为第一批基础设施而不是"以后再说"。特别是**"意图与结果并排存档"**——观战者最想看的不是数值是意图，评测的过程指标也要从这里取数。

### 启示 9｜地图规模要一次定死

**证据**：三国志 11 的 42 城、40000 张地格、1100 武将全是定长数组；二十年里能改地图的作品不到十个，且报道明确指出难点在"AI 运算"而非挪城本身。

**行动**：105 郡国 / 61 节点 / 578 武将这三个数，要在第一版就当作**不可变常量**来设计平衡与 prompt 模板。不要留"以后扩展到 200 郡国"的幻想——那会污染整套数值和所有已跑过的对局。

### 启示 10｜规则要成套发布，不要做成一堆可自由拼装的旋钮

**证据**：如梦似幻的 AI 增强包无法移植到别的 MOD，因为人口系统、特技定义、粮食系统各不相同，"除非完全采用《如梦似幻》的配置"。

**行动**：发布**少数几个完整平衡过的规则套件**（如 `ruleset-194-v1`），每局记录所用套件的版本号。**禁止提供"任意组合参数"的接口**——那会让所有对局数据失去可比性。

### 启示 11｜先行者的坑要提前避开

**证据**：「赛博斗蛐蛐」的四个坑：模型按史实结盟、模型拒战、后勤成为最大失败点、外交承诺难维持。

**行动**：
- 系统提示里明确"这是抽象策略博弈"，并在评测协议里**记录拒答率**作为一个独立指标。
- 观测里剥离历史身份的强暗示，或做显式对照实验。
- **补给的因果链必须在观测里可见且量化**（当前路径、剩余天数、断点风险），否则它就是噪声而不是能力维度。
- 承诺要格式化到可被机器校验，违约要可测量。

### 启示 12｜LLM 当选手，不当裁判

**证据**：HiStrategy 把 LLM 放在世界模拟的位置。这条路对我们不可行。

**行动**：坚持"确定性裁决"。裁判有方差，选手的优劣就被淹没——直接违反约束 ⑤。这一条要写进架构文档的不可协商项。

### 启示 13｜"同时裁决"要成立，先得把随机数从全局单流改成按键派生

**证据**：三国志 11 全游戏共用一个 `random_value`，谁先被遍历到谁吃掉序列里的好数；「评定」这个免费指令能推进序列，玩家据此洗随机数（见 2.7）。

**行动**：把 M18 写进架构文档的不可协商项，与 M6 并列。两者是同一件事的两面——M6 管"不给加成"，M18 管"不给先手运气"；缺了 M18，WEGO 的"同时"只是名义上的，而且**重构一次求解器的循环顺序就会改变对局结果**。另外，观测与探查动作必须严格无副作用：免费且能碰随机流的动作，一定会被善于发现模式的选手变成策略通道。
