## 1. Diagnosis of the existing implementation

### Code size

| File | Lines | Responsibility |
| --- | --- | --- |
| `lib/game/strategy.ts` | 322 | All game rules, factions, resolution, AI |
| `lib/game/historical-map.ts` | 308 | 79 locations, about 100 roads, 4 rivers |
| `lib/game/map-rendering.ts` | 319 | Road-corridor contraction, label layout, administrative polygons |
| `app/game/StrategyGame.tsx` | 655 | All UI |
| `app/game/HistoricalMap.tsx` | 194 | SVG map |
| `app/game/MapSiteIcon.tsx` | 66 | City icons |
| `app/game/game.css` | 743 | Styles |

The git repository has no commits yet; every file is untracked.

### Problem 1: the map is a vector infographic, not a game screen

- The outline of China is a single hard-coded SVG path (`CHINA_OUTLINE`, about 300 coordinate points), nailed into the top of `HistoricalMap.tsx`.
- The city icons are assembled from CSS boxes: `site-wall` / `site-tower` / `site-roof` / `site-gate` are each a `<span>`, using `clip-path: polygon(...)` to cut out the crenellations of the wall and the outline of the roof (`game.css:465-480`).
- The base image `han-terrain-geographic-v1.webp` is stretched to fill with `preserveAspectRatio="none"`, which destroys its aspect ratio.
- The result: the entire picture is made of 1px strokes, linear gradients, dashed lines and `clip-path` polygons — that is the technology stack of an infographic, not of a game.

### Problem 2: the wrong map scale was chosen

```ts
const CHINA_BOUNDS = { west: 73.5, east: 135, north: 53.6, south: 18.2 };
```

The projection covers **the whole of modern China**, including Xinjiang, Tibet and Inner Mongolia. The actual theatre of 194 CE takes up only about 1/4 of the picture, in the centre; the rest is empty plateau. And using modern national borders as the frame of the "theatre" does not hold up historically either.

### Problem 3: gameplay density far below that of a strategy game

- There are only 4 actions: `develop` / `recruit` / `appease` / `march`.
- **Each faction can submit only one order per season** (`resolveStrategyRound` takes one `PlannedOrder` per faction).
- `maxTurns: 20`, i.e. it is over in 5 years.
- There is no officer system: the 18 factions in `FACTIONS` have 1 `leader` each, 18 "officers" in the whole game.
- Combat is a one-line formula comparing two numbers:

```ts
attackPower = 兵力 × (0.78 + 士气/300 + 统率×0.035 + 武力×0.012) × 随机(0.9~1.1)
defendPower = 兵力 × (0.79 + 士气/320 + 防御/500 + 统率×0.028 + 地形 + 节点) × 随机(0.91~1.09)
```

(兵力 troops, 士气 troop morale, 统率 leadership, 武力 might, 防御 defence, 地形 terrain, 节点 node, 随机 random.)

A single comparison decides outright who owns the city. There are no troop entities, no marching, no unit types, no stratagems, no diplomacy, no itemised internal affairs.

### Problem 4: the documents and the implementation contradict each other

`docs/ARCHITECTURE.md` says plainly:

> The Godot 4.7 game client is the primary play surface... It must not render the campaign map as DOM/SVG markers.

And the implementation is exactly DOM/SVG markers. Likewise, `THREE_KINGDOMS_RESEARCH.md` prescribes "the ten-day *xun* as the smallest unit of advance, 36 strategic cycles per year", while the code runs one turn per season, 20 turns in total.

**Conclusion: the three documents describe three different games. Unify the target first, then touch the code.**

## 2. Map technology options

### Why generating an image is a dead end

1. Image generation has a hard resolution ceiling (usually 1024–2048px); covering the whole map is bound to be blurry.
2. No local edits — moving one city means regenerating the entire image.
3. **An image carries no data**: which cell is mountain, which is river, whether it can be crossed, which commandery it belongs to — none of that can be expressed. A strategy game's map is first a data structure and only second a picture.

### Recommended: a tilemap

The terrain grid is both the picture and the data. This is the structure the KOEI *Sangokushi* (三国志, Romance of the Three Kingdoms) series actually uses — the continuous large map of Sangokushi 11, the hex grid of Sangokushi 14.

**Editor**: [Tiled Map Editor](https://www.mapeditor.org/) — free and open source; `.tmx` / `.tmj` is the de facto standard format for 2D game maps and can be read by Godot, Unity and the web alike.

**Web rendering**: [PixiJS v8](https://pixijs.com/) + [`pixi-tiledmap`](https://www.npmjs.com/package/pixi-tiledmap) (2.8.0, still being updated as of August 2026)
- Static tiles are batched by texture into mesh geometry; a large map is no strain
- Supports loading `.tmj` / `.tmx` directly, animated tiles, flipping and rotation, tint colouring, partial updates at runtime
- Zoom, drag and click-select are all handled in the WebGL layer

Alternatives: Phaser 3 (ships with Tiled support, but drags the whole UI into the canvas); or export to the web from Godot 4 directly (which matches the existing ARCHITECTURE.md, but gives up the development speed of the React UI).

### Suggested map scale

Draw only the core area actually held at the end of the Han, and drop the modern national borders:

| Parameter | Suggested value |
| --- | --- |
| Longitude range | about 97°E – 123°E (western end of Liangzhou – Liaodong) |
| Latitude range | about 19°N – 43°N (Jiaozhou – northern edge of Youzhou) |
| Cell edge length | ≈ 10 km |
| Grid size | about 260 × 240 = 62,400 cells |
| Virtual canvas at 32px/cell | 8320 × 7680 px |

As a single image that is a disaster; as a tilemap it is an ordinary size. For reference: the map of Sangokushi 14 is "several thousand hex cells" carrying 46 cities and about 340 districts.

### Data each cell must carry

- Terrain type: plain / hill / mountain / forest / marsh / water / walled city / fortified pass
- Elevation band (affects marching speed and line of sight)
- River bit, road bit (the orientation is used to auto-join tiles)
- Which province / commandery / county it belongs to
- Traversal cost, defence bonus

### Semi-automatic generation of the underlying terrain

This is the key to pushing the workload down:

1. Map public-domain DEMs (SRTM / GEBCO / Natural Earth hillshading) onto terrain types by elevation threshold
2. Lay the river network from Natural Earth rivers / HydroSHEDS
3. **Fix the course of the Yellow River by hand** — after Wang Jing (王景) regulated the river in the Eastern Han it ran along the "Eastern Han old course", from north-east of Xingyang (荥阳) out to sea near present-day Lijin in Shandong, very different from today's course; automatic generation is guaranteed to get it wrong
4. Hand-refine the surroundings of cities and passes

### D. Geographic base data

| Source | Licence | Use |
| --- | --- | --- |
| Natural Earth | Public domain | Coastlines, rivers, terrain hillshading |

## 4. Mechanics research: how many stat dimensions

### Officer stats (the KOEI canon, the version players agree on most)

The five stats as defined in the [official manual](https://www.gamecity.ne.jp/manual/sangokushi8-re/jp/3300.html) of *Sangokushi 8 REMAKE* (三国志 8 REMAKE):

| Stat | Effect |
| --- | --- |
| 統率 (Leadership) | Unit attack, defence, action order, repair effect |
| 武力 (Might) | Battle-tactic effect, strength in single combat, public order |
| 智力 (Intelligence) | Battle-tactic effect, stratagem success rate, debate, magnitude of technology effects |
| 政治 (Politics) | Land reclamation, commerce, effect of remonstrance |
| 魅力 (Charm) | Recruitment, alliance success rate |

The systems that go with the five stats:

- **Skills (特技)**: grouped by system, Lv3 at most; training every skill of one system to Lv3 unlocks a special skill
- **Battle tactics (战法)**: combat-only, Lv3 at most, learned by spending "insight" (心得)
- **Innate talent (奇才)**: an intrinsic ability on some officers, heritable
- **Fame (名声)**: three kinds — martial fame (武名) / literary fame (文名) / infamy (恶名) — affecting interaction and story events
- **Training (锻炼)**: raise stats at one's residence; officers of compatible affinity assist more effectively
- Stats cap at 100 (an officer starting at 99 or below can only grow to 99)
- Also: affinity (相性), sense of duty (义理), personality (性格), ideology/ambition (主义/志)

### Faction attributes

Gold, provisions, troops, number of cities, fame/prestige, noble rank, diplomatic relations (alliance / truce / hostile), technology.

### Map scale, side by side

| Title | Cities | Map structure |
| --- | --- | --- |
| Sangokushi 11 | 42 | Continuous large map + passes and ports |
| Sangokushi 14 | 46 | About 340 districts over several thousand hex cells |
| Sangokushi 8 Remake | 51 | Zoned region map |
| **This project today** | **69 contestable / 79 points total** | SVG points |

## 5. Historical strongholds: where the ceiling on completeness lies

### The authoritative list: the *Treatise on Commanderies and Kingdoms* in the *Book of the Later Han* (后汉书·郡国志)

Sima Biao's (司马彪) *Treatise on Commanderies and Kingdoms* in the *Continued Book of Han* (续汉书·郡国志), folded into Fan Ye's (范晔) *Book of the Later Han* (后汉书), records the cross-section at **the fifth year of Yonghe under Emperor Shun of Han (汉顺帝永和五年, 140 CE)**:

- **Provinces: 13** (the Colonel-Director of Retainers' region 司隶校尉部 plus the twelve provincial inspectorates)
- **Commanderies and principalities: 105**
- **Counties, towns, marches and marquisates (县、邑、道、侯国): 1180**
- 9,698,630 households, 49,150,220 individuals

By comparison: at the end of the Western Han there were 103 commanderies and 1587 counties; English Wikipedia, counting on another basis, gives 99 commanderies and 1179 counties for the Eastern Han (the difference comes from whether the dependent states 属国 and the Western Regions Chief Clerk's office 西域长史府 are counted). The count in the original text of the *Treatise on Commanderies and Kingdoms* is the one that governs here.

**The seats of the thirteen provinces** (140 CE):

| Province | Seat |
| --- | --- |
| Sili (司隶) | Luoyang |
| Yuzhou | Qiao County (谯县) |
| Jizhou (冀州) | Gaoyi (高邑) |
| Yanzhou (兖州) | Changyi (昌邑) |
| Xuzhou | Tan County (郯县) |
| Qingzhou (青州) | Linzi (临淄) |
| Jingzhou (荆州) | Hanshou (汉寿) |
| Yangzhou (扬州) | Liyang (历阳) |
| Yizhou (益州) | Luo County (雒县) |
| Liangzhou (凉州) | Long County (陇县) |
| Bingzhou (并州) | Jinyang (晋阳) |
| Youzhou (幽州) | Ji County (蓟县) |
| Jiaozhou (交州) | Longbian (龙编) |

Note: by 194 CE the provincial seats had already changed from those of 140 (Jingzhou seated at Xiangyang 襄阳, Yizhou at Chengdu 成都, Yanzhou at Juancheng 鄄城); the scenario has to be corrected to 194.

### Suggested stronghold tiers

| Tier | Count | Capturable | Notes |
| --- | --- | --- | --- |
| Province | 13 + Sili | — | A strategic zoning, not a stronghold |
| Commandery | **105** | Yes | A hard target; every one can be checked line by line against the *Treatise on Commanderies and Kingdoms* |
| County / town / march / marquisate | **1180** | Some | Secondary strongholds, resource points, march nodes |
| Pass | ~30 | Yes | Hulao (虎牢), Hangu (函谷), Tong Pass (潼关), Wu Pass (武关), San Pass (散关), Jianmen (剑门), Yangping (阳平), Baishui (白水), Hu Pass (壶关), Jingxing (井陉), Feihu (飞狐), Juyong (居庸), Jiameng (葭萌)… |
| Ford | ~15 | Yes | Guandu, Baima (白马), Yanjin (延津), Puban (蒲坂), Mengjin (孟津), Liyang (黎阳)… |
| Port | ~15 | Yes | Xiakou (夏口), Ruxukou (濡须口), Niuzhu (牛渚), Hukou (湖口), Jiangjin (江津), Hanjin (汉津)… |
| Granary / salt-and-iron office | ~10 | Yes | Economic nodes such as the Ao Granary (敖仓) and the Liyang Granary (黎阳仓) |

**This is what "more complete than the existing Three Kingdoms games" concretely means: all 105 commanderies, plus the 1180 counties as a secondary tier — one to two orders of magnitude more than the 42–51 cities of the Sangokushi series.**

Today's 79 points are about 15× short of that target.

### How to get the data

1. **The original text of the *Treatise on Commanderies and Kingdoms* (后汉书·郡国志)** ([full text on ctext.org](https://ctext.org/hou-han-shu/jun-guo-yi), public domain) — the authoritative list of the commanderies and their subordinate counties; a script can extract "commandery name + list of subordinate counties + household figures"
2. **Tan Qixiang's (谭其骧) *Historical Atlas of China* (中国历史地图集), volume 2 (Qin · Western Han · Eastern Han)** — the positional reference. **It is under copyright: manual cross-checking only, no scanning and no tracing**
3. **CHGIS / Fudan TGAZ** (CC BY-NC) — coordinate checking; does not go into a commercial product
4. **Wikidata** (CC0) — a source of coordinates usable commercially

Workload estimate:
- Manually calibrating the coordinates of 105 commandery seats: 1–2 days
- The 1180 counties: first auto-extract names and parent relations from the text of the *Treatise on Commanderies and Kingdoms*, then place the coordinates semi-automatically by "neighbourhood of the commandery seat + modern place-name matching", then refine province by province

## 6. Decisions that have to be made first

1. **Fix the rendering layer**: React + PixiJS tilemap, or Godot 4 exported to the web? The existing ARCHITECTURE.md says the latter, the code does the former; it has to be one or the other.
2. **Turn granularity**: one order per season (today) / one batch of orders per ten-day *xun* (the research document) / by month? This decides the cost model for AI calls.
3. **Stronghold scale for the first version**: do the 105 commanderies first, or go straight down to county level?
4. **Art style**: pixel art (with the B.B.Bits ecosystem) / old-map ink wash / realistic colour painting? This decides the direction of every asset purchase that follows.

## 7. Decisions already taken (2026-08-31)

| Decision | Conclusion |
| --- | --- |
| Rendering layer | **React + PixiJS tilemap**. Keep the existing React / Cloudflare platform shell and the OpenRouter integration; replace the map area with a PixiJS WebGL tilemap. The clause in `ARCHITECTURE.md` making "Godot the primary play surface" is void and has to be rewritten. |
| Stronghold scale for the first version | **All 105 commanderies plus about 60 passes / ports / fords / granaries**, roughly 165 contestable strongholds in total. The 1180 counties are left to a later version as a secondary tier. |
| Art style | **Old-map ink wash**. The campaign map takes Sangokushi 11-style ink-wash mountains and rivers; officer portraits are based on public-domain Qing illustrated woodblock prints, aged and coloured. All tiles are drawn originally; no pixel assets are purchased. |

### Constraints that follow from the decisions

- There is no ink-wash tileset on sale, so the terrain tiles have to be original. To bring the cost down, the terrain layer takes a hybrid route — "procedurally generated ink-wash texture + hand-drawn key features" — rather than hand-drawing cell by cell.
- Neither the B.B.Bits pixel series nor Kenney's CC0 assets enter the production art pipeline; they may serve only as placeholders during technical validation.
- Public-domain illustrated woodblock prints are the only confirmed usable source of character art; a standard cropping, ageing and colouring process has to be established.

## 8. A second pass over the asset marketplaces (after the ink-wash decision)

Once the style was fixed as old-map ink wash, the major asset marketplaces were searched again along that line. Conclusion: **finished art packs are basically useless; what is actually valuable is two kinds of raw material — "real ink brushstrokes" and "public-domain old maps".**

### What cannot be used

| Marketplace | What turned up | Why it does not work |
| --- | --- | --- |
| Unity Asset Store | [Chinese Ink Painting](https://assetstore.unity.com/packages/3d/environments/chinese-ink-painting-249173) (3D environment), [Dissolvable Ink Painting Effects](https://assetstore.unity.com/packages/vfx/shaders/dissolvable-ink-painting-effects-321588) (VFX shader), [Ancient China Sprite Pack](https://assetstore.unity.com/packages/2d/characters/ancient-china-sprite-pack-183923) | All 3D/shader, not 2D map assets. **More to the point: the Unity Asset Store licence only covers Unity projects** — we use PixiJS, so buying it would not make it legal to use |
| Fab (formerly the Unreal marketplace) | Only generic brushes and a Concept Art Shader Pack | Likewise tied to an engine, and no Chinese ink-wash content |
| itch.io | Pixel tilesets such as the B.B.Bits Three Kingdoms series | Pixel art conflicts with the ink-wash style already decided on |

### Valuable, part one: real ink brushstrokes

The biggest weakness of procedurally generated tiles is that the strokes are "mechanical" — a line drawn by an algorithm has none of real ink's tonal gradation, flying white (飞白), or bleed into the fibres of the paper. The fix is **to use scans of real ink as the brush material and let the program control placement and density**, getting both real texture and seamless control.

| Resource | Contents | Licence |
| --- | --- | --- |
| [Sumi Strokes](https://myphotoshopbrushes.com/resources/444/sumi-strokes-photoshop-brushes) (Denny Tang) | 82 strokes, 1250px (a 2500px version is on the official site), ABR format | **Free for Commercial Use** |
| [Brusheezy Sumi-E](https://www.brusheezy.com/free/sumi-e) | 857 free brushes | CC and others; each has to be confirmed individually |
| [TASHIRO SUMI-E Pack](https://cubebrush.co/tashiro/products/rykblw/affinity-sumi-e-ink-pack) | 32 ink-blot PNGs + 64 brushes, **real ink hand-painted on xuan paper (宣纸), 300dpi** | Paid; personal and commercial use permitted |

ABR is the Photoshop brush format; [`abrupng`](https://github.com/scurest/abrupng) (Rust) or [PSBrushExtract](https://github.com/MorrowShore/PSBrushExtract) (Python) can batch-convert it into greyscale PNGs with alpha, which plug straight into the existing Node/sharp pipeline.

### Valuable, part two: public-domain old maps

| Source | Licence | Notes |
| --- | --- | --- |
| [Library of Congress Chinese maps](https://www.loc.gov/maps/index/subject/?fa=language:Chinese) | Public domain (US government work) | Its collection of Chinese maps is one of the most complete outside Asia |
| [PICRYL](https://picryl.com/collections/ancient-maps-from-the-library-of-congress) | Public-domain aggregator | Convenient for bulk searching |
| Shuge (书格) shuge.org | Scans of Chinese classical books and old maps | Terms have to be confirmed item by item |

Historical maps themselves serve as **a reference for cartographic vocabulary** (how mountains are drawn, the brushwork of the hydrology, how labels are arranged, the ornament of the map border) — not as something pasted straight into the game.

### Two traps that must be avoided

**The David Rumsey Historical Map Collection** — 147,000 high-resolution historical maps, which looks like a treasury, but the digitised images are licensed **CC BY-NC-SA 3.0, which explicitly forbids commercial use**; commercial use requires contacting carto@davidrumsey.com separately. Research reference only.

**Aigei (爱给网, aigei.com)** — a great many ink-wash, Chinese-style and game-map assets, but its [copyright statement](https://www.aigei.com/about/copyright) says "the copyright in works of unknown copyright belongs to the original authors… this site accepts no liability whatsoever for disputes arising from unlicensed use", and the portraits and cartoon figures inside the templates may not be used commercially. Not safe for a commercial project.

### The revised art pipeline

```
真实墨迹扫描（ABR → PNG alpha）
        ↓  程序控制摆放：位置、旋转、缩放、浓淡、密度
地形区域轮廓（由 tilemap 数据聚类提取）
        ↓  沿轮廓分层合成
连绵山体 / 林带 / 水系 / 宣纸底
        ↓
Runware 生成的独立资源：城池图标、关隘港口图标、武将立绘、事件插图、UI 装饰
```

(Scans of real ink (ABR → PNG alpha) → program-controlled placement: position, rotation, scale, tone, density → terrain region outlines (extracted by clustering the tilemap data) → layered composition along the outlines → continuous mountain masses / belts of woodland / hydrology / xuan-paper ground → standalone assets generated with Runware: city icons, pass and port icons, officer portraits, event illustrations, UI ornament.)

The terrain layer carries zero copyright risk and is fully controllable; the standalone icon layer is filled in with a generative model. The two are not mixed.

## 9. The *cun*-texture-stroke asset pipeline (shipped)

### Why not use an off-the-shelf brush pack

The original plan was to buy sumi-e brushes ([Sumi Strokes](https://myphotoshopbrushes.com/resources/444/sumi-strokes-photoshop-brushes) and the like); in practice the download endpoint is behind a Cloudflare challenge, and the stroke vocabulary of Japanese sumi-e is not the same as the *cun* texture strokes (皴法) of Chinese landscape painting.

Switched to **extracting directly from public-domain Chinese landscape paintings**, which is both more on-subject and legally cleaner:

| Painting | *Cun* type | Size | Licence |
| --- | --- | --- | --- |
| Li Tang's (李唐) *Wind in the Pines Among a Myriad Valleys* (万壑松风图) | axe-cut *cun* (斧劈皴) → mountains | 2087×2882 | CC0 |
| Huang Gongwang's (黄公望) *Dwelling in the Fuchun Mountains* (富春山居图, the Wuyong Master scroll 无用师卷) | hemp-fibre *cun* (披麻皴) → hills | 26134×900 | Public domain |
| Fan Kuan's (范宽) *Travellers Among Mountains and Streams* (谿山行旅图) | raindrop *cun* (雨点皴) → rock bodies | 2809×5633 | Public domain |
| Guo Xi's (郭熙) *Early Spring* (早春图) | rolling-cloud *cun* (卷云皴) → mountain ridges | 1952×2839 | Public domain |

All from Wikimedia Commons. `tools/fetch-refs.mjs` can re-download them (about 26MB, stored in `refs/`, which is already in `.gitignore`).

### The extraction algorithm

`tools/extract-cun.mjs`: grid scan → score → take the high-scoring blocks → remove the silk ground colour → output single-channel alpha stamps.

The scoring function is the crux — three factors multiplied together:

- **energy**, stroke density (total horizontal and vertical gradient)
- **isotropy**, the degree of isotropy, cubed. Real *cun* strokes have energy in both the horizontal and the vertical; the mounting edges of a scan and hard edges have it in one direction only, and cubing pushes them close to zero. **Without this factor, the first round of axe-cut *cun* extraction came back as nothing but hard horizontal bands from the mounting**
- **tone**, how moderate the amount of ink is; both blank silk and a solid block of dark ink are penalised

Also: a 6% margin crop (to stay clear of the mounting and the colophons), a minimum distance between blocks (so they do not all crowd onto the same mountain), and a score threshold (anything below 35% of the top score is not taken).

Output: 31 single-channel 256×256 stamps in `public/game/ink/`, plus `manifest.json` (carrying the source painting and the licence).

### One pit already fallen into

Two rounds of debugging went into fixing "horizontal scan stripes"; in fact **the stripes were a bug in the preview code** — the extracted PNGs are 3-channel, and the preview indexed them as 1-channel, which shifted every row. The standard deviation of the row means in the source image is only 1.53/255; there were no stripes to begin with.

The destriping function `destripe()` is kept (it still has value for other scans), but it should be clear that it is not a necessity for this batch of material.

### Still to improve

- The blocks taken for axe-cut *cun* (Li Tang) are on the empty side, mostly plain silk; the scoring parameters for that painting need separate tuning
- What comes out are **fragments of the painting** rather than pure brushwork, containing recognisable objects such as trees, houses and boats. As terrain texture fill that is in fact appropriate (an ink-wash map is like that anyway), but using them as "brush stamps" would require stripping the objects out further

## 10. Three reworks of the terrain rendering, and the final approach

The first version of the map was judged to have "no sense of terrain; the black-and-white blotches cannot be read as anything". Three routes were tried in turn; only the third holds up.

### 1. *Cun*-texture fill (abandoned)

Cluster the terrain regions into connected components and lay real *cun* ink inside them. The result is clumps of ink blots whose meaning cannot be read —
**texture fill can only give light and dark, it cannot give the semantics of "this is a mountain"**.

### 2. *Hua Yi Tu*-style symbols (abandoned)

Instead, draw the "mountain" glyph of old Chinese maps (古舆图): sharp peaks, clear separation of peak and valley, solid dark ink, arranged along the ridges.
Each symbol on its own is right, but tiled across a whole area it becomes a repeating pattern — zoom in and it is the same triangle repeated several thousand times.
Old maps get away with it because the whole sheet has only a few hundred symbols and a great deal of empty space; a game map has to hold up at any zoom level,
and once symbol density goes up it is bound to degenerate into wallpaper.

### 3. Terrain hillshading (adopted)

What makes a map of the Sangokushi 11 kind read as mountains at a glance is not whether the symbols look right, but **lighting** —
ridges facing the light, back slopes falling into shadow, light and dark modelling volume. This is a rendering problem, not a question of drawing technique.

The pipeline:

1. **Elevation**: `tools/fetch-dem.mjs` pulls AWS Terrain Tiles (terrarium encoding, public domain),
   575 tiles at z=8, stitched into a 6400×5888 Int16 raster
2. **Resampling**: Web Mercator → equirectangular, bilinear
3. **Hillshading**: slope and aspect from Horn's third-order finite difference, light direction 315°/42° (the cartographic convention of light from the north-west),
   vertical exaggeration 5.5×. The east-west pixel span has to be multiplied by cos(lat), or terrain at high latitudes gets flattened
4. **Colour**: a silk-ground colour wash banded by elevation (fresh green along the coast → farmland on the plains → ochre hills → grey-white at the snow line),
   then a layer of silk yellow over it to kill the cool cast of a modern atlas
5. ***Cun* strokes**: the real-ink stamps land only on steep slopes and are brushed along the contour lines, pulling the photorealistic hillshading back into an ink-wash register
6. **Faction territory**: a two-pass chamfer distance transform with label propagation, sourced from the 105 commandery seats,
   giving a smooth approximate Voronoi in O(W·H). The earlier version did brute-force nearest-neighbour at 1/4 resolution, and the borders were visibly jagged

The output is 4620×3780, cut into 512px webp tiles over three levels, 106 tiles and 4.5MB in total (PNG would need 15.7MB).

### The key lesson

Both of the first two versions were agonising over "do the symbols look enough like mountains", and the direction itself was wrong. The solidity of terrain comes from lighting,
not from brushstrokes. Real elevation data was in hand the whole time; hillshading should have been step one.

## 11. The label layer: why it cannot be baked into the base image

Eight passes and fords around Luoyang (Xiaopingjin 小平津, Mengjin 孟津, Hulao Pass 虎牢关, the Ao Granary 敖仓, the Han Hangu Pass 汉函谷关, Yique Pass 伊阙关, Huanyuan Pass 轘辕关,
plus Henan Yin 河南尹 itself) are packed into about 1.5 degrees of longitude. The first version baked the place names and symbols into the raster, with the result that:

- At every zoom level the **type size and the density are fixed** — zooming in does not loosen them
- The names are bound to overlap, and there is no remedy

### Reference

The Sangokushi 11 map is 200×200 cells, 42 cities + 10 passes + 35 ports = 87 nodes, browsed entirely by scrolling,
never shown in one screen. The place names are a **UI layer**, not part of the map texture. This project is 330×270 cells with 166 nodes:
a comparable node density. The problem lies only in how the labels are implemented.

### The approach

The base image bakes only the terrain hillshading, the faction territory and the hydrology; labels move to live drawing in PixiJS screen space:

1. **Constant on-screen type size** — not transformed by the world zoom, so zooming in yields more room
2. **Tiered display**: each label gets a rank by population and type (commanderies 0–3, passes 2, marches/granaries 3, fords/ports 4),
   and the zoom factor decides which ranks are let through
3. **Greedy collision avoidance**: province names claim their space first, then the rest in descending order of rank and population, each trying right / left / above / below;
   if all four are crowded, the label is not shown at this level and appears naturally once zoomed in
4. The symbols themselves also enter the occupancy table, so that someone else's text does not sit on top of a walled city

Besides the base image, `tools/render-terrain-map.mjs` also exports `public/game/data/map-labels.json` (166 entries + 13 provinces).

### Territory division changed to a terrain-weighted shortest path

The Voronoi border of Euclidean nearest-neighbour is a perpendicular bisector, and the pieces it cuts out look like modern administrative divisions.
Instead, give every pixel a traversal cost (rising with the square of the slope, water 6.0) and run multiple passes of chamfer
propagation with label propagation until convergence — the borders then fall naturally on the ridgelines and the great rivers. Guanzhong (关中) is walled off by the Qinling (秦岭) and the Yellow River,
Hanzhong (汉中) forms a block of its own, which matches the historical geography.

### Base-image specification

z=9 elevation (12288×11520), rendered at PPD=220 → 7260×5940,
cut into 512px webp tiles over four levels, 244 tiles and 11MB in total.
