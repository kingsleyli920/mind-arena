# 战略决策时间线与命令对应（2026-09-29）

## 改动与事先约定

上一轮六次有无收据对照显示：收据已进入模型请求，但 Nano 仍把己方辽西当作尚未取得的目标，还把被拒绝的同源命令说成已执行；Flash-Lite 认出迁治，却混淆旧失城与当前断供。

第一阶段只改静态系统提示词，版本 1.19.0 → 1.20.0。提醒模型分清待决策季与刚结算的季、用当前 `seat`/`mine`/`armies`/`planFeedback` 核对战报、把 `picks` 当作尚未结算的意图，并核对计划文字与所选命令的地点和数量。同时纠正旧提示中不存在的 `armies[].supply` 字段引用。游戏规则、候选、准入、存档和结算不变。

固定三个自然后续局面，各只测一次原模型，共三次低价真实请求。局面来自[上一轮有收据分支](reports/decision-correction-2026-09-28/live.json)，新请求要求 observation、schema、reasoning 与旧请求逐字一致，只有 system 变化。端点价格在请求前重新查询；每次最多两次尝试，输出最多 8000 tokens、输入最多 70 KB，总费用预留不超过 $0.20。不会因为模型没纠正就自动增加样本或重试。

人工复核标准在付费前确定：

| 局面 | 需要核对的事实 | 主要观察点 |
|---|---|---|
| Nano 多线 | 辽西已属己方，上季同源倾国出兵被拒 | 不再写辽西未得；不再选同源双征伐；不把拟下命令写成已执行 |
| Nano 围城 | 上季攻东海被拒，本季无己方野战军，下邳仓廪/铁官已建 | 不虚构持续的东莱围城；计划文字与 picks 的建筑地点、出兵方向相符 |
| Flash-Lite 迁治 | 当前治所在广陵，只有琅邪断供；失东海发生在更早季 | 不说当前仍全境断供；分清当前治所与旧战报；少选超额令 |

模型可能随机变化；每例一个新样本只能观察具体错误有没有出现，不能证明提高棋力或普遍可靠。对照使用旧请求的真实响应，不因旧响应在新提示下被免费重放就冒充新的模型回答。

## 验证结果

### 第一阶段：只加强静态提示词

三次真实决策、五次传输尝试均成功，上报费用 $0.00628661。每个请求的 observation、schema 和 reasoning 与上轮同局面收据组逐字相同，只有 system 提示变化。205 项全套测试、TypeScript、ESLint、生产构建及 93 席季观测预算均通过，观测峰值 9833 / 10000。三次真实响应已免费重放，命令准入与完整结算状态一致。

结果：Nano 多线局 6 条采纳、0 拒令，但仍声称己方辽西“尚未取得”；围城局 7 条采纳、0 拒令，仍原样写在下邳兴建已存在的仓廪/铁官，并描述已经不存在的东莱围城。Flash-Lite 迁治局 8 条采纳、3 条刺探超额拒令，仍说当前全境断供，实际当前仅琅邪断供。**更明确的静态文字未解决事实与计划对应。** 三个样本的拒令数变化不能证明普遍减少。

### 第二阶段：候选之后的事实摘要（付费前约定）

观察到候选列表位于观测末尾且很长，前面的计划与战报可能被淹没。因此 observation 1.6.0 在候选之后增加 `decisionFocus`，重述当前季、现治所、断供郡、现存出征、旧目标归属和刚结算季的得失。它只用模型已能看到的己方或公开事实；长列表只列前三例并标总数，避免观测超预算。

仍固定上述三个状态、模型、提供方与推理档，各请求一次。与第一阶段逐项比较：system、schema、reasoning 完全相同；去掉 `decisionFocus` 和版本号后，其余 observation 完全相同。复核标准沿用上表：尤其看辽西归属、东莱围城是否仍在、广陵现治所和断供范围，以及计划文字与本季命令。费用预留上限仍为 $0.20，每次最多两次传输尝试；不因答案不理想追加调用。单样本只能陈述具体输出，不能证明平均棋力变化。

免费预检与 TypeScript、ESLint 已通过。93 席季观测峰值 9969 / 10000，余量很窄，后续扩大输入前需重新测预算。

第二阶段已在两次 Nano 响应后因 Flash-Lite 提供方返回空内容而停止，无自动重试。Nano 多线局仍把己方辽西写成未取得，仅采纳 2 条；围城局选择下邳同源三路进攻，其中 2 条冲突被拒，旧围城文字仍重复。成功响应和空内容故障都已免费重放；保留[第二阶段不完整原始记录](reports/decision-guidance-2026-09-29/phase2-live-partial.json)与[部分重放](reports/decision-guidance-2026-09-29/phase2-replay-partial.json)。上报费用 $0.00231652，保守占用 $0.01466112；第三次请求费用未知，工具保留其预留。该阶段无法评价 Flash-Lite 的新输出。由于已返回样本没有解决目标错误，且峰值只剩 31 tokens，**撤回 `decisionFocus`**。

### 第三阶段：只重置客观失效的进攻记忆（付费前约定）

前两阶段都显示 Nano 严重依附上一季的“攻取辽西”旧计划，即使当前归属已经是己方。第三阶段用确定事实处理这一种情形：旧计划为 attack、目标现在属己方、且目标未被围时，下一季输入的 `plan` 置为 `null`，同时提供 `planReset.target` 和原因。原计划仍留在对局记录，不改模型原文；守住己方目标或被围时不触发。判断基于己方与公开归属，不读取敌方隐藏状态。此时 observation 1.6.0 与 prompt 1.21.0。

仅对公孙度多线局调用 Nano 一次。与第一阶段同一状态、模型、提供方、候选及推理档；除 observation 版本、`plan` 清空、`planReset` 和对应系统说明外，其他字段必须一致。判读重点：它是否停止声称辽西未得，是否提出与命令一致的新目标；准入与一季结算仍单独记录。一次结果仍不能证明长期稳定改正。

默认预检、11 项针对测试及 TypeScript 已通过；评测口径观测预算仍需最终收集。最多两次传输尝试、输入 70 KB、输出 8000 tokens、该阶段预留上限 $0.20；不会对第二阶段的空壳请求重试。

第三阶段真实 Nano 请求成功，2 次传输尝试，上报费用 $0.00173696，保守占用 $0.00784016。输入确实为 `plan: null`、`planReset.target: 辽西郡` 和 `planFeedback.ownership: own`。与第一阶段同局面输入相比，除预期的 plan/planReset/版本及系统说明外，其他观测、候选 schema 与 reasoning 一致。

模型的新计划不再声称“辽西尚未取得”，从旧的进攻目标转为以东海及周边扩张，`target: null`、`stance: develop`。但它仍把状态写为 `continue`，被客观校验标记为目标/方向变化；9 条所选命令有 6 条获采纳，3 条被拒（同源出兵 1、同郡建设超额 2）。这一季结算还失去了东海。**这个样本只说明旧目标错误被打断，不说明模型能稳定写对计划或赢得更好。**

真实响应及免费重放分别见[第三阶段实测](reports/decision-guidance-2026-09-29/phase3-live.json)和[重放](reports/decision-guidance-2026-09-29/phase3-replay.json)。重放的请求、计划、准入、己方战报与完整结算状态哈希一致，费用 0。

最终保留第三阶段的客观失效旧计划重置，撤回第二阶段的末尾摘要。最终版本为 prompt 1.21.0 / observation 1.6.0，未改变包或存档版本。206 项全套测试、TypeScript、ESLint、生产构建、9 份历史响应 18 次免费回放均通过。93 席季观测峰值 9833 / 10000；这项检查没有覆盖所有更长统一局面。第三阶段的限制是单模型单局面、且旧状态最早源于人工预设计划；不把它当成模型平均能力的证明。
