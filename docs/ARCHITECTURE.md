# Mind Arena 架构

Mind Arena 是一个网页三国战略游戏，同时用作比较不同大语言模型的竞技场。
游戏本身要成立——策略深度、历史质感、可玩性；模型对战是它的用法，不是它的替代品。

## 技术栈

| 层 | 选型 | 说明 |
| --- | --- | --- |
| 应用 | React 19 + vinext（Vite 上的 Next.js） | 部署到 Cloudflare Workers |
| 地图渲染 | PixiJS v8 + 多级瓦片 | 底图离线渲染成瓦片，标注为实时 UI 层 |
| 引擎 | TypeScript 纯函数 | observe / listActions / validate / resolve / replay 五段式 |
| 内容 | JSON 内容包 | 规则即数据，见下 |
| 数据构建 | Node + sharp 脚本 | `tools/`，全部可重复运行 |

**已作废的决策**：早期文档写「Godot 4.7 为主要游玩表面，不得用 DOM/SVG 渲染战役地图」。
实际选型是 React + PixiJS，理由见 `RESEARCH-2026-08-31.md` 第七节。

## 规则即数据

游戏内容——动作、数值常数、地形、兵种、适性、胜负判据——全部写在
`lib/game/content/*.json`，引擎只按数据执行。

这不只是可配置性。**同一份定义既驱动引擎，又通过 `toRulesDigest()` 生成
模型提示词里的规则说明。** 若规则硬编码在 TS 中，就必须另写一份给模型看的
文档，两份随迭代必然漂移——模型算出来的和引擎结算的对不上，评测即失效。

`lib/game/content/schema.ts` 提供类型契约、校验器与摘要生成。
校验器拦截的是设计错误而非恶意输入：动作无代价（会被无限刷）、
档位超过 4 个（模型难权衡）、说明过短（模型不知何时该用）、兵种相克引用不存在的兵种。

### 哪一层用像素，哪一层用矢量

判据只有一条：**线用矢量，染用像素**。栅格金字塔总有个头——z4 在 1181 逻辑像素的
画框上，放到十四倍仍要拉伸 2.28 倍；再切一级要 700MB 源图与两千八百块瓦片，
而下一次还要再翻一倍。但拉伸最扎眼的是线（河岸、疆界这种一笔下去的边），
不是那片渐变的染。所以：

| 层 | 形式 | 为什么 |
|---|---|---|
| 地势晕渲、皴、设色 | 瓦片（z1–z4） | 是**染**，拉伸看不出来；且它是逐像素算光学深度画的，浏览器跑不动 |
| 疆域色域 | 画布（0.1° 格网） | 是染。近观档不糊边、色让到 55%，让地形透出来 |
| 疆界墨线 | SVG 两条 path | 是线。3265 段、147KB 的 d 串，任意倍数都是实的 |
| 水系（河、海岸） | SVG path | 是线。4473 个点、90KB，河宽照抄底图那条水力几何式 |
| 道路 | SVG line | 是线。232 条边按地形分笔法 |
| 城郭 / 关津 / 军团 | PNG 贴图 + 遮罩上色 | 是**画**。离线用 brush.mjs 渲，每类多幅，按名字哈希取 |
| 牌记与题记 | SVG text | 屏幕空间贪心避让 |

标注不烤进底图——烤进去就在所有缩放级别固定大小固定密度，洛阳周边八个关津必然重叠。

### 分档

三档，与瓦片那几级同呼吸：远观（k<1.6）只出疆域、州名、城印；中观（<3.2）出关与港、
铺开郡名；近观（≥3.2）据点全出并标名、城画成城郭、水系与道路提亮。
分档的理由不是性能，是**一张图放不下**。

图元按 1/k^0.82 缩：图上缩得比屏幕放得快，放大才真的把挨在一起的城分开
（京兆尹与左冯翊图上只隔 16 像素）。缩小时靠贪心避让，让位者留一枚小点。

### 实测

- 缩放时中位帧 8.3ms、九分位 10ms；过瓦片档时一次 60–120ms 的解码卡顿，
  整个缩放区间发生三次，大半被 280ms 的镜头缓动盖住。
- 疆界的 strokeWidth 曾按倍数连续变，改一次浏览器要把三千多段曲线的笔画几何
  重算一遍；改成按档位给三个值。
- 悬停与静止都是 0 条 longtask，强制布局 0.3ms。

**量之前先验尺子。** 自动化浏览器会把 rAF 限到 1Hz（窗口被遮挡或无头时），
那时一切 rAF 量法都会报出「每帧 1000ms」「悬停 1.8 秒」这类假象——本仓库
据此误判过两次，改用 `PerformanceObserver('longtask')` 与同步强制布局才看清。
先量一串静止时的帧间隔：整齐的 1000ms 就是限帧，不是卡。

### 矢量层为什么不在 .map-stage 里

画心（瓦片、海波、疆域画布）挂在一个被 `transform: scale(k)` 放大的舞台上；
矢量层若也挂在那儿，十四倍下就是一层 16531×13526 CSS 像素的东西，而看得见的
只有一屏。它单独铺满画框、内部用一个 `<g>` 做同样的平移缩放，**不给 viewBox**
（viewBox 比例与元素比例不一致时，默认的 preserveAspectRatio 会整层缩放再居中，
矢量层就与底图错开；实测横向偏差 −73/−56/−24 像素，随位置变）。

对齐靠 `box`（画框实测尺寸）。它此前一直停在初始值 1200×980：观察者挂在
`useEffect + []` 里，而那一次 effect 在选席页就跑了，那时地图还没渲染、
ref 是 null。改用回调 ref 之后，静止探针的对齐偏差是 0/0。

## 对局协议

模型只在「意图层」决策，执行交给确定性求解器：

1. `observe` — 分层观测，硬 token 预算，规则摘要走 KV 缓存不重发
2. `listActions` — 引擎预筛出具体候选，模型做选择题而非自由填参
3. `validate` — 拒绝非法动作，模型不能改写事实
4. `resolve` — 确定性裁决。**唯一随机源是开局种子**，
   所有判定按 `H(seed, 年, 季, 势力, 事件类, 序号)` 派生，与裁决顺序无关，可逐位重放
5. `replay` — 追加式事件时间线

裁决必须确定：裁判若有方差，选手的优劣就被淹没了。
（反面参照：HiStrategy 用 LLM 做世界模拟，见 `research/GAMEPLAY-MOD-ECOSYSTEM.md`）
