# 评测怎么跑

这份文档记的是**实测出来的约束**，不是设计意图。每一条都对应一次真花了钱
或花了时间才发现的事，重新发现一遍很贵。

## 一分钟版

```bash
# 基线，不花钱，永远先跑
npm run eval -- --agent=bot:balanced --games=48

# 单个模型
npm run eval -- --agent=model --model=anthropic/claude-sonnet-5 --games=48

# 排行榜
npm run eval:suite -- --agents=bot:balanced,bot:purpose,model:<id>,model:<id> \
  --games=48 --reasoning=low --jobs=4 --budget=6 --out=./eval-out

# 把一次跑拆开看：按席位、动作构成、被丢的令、令数用率
npm run eval:dissect -- eval-out/board1/*.json

# 一整局的逐季实录（引擎级算式、候选全文、逐郡 diff、游戏外元数据）
npm run match -- --model=<id> --seasons=32          # 席位随机抽签
npm run match -- --model=<id> --seasons=32 --pick3  # 抽三家交互选一

# 多模型同场厮杀（好看，但**不能当排行榜**：A 的成绩取决于 B 那天的发挥）
npm run melee -- --seats=caocao=<id>,yuanshao=<id> --seasons=32
```

`--budget=<美元>` 是花超即停的闸门，`--provider=A,B` 钉住提供方（见第 7 条）。
`--maxcost=<美元>`（默认 1.5）是**跑之前**的闸门：任一对局方预估超了就拒跑，
开发期用便宜档，贵的要显式放行（见第 22 条）。
单跑 `npm run eval` 时逐季打一行心跳（局/季/令数/档位/耗时），`--heartbeat=off`
可关；套件默认关掉——几路并发交错刷屏，还会灌满失败时唯一的现场 stderr。

密钥放 `.env.local`（已在 `.gitignore`）。**必须走 `npm run eval`**——脚本是
plain node，靠 npm script 里的 `--env-file-if-exists=.env.local` 才读得到，
直接 `node tools/eval-run.mjs` 读不到。

## 二十一条硬约束

### 1. 少于 48 局，名次不可当结论

拿 `bot:purpose` vs `bot:balanced`（自对局实测相差约 20 分）做同 seed 同席位
的配对比较：

| 局数 | 配对差 | 95% CI | 分得开 |
|---|---|---|---|
| 6 | +0.0 | ±0.0 | 否，**每个 seed 上两者得分完全相同** |
| 12 | +16.7 | ±32.7 | 否 |
| 24 | +20.8 | ±23.5 | 否 |
| 48 | +29.2 | ±19.3 | 是（勉强） |
| 96 | +20.8 | ±12.6 | 是 |

根子在计分表只有四档（甲 300 / 乙 200 / 丙 100 / 丁 0），配对差每局只能取
0 或 ±100。换连续指标救不了场：郡数增量完全没信号，而且方向相反——purpose
拿分更高却占郡更少（−0.4 郡）。那反证 `gain` 是对的，它挑值钱的郡不是多的郡。

`tools/eval-suite.mjs` 低于 48 局会警告两次。低于这个数的跑仍然有用——
验管道、抓崩溃、看非法率——但排名不是结论。

### 2. 必须有 bot 基线

模型拿「均分 200」说明不了任何事，除非知道同席同 seed 下 `bot:balanced`
拿多少（6 局轮换实测 166.7）。基线不花钱，永远先跑。

机器人走的是与模型**完全相同**的那条路：`picks → admit() → orders`。
绕过准入层的话，illegalRate 与令数用率两列对基线是空的，而那正是判
「模型有没有在乱下令」的参照。

### 3. `--reasoning=low` 不是归一化——它对某些模型是「开启」

实测 claude-haiku-4.5，同一批 6 局：

| | 出参/次 | 推理占比 |
|---|---|---|
| 不传 `reasoning` | 103 | 0% |
| 传 `--reasoning=low` | 1011 | 56% |

它把本来关着的思考**打开**了，出参涨 10 倍。而 gemini-3.1-flash-lite 传了
`low` 仍是 91% 推理，并硬失败 3 次（`finish=error`）。

也就是说「给所有模型传同一个 effort」并不产生同等的测试时算力：
默认不推理的模型被打开，默认推理的模型被压低，不吃这个参数的模型不受影响。
三种效果，一个参数。用它之前先想清楚要的是哪一种；无论传不传，
报告都会把推理占比列出来。

### 4. 必须报降级档位与推理占比，否则分数不可比

**降级档位**：客户端有四档阶梯 `schema → schema-notemp → schema-any → text`，
每档松一个约束。落在不同档位的模型受的约束不同（有无解码层强制、有无
temperature），分数本来就不完全可比。

为什么需要 `schema-notemp`：`provider.require_parameters` 要求端点支持请求里的
**每一个**参数，而 OpenAI 推理系的端点不接受 `temperature`——两者一撞，
OpenRouter 把 4 个端点筛成 0，返回 404「No endpoints found」。
实测 gpt-5-nano 的 16 次调用全部落在这一档；没有它会全部退到自由文本。

**推理占比**：实测 gpt-5-nano 每次调用烧 6739 出参 token（97.7% 是 reasoning），
claude-haiku-4.5 只烧 103，相差 65 倍。不指定 `--reasoning`，比的就不是
策略能力而是各家默认给多少测试时算力。

- 统一档位：`--reasoning=low`。实测 gpt-5-nano 出参 107830 → 25338（少 4.3 倍），档位不变
- 按出厂设置比也是正当口径，但必须是显式选择。报告会在推理占比过半且未指定时提醒

### 5. 失败要分四栏，只有一栏算模型的分

    credits 账户额度耗尽 —— 整跑作废，与模型能力毫无关系
    infra   超时 / 网络 —— 基础设施
    budget  出参预算被推理吃光 —— harness 的配置问题
    model   答不上来 / 解析不出 —— 只有这一栏才算模型的分

**同一个洞踩了两次：没有桶的失败会掉进 model。**

第一次是超时：kimi-k2.5 报「模型答不上来 55 季」，其中 54 季是 180s 超时。

第二次是额度耗尽。跑了一份八个国产模型 × 48 局的榜，结果是：

    bot:balanced            147.9   基线
    deepseek-v3.2            35.4   −76%
    qwen3.7-plus             27.1   −82%
    …
    xiaomi/mimo-v2.5          4.2   −97%

看着像「国产模型全线不敌规则机器人」。真相是**账户余额见底**——每个模型
768 席·季里有 688–765 季的请求根本没发出去，OpenRouter 返回
`This request would exceed your available credits`，而那个 402 属于
`budget` 分级，在 model-seat 里没有对应的桶，于是落进了默认的 model。
令数用率 0–7%、总调用只有 278 次（应是六千次量级），都是同一件事的表征。

现在：`credits` 单独成栏；`eval-run` 见到即 `process.exit(3)` 就地停跑；
`eval-suite` 收到退出码 3 就中止整跑并在榜首打上「下面的名次不可用」。
继续跑只会用几百条「请求都没发出去」的记录堆出一份看起来煞有介事的假榜。

实测教训：一轮 6 局的套件里，kimi-k2.5 有 55/96 季、deepseek-v3.2 有 35/96 季
被记成「模型答不上来」。查下来 **54 季与 35 季全部是 `The operation was
aborted due to timeout`**——180s 的单次超时对慢提供方不够（deepseek 单次
实测 38–69s，八路并发下常顶穿）。按那份报告排名，等于按提供方的快慢排名。

默认超时因此提到 300s。基础设施失败占比超过 20% 时，套件会直接标注
「这一行的名次不可信」。

同一批数据还暴露另一处虚构：失败记录里的 `rung` 留着初始占位值 `"text"`，
于是报告里出现「kimi text×54」这种从未发生过的档位分布。现在失败记录的
rung 是 null，档位分布只统计成功的调用。

### 6. harness 的失败不能算到模型头上

出参预算被推理吃光（内容为空、`finish_reason=length`）是我们没让它说完，
不是模型答不上来。默认 `max_tokens` 8000，饿死则翻倍重试至 32000；
报告把两类失败分开计数。

原值 2000 的后果：gpt-5-nano 16 季全部返回空串，报告记成
「解析不出决策 / 0 分 / 令数用率 0%」——看着像模型不行。

### 7. 提供方不钉住，「同一个模型」就不是同一个东西

OpenRouter 按可用性路由。一份 24 季实录里，同一个 model id 跳了 **7 家**
提供方（Parasail / Cloudflare / Fireworks / Together / Venice / NextBit / Morph）。
后果三条：

- 量化精度与上下文实现各家不同；
- 单次用时中位 11.2s、最慢 **723.9s**（差 45 倍），慢的那次还断了流；
- 前缀缓存按提供方存，命中率掉到 **2%**（197k 入参只命中 4k）。

第一份排行榜正是被它拖垮的：两个模型跑到墙钟上限只完成 38/48 与 26/48。
`--provider=A,B` 可钉住（默认 `allow_fallbacks:false`）。不钉也行，
但要在报告里读到实际提供方那一列再下结论——每次调用的提供方与
generation id 都逐条落盘了。

### 8. 闸门本身也会撒谎，先验闸门

三个真实例子，都是「检查通过」而实际不通过：

- **观测预算闸门只测 16 季、且把跨季方略按 null 计 2 tok**。
  而对局界面给了 104 季选项，观测的 mine 段随疆域线性长（95 tok/郡）；
  方略实跑中位 173 tok。按最坏情形重测：**27/341 席·季超顶**，
  而它当时报「✓ 全部通过，袁绍余量 +86」——真实是 −87，差了一个符号。
  所有「预算不够，这个字段加不进来」的取舍都建立在那个数上。
- **`npx tsc --noEmit` 在 node_modules 缺失时会现装一个 2015 年的空壳包
  `tsc@2.0.4`**，然后「通过」。用 `./node_modules/.bin/tsc` 或先确认依赖在。
- **曹操那条判据在 n=24 上直接比点估计**：真实出局率 45% 时也有四成概率报红。
  改判单侧 95% 下界——判据不动，但按样本能支撑的强度来判。

判据的价值全在「它红的时候确实有问题」。一个四成时间在撒谎的判据，
很快就没人看了。

### 9. 观测里缺一项，模型就在按错的规则思考

这一类问题最阴险：一切「正常运行」，分数也出得来，只是模型手上的信息是错的。
逐条都是实测：

| 缺陷 | 后果 |
|---|---|
| 作废的令数不回传 | 模型每季从零问答，不知道上季有没有花完；实测用率 67%~92%，机器人 93%，一局白扔一千五到一千九百条令 |
| `clock.epoch` 只发一个序号 | 纪元推进唯一的后果是无主郡国守军每季自增（0→8%→15%），而模型看不见增速、也看不见本纪元还剩几季——「早取无主之地」的时间价值整个不存在 |
| 简报滤掉「我 0 郡且无空地」的州 | 恰好把**整州都在他方手里的邻州**全滤了——吕布看不到五郡全归刘备的徐州，而那是他最值钱的方向 |
| 调任候选只写这个人的政治 | 太守由「驻此郡者中政治最高者」派生、收入按它打系数，而现任太守是几分观测里查不到——「调他来会不会换掉太守」无从判断 |
| 断供不在观测里 | 模型在断供之郡集结 2033 人，当季粮尽溃散，而它的意图还是「下季自此出兵」 |
| `clock.totalTurns` 读内容包默认值恒 16 | 打 104 季的局也告诉模型「共 16 季」 |
| `mine[].officers` 按 id 序取前三 | **63.6%** 报的三人与实际守城不是同一批，模型据此调将 |
| 攻城的缺口/可防守没回传战报 | 围城「加码还是撤」失据：实录里袁绍给一个「缺口 0 对可防守 4」的围城增兵 |
| 围城中的军团没有前瞻预告 | 100% 空白，只能靠上季结果反推 |
| 赴援候选不看待命军团 | 标签写「可出 2425」而引擎派 1084，判词与结果反号 |
| 包里写「6 旬未破自动撤围」 | 引擎按 3 **季**；模型以为围城撑不过一季，不用增兵续围 |
| 包里写「已探 ±15%」 | 误差比是 0.08 |
| scout 许诺探到产出与民心 | 引擎只给守军与阵型，而民心是劝降成功率的直接输入 |
| 「消耗」整节讲粮耗 | params.ts 一个字段都没读，金节写着「不另设兵粮」 |
| 借道生成不出候选 | 摘要三处许了它，48 季实跑 passages 恒为空 |

找法是**四方对账**：内容包写的规则 × 引擎里的状态 × 观测里的字段 ×
界面给人看的东西。`supplyCut` 就是这么找出来的——界面表里早有「供」栏，
观测里没有，于是人和模型看的不是同一场战争。

### 10. 局变长，机器人的分在涨而地盘在缩——涨的是掷骰次数

有人怀疑「16 季太短，会规划的一方来不及滚起来」。用机器人验了一遍：
五个画像 × 16/32/64 季 × 48 局 = **720 局**，零成本、113 秒跑完。

| 局长 | 目的流均分 | 目的流疆域倍数 | 进攻流疆域倍数 | 出局率（五家） |
|---|---|---|---|---|
| 16 季 | 158.3 | 1.37 | 0.92 | 0~38% |
| 32 季 | 164.6 | 1.37 | 0.74 | 6~48% |
| 64 季 | **172.9** | **1.29** | **0.41** | **21~67%** |

**均分在涨，地盘在缩。** 这两列必须一起看——分涨的原因是 `bestGrade`
是**历史最高档的棘轮**（`resolve.ts`：`if (RANK[grade] > RANK[f.bestGrade])`），
局越长摸到乙/甲的机会越多，摸到之后再被灭也不退分。
64 季下目的流有 44% 的局最终被灭，却照样按历史最高档记分。
**那不是「后期滚起来了」，那是掷骰次数变多了。**

唯一经得起正经检验的正向发现是**死亡率**：同 seed 差中差 16→64，
五个画像全部显著（+20.8pp±11.6 到 +39.6pp±14.0）。
策略差本身没被放大——目的流对均衡流 +4.2 → +6.2 → +10.4，
方向单调但三段的区间都盖过零；差中差 @64−@16 = +6.25±14.8，也不显著。
这是「测不出」而非「没有」：区间容得下优势翻一倍。

**超/霸/王三档在 720 局里一次都没被摸到。** 最大 zhouGain = 3（超要 4），
最大绝对控州 = 3（霸要 7、王要 11），零统一。内容包里
「长局才够得着超/霸/王」这句设想在规则机器人这一层完全没有兑现。

这个实验能证伪的是「纯粹因为局短」当中属于机器人的那一半——
**规则机器人在 64 季里也没有更长远的东西可展开**。模型那一半还没测。

#### 于是加了「终局分」这一列，而它把尺子换了个方向

`finalGrade` = 局终这一刻实际站在哪一档，与棘轮的 `bestGrade` 并列报。
同一批 48 局：

| | 均分（历史最高） | 终局分 | 背离 |
|---|---|---|---|
| 16 季 目的流 | 158.3 | 114.6 | 19/48 局掉档，平均 −44 |
| 16 季 进攻流 | 137.5 | 75.0 | 24/48 局掉档，平均 −63 |
| **64 季 目的流** | **172.9** | **104.2** | 27/48 局掉档，平均 −69 |
| **64 季 进攻流** | **147.9** | **33.3** | 36/48 局掉档，平均 −115 |

**历史最高档随局长上涨，终局分随局长下跌。** 两条线是反的。

更要紧的是分辨力。进攻流对目的流的配对差：

| | 历史最高档 | 终局档 |
|---|---|---|
| 16 季 | −20.8±22.6　不显著 | **−39.6±36.8　显著** |
| 64 季 | −25.0±27.1　不显著 | **−70.8±36.4　显著** |

**棘轮那把尺子分不开的两种打法，终局分分得开，而且局越长分得越开。**
一个「曾经摸到过甲档」的记分方式，天然把「守不住」这件事从账上抹掉——
而守不住恰恰是长局里最贵的错误。榜上两列并排，背离本身就是信息。

顺带修了一个静默失效：`tools/eval-suite.mjs` 此前不转发 `--seasons`，
`npm run eval:suite -- --seasons=64` 会**按 16 季跑而报告上看不出来**。
子进程参数是套件与 eval-run 之间唯一的接口，加参数就要在那里加一行。

### 11. 32 季的同场混战里出现了第一个超档——机器人 720 局零次

两家模型各执三席同场（glm 执曹操/袁绍/刘表，hy3 执吕布/袁术/刘璋），
32 季打满，$0.386、137 次调用：

| 席位 | 模型 | 开局 | 终局 | 控州 | 历史最高/终局档 |
|---|---|---|---|---|---|
| 袁绍 | glm-5.3-flash | 13 郡 | **40 郡** | **6 州** | **超 / 超** |
| 刘表 | glm-5.3-flash | 7 郡 | 11 郡 | 1 州 | 甲 / 丙 |
| 刘璋 | tencent/hy3 | 9 郡 | 16 郡 | 1 州 | 乙 / 乙 |
| 曹操 | glm-5.3-flash | 1 郡 | 0 郡 | — | 乙 / 丁 |
| 袁术 | tencent/hy3 | 2 郡 | 0 郡 | — | 丙 / 丁 |
| 吕布 | tencent/hy3 | 6 郡 | 0 郡 | — | 丁 / 丁 |

**超档（州增量 ≥4）此前从没被摸到过**：规则机器人 720 局最高 3 州 25 郡，
四模型 48 局排行榜里州增量也从没超过 2。所以上一条里那句
「瓶颈不在时钟，在规则机器人不会滚雪球」是对的——**模型会**。

**但这是一局，不是名次。** 混战里 A 的成绩既取决于自己也取决于 B 那天的
发挥，跨局不可比。它回答的是「这几家凑一桌谁能活下来」，不是「谁更强」。

一处旁证：曹操那一席第 15 季的方略写着「再捡豫州无主郡
（守军每季 +15%，宜早）」——它在用刚补进观测的纪元信息做决策，
而那一项此前只有一个光秃秃的 `epoch: 1`（见第 9 条）。

### 12. 局越长，模型不是越强，是越两极——而旧尺子只看得见好的那一极

拿模型跑了第 10 条那个实验缺的另一半：glm-5.3-flash 对 bot:purpose，
同一批 24 个 seed、同席位轮换、提供方钉住 Parasail，**16 季与 64 季各一遍**。
实扣 $2.73。

### 13. 四级台阶那把尺子，48 局下一格都量不出显著

把六个机器人画像两两配对 × 三个局长 = **18 格**，每格 48 局（免费，113 秒），
拿三把尺子量同一批配对数据：

| 尺子 | 信噪比中位 | 平局中位 | 48 局下显著的格数 |
|---|---|---|---|
| 四档（现行） | 0.151 | **28/48** | **0/18** |
| 细分（fineScore） | ≈0.15 | 14/48 | 0/18 |
| **连续（州进度）** | **0.193** | **8/48** | **4/18** |

**四档那把尺子，十八格里一格都没打到显著**，而且三分之二的局被记成平手。
这不是「48 局不够」的问题——是尺子本身把信息扔了。

连续尺子 = `100 × (州进度增量 + 0.5 × 州治增量)`，其中
**州进度**是每个州按「我方郡数 ÷ 过半所需」计、封顶 1、全图求和
（`victory.ts` 的 `zhouEquiv`）。它把定档那道台阶摊成斜坡，且
**长在定档判据自己的轴上**：一个郡值多少取决于它在哪个州、离控住还差多远
（徐州五郡过半要三，一郡值 1/3；益州十二郡过半要七，一郡值 1/7），
控住之后再多拿一分不值——与「第五个散郡值 0 分」是同一条规则的连续版。

拿郡数增量当细分做不到这一点，`fineScore` 那一版的失败已经证过：
目的流拿分更高而占郡更少（−0.4 郡），郡数不是目标函数。

**代价要说清楚。** 逐格看是 12 格更灵敏、6 格更钝：赢的时候赢得多
（最高 9.3 倍），输的时候输得少（最低 0.47 倍）。它在**长局**与
**差距明显的对手**上稳赢，在 16 季的近似对手上不稳定——64 季自对局里
进攻流的州进度是 **−49**（终局比开局还退），而档位分 147.9 把这件事整个盖住了。

两条方法上的自律：
- 「要多少局才显著」那种反推数（n ∝ 1/均值²）**只在均值本身显著时可信**。
  十八格里只有四格显著，其余的 n 建立在盖过零的点估计上，不能引用。
  这个仓库在第 14 条为同一件事栽过一次。
- 州治权重扫过 0 / 0.25 / 0.5 / 1，信噪比中位 0.210 / 0.197 / 0.193 / 0.193——
  **差异在噪声内**。取 0.5 是因为定档判据本身就这么说（1 州 + 2 州治 = 2 州 = 甲），
  不是因为它拟合得最好。对着指标调参，包一改就不成立。

榜上加一列「州进度」，与均分、终局分并排。三列答的是三个不同的问题：
**做到过什么、守住了什么、离控住一个州还有多远。**

### 15. 提供方会把中文 key 转码搞坏，而那会记成模型的非法率

第二份排行榜里 qwen3-30b 的非法率 **50.9%**（上一份是 1.0%），
令数用率掉到 31%。查下去：2806 次 `unknown-key` 全长这样——

```
'appoint:æµ\x8eé\x98´é\x83¡:caoren'   ← 应该是 'appoint:济阴郡:caoren'
```

中文按 UTF-8 编码后又被按 Latin-1 解了一遍。**它每一条其实都选对了。**
这是路由层或提供方的编码问题，与模型能力无关，而我们把它算成了
「候选表里没有这个 key」——又一次把基础设施的失败算到模型头上。

准入层现在会复原（`Buffer.from(key,"latin1").toString("utf8")`），
但**只在复原后恰好命中候选时才认**，所以真正的幻觉洗不白：编造的 key
复原之后仍然不在表里。复原计数单独上报，非零就在报告里打一行
「N 条 key 被提供方的编码搞坏（已复原）——不计模型的非法率」。

顺带一提：出问题的那两个模型都落在 `schema-any` 档。严格 schema 档下
enum 由解码层强制，编码坏了会直接被端点拒掉；降到 schema-any 之后
enum 不再强制，模型自由拼 key，编码问题才显出来。

**修好之后它的分反而掉了**，这一条比修复本身更要紧。同 48 局重跑：

| | 非法率 | 令数用率 | 均分 | 出局 | 档位构成 |
|---|---|---|---|---|---|
| 修复前 | 50.9% | 31% | 135.4 | 6/48 | 乙23 丙16 丁8 甲1 |
| 修复后 | 5.4% | 62% | **120.8** | **14/48** | 乙19 丁15 丙11 甲3 |

一半的令被丢掉时，它被迫少做事；令真的执行之后，它的决策把自己打死了。
**那个 bug 一直在替它兜底。** 所以：修掉一个基础设施缺陷之后分下降，
不等于修错了——要分开看「它的令是不是合法」（修对了：50.9% → 5.4%）
与「它的令好不好」（本来就不好，只是此前看不到）。
甲档从 1 涨到 3、丁档从 8 涨到 15，赢得更大也输得更惨，也是同一件事。

（复原数这一跑是 775 条、上一跑 2805 条——提供方的编码损坏是**间歇**的，
两跑之间路由多半换了。所以这不是一次干净的 A/B，只有非法率那一列是确定的。）

### 16. 跨季记忆值约 +92 分，但小样本会把符号讲反

### 17. 令数的措辞值 40 个百分点

### 18. 新机制上线，先花一美元看模型认不认，别直接开榜

名器（授官州牧）上线当天跑的烟测：`claude-haiku-4.5`，钉住 Anthropic，
2 局 × 16 季 × 2 席（李傕、刘表），**总花费 0.79 美元**——每席·季约 0.025 美元，

要看的不是分数（2 局什么也说明不了），是**这条新令有没有被看见**：

    第 0 季 李傕  invest:凉州:lijue   「获取凉州牧以传檄收无主郡」
    第 4 季 刘表  invest:豫州/交州     「授牧豫州与交州便于传檄收郡」
    第 5 季 刘表  invest:司隶:liubiao 「授己司隶牧为后续传檄做准备」

开局第一季就用上了，且理由复述得与规则一致。反过来，如果一个新机制在

### 19. 第一份 48 局的榜：两个模型都输给规则机器人，且输得显著

规则冻结后跑的第一份正经排行榜（同 seed、同对手、席位轮换、16 季、48 局、
钉住 OpenAI、`--reasoning=low`、`--keyenum` 默认开）：

| 对局方 | 均分 | 终局分 | 州进度 | 对基线 ±95% | 疆域倍数 | 出局 | 非法率 | 令数用率 | 成本 |
|---|---|---|---|---|---|---|---|---|---|
| bot:purpose | 191.7 | 141.7 | +105 | 基线 | 1.51 | 5/48 | 0.0% | 97% | — |
| bot:balanced | 158.3 | 112.5 | +90 | −33±20 | 1.50 | 4/48 | 0.0% | 96% | — |
| gpt-5-mini | 135.4 | 58.3 | +15 | **−56±23** | 0.89 | 7/48 | 7.6% | 81% | $5.31 |
| gpt-5-nano | 120.8 | 81.3 | +46 | **−71±25** | 0.93 | 11/48 | 9.4% | 66% | $1.05 |

合计 $6.36、1400 次调用、60 分钟（并发 2）。两个置信区间都不跨零：**这个差是真的**。

三条读法：

**一、疆域倍数 < 1 —— 它们在缩。** 机器人把地盘做到 1.5 倍，两个模型平均比开局
还小（0.89 / 0.93）。均分之所以还有 120–135，是因为档位按**历史最高档**记
（棘轮），冲高之后丢光也不扣分。终局分（58 / 81 对基线 142）才是它们守住的东西。

**二、非法率 7.6–9.4% 是真的，不是转码。** 钉住提供方之后 mojibake 为 0，
`unknown-key` 也是 0——枚举拦住了幻觉，一条编造的 key 都没有。被丢的是另一类：

    rejected     mini 427 / nano 344    单看每条都合法，合起来不合法
    duplicate    nano 93                同一条 key 选了两遍
    over-budget  nano 41 / mini 8       令数不够还要下

即模型选的是一**组**令：每条在候选表里都真实存在，但同一郡每季至多 2 令、
金不够、令数不够——它不核算自己这一季的预算。这是可测量的决策质量缺陷，
不是接口问题。

**三、mini 花了 5 倍的钱，换来 +15 均分和 −31 州进度。** 它冲得更高（乙档 26 局
对 24 局）却守得更差（终局分 58 对 81、州进度 +15 对 +46）。在这套判据下
「更大的模型」不等于「打得更好」，而连续尺子（州进度）与档位分给出的排序相反——
两把尺子一起看才看得出这件事。

### 20. 把「被丢的令」回授给模型：用率 +6.2pp、重复减半，但非法率没动

第 19 条挖出的病是「单看每条都合法、合起来不合法」，而提示词里**早就写着**
「同一郡每季至多 2 令」。所以改的不是措辞，是回授：观测新增
`droppedLastSeason`（上季选了却没执行的令 + 原因，至多五条，干净的季不发）。

同 seed、同席位轮换、gpt-5-nano、24 局各一臂，唯一差别是 `--dropback`
（这个开关必须与 `--memory` 分开，两者都是跨季回授，挂一个开关上就分不出
是哪条起的作用）：

| | 对照 | 开回授 | 差 ±95% | |
|---|---|---|---|---|
| 非法率 | 8.47% | 9.26% | +0.79 ±1.55 pp | **不显著**（z=1.01） |
| 其中重复率 | 2.06% | 1.25% | −0.81 ±0.69 pp | 显著（z=−2.30） |
| 令数用率 | 65.1% | 71.3% | +6.2 ±3.7 pp | 显著（z=3.27） |

各 $0.52。**头号指标没动**：告诉它「上季这几条被丢了」并没有降低总非法率。
动的是两件事——它不再把同一条 key 选两遍（重复几乎减半），以及每季多花了
6 个百分点的令。

一个说得通的机制：被丢的那类里，`duplicate` 是模型**自己一眼可查**的
（同一条 key 出现两次），回授一提醒就改得掉；而 `rejected` 要它模拟引擎的
逐条校验（这一郡这一季已经下了几令、金还剩多少），回授只告诉它「上季错了」，
没给它算的办法。两臂的 `rejected` 分别是 150 与 183——回授之后反而多了，
与「令下得更多、碰撞机会也更多」一致。

留着：两项显著改善、一项不显著变化，而代价只有「有令被丢的那些季多约 40 tok」。
下一步若要压 `rejected`，得给它可算的东西——例如候选上直接标出「本郡本季已用几令」，
而不是继续告诉它错了。

### 21. 教模型「先按郡数一遍」是负收益——已退回

第 20 条留了个下一步：非法率里 63% 是「本郡本季令数已满」，而回授只告诉它
「上季错了」，没给它算的办法。于是提示词加了一句：「先按郡数一遍——同一个郡
出现两次就到顶，第三次必被丢弃。郡名就在 key 里」。

同 seed、同席位、gpt-5-nano、24 局，唯一差别是这一句：

| | 加这句之前 | 之后 | 差 ±95% | |
|---|---|---|---|---|
| 令数用率 | 71.3% | 66.9% | **−4.3 ±3.5 pp** | 显著（z=−2.46） |
| 非法率 | 9.26% | 8.11% | −1.15 ±1.58 pp | 不显著（z=−1.43） |

**换回来的那点合法性盖不住损失。** 教它数令位，它就变谨慎、少下令——
而令数用率是这套评测里少数几个与得分强相关的过程指标（第 17 条：措辞一改
36%→76%，同一局第一次打出甲档）。已退回 1.11 的写法。

两条方法上的教训：

**一、先想清楚「拿什么跟什么比」。** 这一轮里「令位已满 0% → 6.33%」看着惊人，
其实是假的：对照臂跑的时候还没开始存拒收细节，那边的字符串里根本没有
「令数已满」四个字。**改了记录格式，旧记录就不能再跟新记录比这一维。**

**二、想给候选补 `sites` 字段（列出占用的郡）之前先测了一下，发现一条都发不出来**
——郡名全在 key 里，连集结也是（`muster:中山国:中山国+安平国+河闲国`）。
信息早就在，模型只是没去数；而上面这个实验说明，让它去数并不划算。

### 22. 开发期一律用便宜档——贵的模型没多告诉我们什么，只是多花了钱

第一份 48 局排行榜花了 $6.36，其中 **gpt-5-mini 一个占 $5.31**，比同一份榜上
其他所有对局方加起来还多 4 倍。它换来的结论是什么？

| | 均分 | 与基线差 | 疆域倍数 | 非法率 |
|---|---|---|---|---|
| bot:purpose | 191.7 | — | 1.5 | 0 |
| gpt-5-mini（$5.31） | 135.4 | −56 ±23 | 0.93 | 7.6% |
| gpt-5-nano（$1.25） | 120.8 | −71 ±25 | 0.89 | 9.4% |

**两者的结论是同一句话**：都被基线打穿，都在「攒兵不打」，疆域都不到基线的
三分之二。贵的那个把 −71 变成 −56，而这两个数的置信区间是重叠的——
$4 买到的是一个统计上分不开的差别。

调试规则、验证机制、跑 A/B，要的是「模型认不认这套协议、非法率什么量级、
哪一档掉降级」，这些**便宜档一样看得见**。48 局的价目（2026-09 实测）：

| 模型 | 入 $/M | 出 $/M | 48 局 |
|---|---|---|---|
| qwen/qwen3.7-flash | 0.03 | 0.13 | **$0.62** |
| ~deepseek/deepseek-v4-flash-latest | 0.05 | 0.16 | $0.96 |
| z-ai/glm-4.7-flash | 0.06 | 0.40 | $1.40 |
| openai/gpt-5-nano | 0.05 | 0.40 | $1.25 |
| openai/gpt-5-mini | 0.40 | 3.20 | $3.84 |

所以 `eval-suite` 加了 `--maxcost`（默认 **$1.5/对局方**）：预估超了就**拒跑**，
并把便宜替代打在屏幕上。要跑贵的，得显式写 `--maxcost=4`——
**让「花大钱」成为一次刻意的动作，而不是默认动作。**

贵的模型留到规则冻结之后的正式榜；那时结论要发出去，才值这个钱。

## 候选 key 写进 schema 的 enum：拿钱换正确性

默认**开**。解码层强制「只能从候选里选」（R13），代价是 Anthropic 的前缀缓存
整块失效——OpenRouter 把 `json_schema` 译成 tool，而 Anthropic 的缓存前缀顺序是
**tools → system → messages**，候选 key 每季都变 → tool 变 → 后面的 system 全废。
system 占入参 38–52%，按缓存 0.1× 计价即入参贵约 2.8 倍。

隔离实验（同一 4.3k tok 的 system 连发两次，claude-haiku-4.5）：

| | 第 2 次调用 |
|---|---|
| 无 `response_format` | cached 4317 ✓ |
| 有，schema 恒定 | cached 4534 ✓ |
| 有，schema 每次不同（默认） | cached 0，重写整块 ✗ |

这条曾被改成默认关闭，依据是「实测 enum 拦下的错误是 0」。**那个结论是错的**，
它建立在每个模型只跑 1 局（16 季）的样本上。放大到 6 局（96 季）：

| claude-haiku-4.5 | 均分 | 非法率 | unknown-key | 缓存 |
|---|---|---|---|---|
| enum 关 | 216.7 | 8.6% | 47 | 45% |
| enum 开 | 233.3 | 0.7% | 0 | 0% |

那 47 条是模型本想下而被丢掉的令，占它下令数的 8.3%。分差 +16.6 在 6 局下
不算显著（见上面的功效分析），但非法率的差是直接的机制性差异。而且逐字复现
长中文 key 是转写能力不是策略能力，让它进分数是测错了东西。

`--keyenum=off` 换回缓存；换到的分数要按「该模型有 x% 的令被丢掉」来读。

Anthropic 还必须显式打 `cache_control` 断点，纯字符串 system 一次都不命中。
OpenAI / Gemini / DeepSeek 是自动缓存，两种写法都行。

**这条的教训比结论本身重要**：1 局 16 季的样本不足以支持任何「从未发生」的
结论。`unknown-key` 在 16 季里是 0，在 96 季里是 47。

## token 口径

`estTokens` 的系数由三家真实 tokenizer 标定（13 份真实提示词，最小二乘）：

| | 汉字/字 | ASCII/字 | 实际/估算 |
|---|---|---|---|
| anthropic/claude-haiku-4.5 | 1.300 | 0.446 | 1.59× |
| openai/gpt-5-nano | 1.040 | 0.420 | 1.37× |
| deepseek/deepseek-v3.2 | 0.855 | 0.467 | 1.33× |
| 曾经的系数 | 0.900 | 0.250 | — |

取 Claude 的（最保守，也正是主要评测对象）。观测预算闸门
`npm run obs:budget` 的单位因此是**真实 token**，默认 10000/席·季。
