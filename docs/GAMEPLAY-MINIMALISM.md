### 0.2 一句话的结论

**规则数量和策略深度之间没有正相关。**
真正的自变量是**规则之间发生非平凡交互的密度**，以及**动作之间是否互斥**。
本项目的 O(10²) 约束不是深度的敌人——国际象棋的平均分支因子是 35，围棋是 250，
人类玩过的最深的两个游戏，动作集都落在这个区间里面。

## 一、先把"深度"和"复杂度"分开

不做这一步，后面每一条设计建议都会退化成"多加点东西"。

### 1.1 学界目前最好的深度定义：strategy ladder【学术】

Lantz, Isaksen, Jaffe, Nealen, Togelius,
*Depth in Strategic Games*, AAAI 2017 Workshop（NYU Game Center / Game Innovation Lab / Spry Fox）。

他们提出一个可测量的属性 `d`，定义为：

> "the capacity of a game to absorb dedicated problem-solving attention
> and allow for sustained, long-term learning."

形式化手段叫 **strategy ladder（策略阶梯）**：
把"策略"定义成算法，横轴是算法可用的计算资源（速度 / 算法尺寸 / 工作内存），
纵轴是该资源档位下最强算法的强度。**`d` = 这条曲线上"台阶"的数目**
（一个台阶 = 相对上一台阶胜率提升达到阈值，传统 skill chain 取 60–75%）。

三种曲线形状：

| 形状 | 含义 | 例 |
| --- | --- | --- |
| 早早触顶 | 低算力就能完美解 | 井字棋 |
| 长而平，末端垂直 | 需要巨量算力才能完美解，但中间没有台阶 | 纯搜索型游戏 |
| **长而多台阶** | 每增加一点资源都立刻换来可见的强度提升 | 围棋、国际象棋、桥牌 |

**对本项目的直接翻译**：把"计算资源"换成"模型的推理能力与推理预算"，
`d` 就是**这个沙盘能分辨出多少档模型强度**。C5 说的"更强的推理稳定转化为更好的结果"，
在学术语言里就是"这个游戏的 strategy ladder 台阶足够多、且台阶是单调的"。
**Mind Arena 要的不是"好玩"，是 `d` 大。**

### 1.2 三个否定：这些都不是深度

论文用三个思想实验把常见的替代指标全部排除，每一个都直接对应本项目的一种诱惑。

**（一）状态空间不是深度。**

> "imagine any existing game and then add a new rule that allows either player,
> after their turn, to flip a token from side A to side B.
> This immediately doubles the size of the game's state space without affecting its depth in the slightest."

**对应本项目的诱惑**：把 105 个郡国的十几个字段全部做成可操作的量。
状态空间涨了几个数量级，深度一点没涨，观测预算全被吃掉。

**（二）分支因子不是深度。**

> "we can imagine inflating a game's branching factor artificially by adding
> any arbitrarily large number of 'dud' alternatives at each node of the tree.
> Every dud branch leads in an obvious way to a losing position."

作者接着说，一个每步只有二选一但两条都有意思的游戏，比一个 100 选 1 但其中一条明显最优的游戏更深。

**对应本项目的诱惑**：`GAMEPLAY-DESIGN.md` §2.4 论证第 2 条说"动作太少，强模型和弱模型选的是同一个"——
这句话是对的，但它的逆命题不成立。**把动作数从 20 堆到 98，如果新增的 78 条里大多数是 dud，
`d` 一点没涨，只是把 2450 token 花掉了。** 详见 §9.3。

**（三）计算复杂度类不是深度。**

> "Knowing whether a game is in PSPACE or EXP, for example, doesn't give us enough detail
> about the game to help us distinguish it from the myriad other games in the same category."
> "A problem can require lots of resources to solve without being interesting.
> Searching for a needle in a haystack is a difficult problem ... but it's not the kind of problem
> that requires cleverness and creativity."

### 1.3 肯定的部分：半有序（semi-ordered）

论文给出的正面刻画是本文最重要的一段：

> "We believe the quality we are looking for is a kind of semi-orderedness of the game's state space,
> a level of underlying structure that allows for some useful compression of the game tree
> but not so much that pure search is never needed."

两种失败模式，**结构上是对称的**：

| 失败模式 | 描述 | 最优策略的描述长度 | 后果 |
| --- | --- | --- | --- |
| **纯搜索型** | 没有任何可用的启发式，只能一层层算 | 短（"搜完整棵树"） | 台阶少：低算力档全在瞎走 |
| **一招鲜型** | 存在一条启发式就能近似完美地玩 | 短（"永远把最小的子往前推一格"） | 台阶少：低算力就触顶 |
| **深** | 启发式与搜索交替 | **长而复杂** | 台阶多 |

论文用 Kolmogorov 复杂度描述这一点：**深游戏的"如何找到最优着法"这份说明书本身很长。**
围棋的定式书、国际象棋的开局库、扑克的范围表，全都是这份说明书的一部分。

**这条对本项目是判据级的**：
`GAMEPLAY-REVIEW.md` §3.2 判定"综合分把苟活定为最优解"、§3.4 列出五条退化策略
"每条都能被模型在第一次读规则时找到"——这就是**一招鲜型失败**。
不是数值没调好，是 `d` 塌成了 1 个台阶。这比"动作太多"或"token 超预算"严重一个量级，
审查文档把它排在第一位是对的。

### 1.4 学界其他可用的量化工具【学术】

| 工具 | 出处 | 测什么 | 对本项目可用性 |
| --- | --- | --- | --- |
| **状态空间复杂度 / 博弈树复杂度 / decision complexity** | Allis 1994；见 Wikipedia *Game complexity* | 三个不同的"大"。decision complexity = 判定初始局面价值所需的最小决策树叶子数（即最优剪枝后的必要计算量） | 只能算量级，不能测深度。用来做**上界体检**，不做设计目标 |
| **restricted play（受限对弈）** | Alexander Jaffe, *Understanding Game Balance with Quantitative Methods*, PhD, U. Washington, 2013；会议版 *Evaluating Competitive Game Balance with Restricted Play*, AIIDE 2012（最佳学生论文） | 给一个 agent 施加算法上的限制（禁用某类动作、限制前瞻深度），看胜率掉多少。掉得越多，说明被禁的那条维度越重要 | **★★★★★ 直接可用**。见 §10 手法 8 的验收方法 |
| **hierarchical knowledge base 规则数** | Apeldoorn & Volz, *Measuring Strategic Depth in Games Using Hierarchical Knowledge Bases*, IEEE CIG 2017, pp.9–16 | 从对局轨迹里抽出分层规则库，用规则的**数量与具体度**当深度指标，并与人类问卷的主观深度对照 | ★★★☆☆ 思路可用（"最优策略说明书有多长"的可操作版），但只在三个街机小游戏上验过 |
| **技能-运气分解** | Dürsch, Lambrecht & Oechssler, *European Economic Review* 2020;127:103472（海德堡大学），400 万+ 局在线数据 | 用 Elo 评分的**离散度**当技能含量的度量；另有 **Rep. 列**直接给出"排名要跑多少局" | **★★★★★ 见下。全文最有用的单个来源** |

**海德堡那组数据是本文最有价值的单个经验事实：**

- 国际象棋的 Elo 标准差 **> 170**
- 扑克与斯卡特（skat）**不超过 30**
- **对照实验**：把国际象棋的对局每隔一局替换成掷硬币，Elo 标准差从 170 掉到 **45**

第三条是关键。**"一半对局改成掷硬币"这个操作，把一个游戏的区分度砍掉了约 3/4。**
本项目每往结算里放一次随机，就是在按这个比例毁掉自己的测量仪器。
`GAMEPLAY-AI-FRIENDLY.md` 原则 7（随机只放在决策之前）现在有了定量支撑。

**注意来源版本差异【本文核对】**：上面三个数（170 / 30 / 45）来自海德堡大学 2020 年的新闻稿，
对应 *European Economic Review* 2020 的**正式发表版**（数据集为国际象棋 / 扑克 / 斯卡特）。
我另外核对了 2018 年的工作论文版（数据集不同：国际象棋、扑克、Tetris、双陆、Rummy 等在线游戏，**不含斯卡特**），
它给出的是另一组数：常客（≥100 局）口径下国际象棋 **188.3**、50%-chess **56.4**、扑克 **31.0**；
全体玩家口径下国际象棋 **123.4**、50%-chess **28.1**、扑克 **6.0**。
**结论方向完全一致，绝对值随口径变化**。本文引用发表版的数，但下面的推论只用比值。

#### 这篇论文里对本项目最有用的一个量，新闻稿没提【本文核对，取自工作论文 Table 2/3】

论文有一列叫 **Rep.**，定义是：
**"强一个标准差的玩家，要打多少局，才能以 >75% 的把握确认他赢得更多"**——
换句话说，**这就是"把排名跑出来需要多少局"，即评测成本本身**。

| 游戏 | Rep.（常客口径） | Rep.（全体玩家口径） |
| --- | --- | --- |
| **国际象棋**（零随机） | **3** | **5** |
| Tetris | 9 | 21 |
| **50%-chess**（一半对局换成掷硬币） | **19** | **71** |
| 双陆（有骰子） | 43 | 351 |
| **扑克** | **59** | **1,405** |
| 纯掷硬币 | ∞ | ∞ |

**这张表是本文对 C5/C6 最直接的定量支撑：**

- 零随机的确定性游戏，**3–5 局**就能分出高下
- 掺一半随机，成本涨到 **19–71 局**（**×6 到 ×14**）
- 到扑克的随机水平，成本涨到 **59–1,405 局**（**×20 到 ×280**）

**对本项目的翻译**：`GAMEPLAY-DESIGN.md` 的一局是 60 季 / 每方 ~15 次全量模型调用。
如果结算是确定性的，**跑 3–5 局就能给两个模型排序**；
如果往结算里放一次掷骰，同样的置信度要 **20–70 局**。
这不是"多花点钱"，这是**评测预算乘一个数量级**，直接和 `GAMEPLAY-REVIEW.md` §5.5 的预算冲突。

**因此 F2（结算随机）不是一条设计偏好，是一条预算约束。**
本项目的确定性结算骨架必须守住——它买到的不是"公平感"，是**两个数量级的评测成本**。

### 1.5 把这套语言接到本项目的六条约束上

| 约束 | 用深度语言重述 |
| --- | --- |
| C1 高层战略不微操 | 动作应处在**启发式能压缩**的抽象层，而不是必须逐格搜索的层 |
| C2 观测可序列化 | 状态空间要"有意义"——每一个进观测的字段都要能改变至少一条策略的排序 |
| C3 决策频率解耦 | 与 `d` 无关，是工程约束 |
| C4 动作集可枚举 | 分支因子要小，且**里面不能有 dud** |
| **C5 推理稳定转化为结果** | **就是 `d` 大 + 台阶单调 + 方差小。这是唯一真正的设计目标** |
| C6 局长可控 | 台阶要在 60 次决策内走完，不能要求 1000 局才分得出来 |

### 2.2 命令书：本文要讲的最重要的一条规则

> "命令书是君主管理国家各方面情况的任务书，政治、军事、文化的各个任务都需要密令书。
> 命令书的数量与你所控的城池数量有关，控有的城越多，命令书越多。
> **命令书的底限和上限分别是 3 和 12**，即你哪怕只有一个城池也会有 3 枚命令书，
> 城池再多也只会有 12 枚命令书。"
> —— 豆瓣攻略

> "任何任务的执行都需要使用一枚命令书，**除了选任君主**（按：指「任命」太守）。"

拆开看，这一条规则做了五件事：

**（一）动作预算是全局的，不是每城的。**
不是"一城一月一令"——这个流传很广的说法**不准确**。
准确的说法是：**全国一个月共 3–12 次操作机会，每次操作是一个 (城, 命令) 二元组。**
你可以把 12 次全砸在一座城上，也可以摊到 12 座城。

**（二）预算与领土规模脱钩。**
从 12 座城扩到 30 座城，命令书**一枚不涨**。
这是一条**天然的反滚雪球机制**：领土的边际收益递减到 0，
每城人均决策带宽从 1.0 掉到 0.4。**领先者被迫放弃大部分领土的发展。**

**（三）预算把"清单"变成"背包问题"。【本文推导 —— 本文最核心的一条论证】**

设某一月你有 12 座城、每城约 16 种可下命令，则第一级动作条目 ≈ **192 条 = O(10²)**。
**如果没有命令书，最优解是"每条都下"**，192 条这件事对深度的贡献是 **0**——
它们互不排斥，不构成选择。有了 12 枚命令书，问题变成
"从 192 条里挑 12 条，且每条的价值依赖于你挑了哪 11 条"。

**深度来自互斥，不来自数量。** 这是 Lantz 的 dud 论证的对偶形式：
Lantz 说"多加没用的选项不增深度"，这里说"**加了有用但不互斥的选项，同样不增深度**"。

**（四）它自己是一个跨维度的兑换率。**
垦田、征兵、离间、送钱、买武器、加智力——全部从同一个 12 枚的池子里出。
所以"这个月要不要去挖吕布"的代价，不是金钱，是"少垦一次田"。
**把所有子系统接到同一个稀缺资源上，就是把所有子系统连成了一张交互图。**
（注意：这和 EU4 的 mana 是**同一个手法**，代价与收益见 §7。差别在霸王的大陆的池子是 3–12 这种**小整数**，
EU4 的池子是 999 上限的连续量。小整数逼出取舍，大数值池只逼出"攒够了再花"。）

**（五）「任命太守」不消耗命令书。**

**这一条已由日方来源独立证实【本次核对】**：日文维基百科条目在描述指令时，
明确写「侦察」是"命令書が1枚必要となるが"（需要 1 枚命令书）、可无限次使用，
而「任命」一项**不需要命令书**。
中日两侧来源在这一条上一致，**所以它是本节可信度最高的规则之一**——
这很重要，因为下面手法 1 的整个论证都建立在"预算是全局的、且有一条免费通道"这个形状上。

这是一条**故意开的口子**：人事调整免费，所以调将、换太守可以每月做，不占预算。
效果是把"人放在哪"从预算竞争里摘出去，变成一条永远可用的、纯结构性的操作。
【本文推导】这可能是无意的，但它的效果是让"人事"成为一条**零成本但高杠杆**的维度，
玩家可以在完全不花预算的情况下重排全国的能力分布。

**现代重发明的对照**：Old World（Mohawk Games，Soren Johnson，2021）的 **Orders** 系统。
Johnson 自陈灵感来自十年前 Facebook 页游的体力系统：

> "if you took this system and put it right on top of a 4X game - what would that look like?"

Old World 的数值【社群资料，Old World 官方 wiki / 攻略】：基础每回合 10 点（最高难度 "The Great" 只有 5 点），
每个市民 +0.1、每点 Legitimacy +0.1、马/骆驼/象的牧场各 +1、羊猪山羊 +0.5、驻军与要塞另加。

**关键差异**：Old World 的 Orders **随帝国规模平滑增长**（软上限），
霸王的大陆是 **12 封顶的硬上限**。
对本项目，**硬上限更可取**——它同时满足 C4（动作集有界）与反滚雪球，
而软上限只满足后者。

**这张表是整个游戏最巧的一处设计。【本文推导】**
升级**不是"变强"，是"变成另一种东西"**。
8 级武将**一个步兵都没有**——而攻城时步兵是主力。

| 当前武力 | 每次升级 |
| --- | --- |
| > 80 | +2 |
| 70–80 | +4 |
| 50–70 | +5 |
| 30–50 | +6 |
| ≤ 30 | +7 |

**弱者涨得快，强者涨得慢，且封顶 90。** 这是把武力这条轴**主动压平**，

#### 单挑（7 个选项）

牵制 / 攻击（成功率 50%）/ 战术（智力 < 80 慎用，不成反受害）/ 舍身一击 / 后退（可能被追讨掉血）/ 降伏 / 侦查。

**装备只在单挑时生效。** 武器分剑 / 刀 / 矛三类共 24 把，另有防具 8 件。
武器有重量，重量过大动作变迟钝。武器之间有克制关系（命中率表，攻方在左）：

| 攻 \ 守 | 剑 | 刀 | 矛 |
| --- | --- | --- | --- |
| 剑 | 70% | 75% | 60% |
| 刀 | 55% | 60% | 70% |
| 矛 | **80%** | 50% | 60% |

**这是一个非传递（intransitive）的三角**：矛克剑（80%），剑克刀（75%），刀克矛（70%）。
【本文推导】这是石头剪刀布结构，本项目要**谨慎**——非传递性会让 Elo 不收敛
（`GAMEPLAY-AI-FRIENDLY.md` 原则 12 已经点到席位轮换的必要性）。
在霸王的大陆里它只影响单挑这个边缘子系统，无害；如果放到主战斗结算里就是灾难。

#### 俘获

对方**体力被伤到 30 以下且被包围无处可逃**时才会投降。
所以"围而不杀"是一整套操作：呪缚定住 → 包围 → 打到体力 30 以下 → 收降。

| 每年 **4 月** | 百姓交租金（收金）。土地/产业/人口越高收得越多 |
| 每年 **5–6 月** | **水灾**。防灾值高则减少损失。主要损**钱粮** |
| 每年 **8–9 月** | **旱灾**。主要损**兵力**，每名武将减 150 人 |

**征兵**：100 兵 = 20 金。**每兵 0.2 金。**
**赏赐**：只有 10 / 100 两档。
**宝物**：1 宝 = 100 金，但赏赐效果强于 100 金。

【本文推导】把上面全部规则做一次统计：

| 类别 | 条目数 |
| --- | --- |
| 命令 | **16**（其中 1 条免费，1 条是存档，实际有效 14） |
| 城市状态字段 | 8 |
| 武将状态字段 | 10 |

| 阵形 | 4 |

| 地形 | 5 |
| 武器类别 | 3（+防具） |

75 条确实能写进一页纸（本节 §2.2–§2.8 全文约 4 页，其中大半是表格和公式）。

按 §8 的分类打标签，并给出**本项目适配度 ★1–5**（对照六条硬约束）。

| # | 机制 | 深度类型 | 适配度 | 理由（对照 C1–C6） |
| --- | --- | --- | --- | --- |
| **1** | **命令书 3–12 全局硬预算** | 机会成本 | **★★★★★** | C4 直接满足（把联合动作空间从 2^n 压到 C(n,12)）；C1 因预算稀缺被迫做战略取舍；C5 因每一枚命令书的错配都可归因 |
| **2** | **预算与领土脱钩** | 机会成本 + 反雪球 | **★★★★★** | 直接治 `GAMEPLAY-REVIEW.md` D1（"没有 kingmaker"是错的）与滚雪球；C6 因领先者也扩不快，局长可控 |
| **3** | **智力/忠诚的离散门槛（85/93/95/98/99；忠 90/40）** | 正交 + 交互 | **★★★★★** | C5 的核心：门槛让推理→结果的映射是**台阶状**的，正好对应 Lantz 的 step。模型只需判断"过没过 93"，不用算浮点 |

| **7** | **忠诚是可被对手操作的公共资源（离间/劝降）** | 交互 + 对手建模 | **★★★★☆** | 你的武将也是敌人的资源池。且离间要花命令书 → 跨维度机会成本。治 `GAMEPLAY-REVIEW.md` F8（忠诚公式全空） |

**第 10 条值得单独说。** 攻略原文：

> "当你所要进攻的城池中粮草不足却武将众多、兵力充足时，你可以智取，
> 即派一个平军（因为耗机动力最少），不带一兵一卒，只带 1 斤米，让敌方主动来攻击你，
> 你不与之接战，在屏幕中四处游走，因为电脑只有多部同进的习惯，他们需要耗费大量的机动力，
> 因而抓不到你，而他们的粮草却逐渐耗尽了，你就不战而胜。"

这是**四条独立规则的乘积**：
(a) 机动力随兵力变化，兵少则省 → (b) 平军在空地最省机动力 → (c) 守方也消耗粮草 →
(d) 30 日时限判守方胜，但粮尽就得退。
**没有任何一条规则说"可以饿死守军"。这个策略是玩家从规则交互里挖出来的。**

这正是 Lantz 说的"深游戏的最优策略说明书很长"。
一个 1992 年的 8 位机游戏，30 年后还有人在写新的攻略条目——
**这就是 `d` 在现实中的样子。**

但要诚实：**这条打法同时暴露了它的浅处**——它利用的是 AI 的行为缺陷
（"电脑只有多部同进的习惯"），不是对手的策略。本项目是模型对模型，
这类利用对手实现缺陷的策略**恰恰是我们要防的**（那是在测提示注入不是测推理）。

## 三、围棋与国际象棋：深度来源的一般原理

### 3.1 规则量：围棋的完整规则是十句话

Tromp–Taylor "Logical Rules of Go"（John Tromp & Bill Taylor）——
本质是新西兰规则（最简的中国式数子规则）的重述，为消歧义与简洁而优化：

1. 围棋在 19×19 方格上由黑白两方对弈。
2. 每个点可以是黑、白或空。
3. 点 P（颜色非 C）"reach" C，当且仅当存在一条从 P 出发、沿 P 同色点上下左右相邻、到达某个 C 色点的路径。
4. "Clearing 某色" = 清空该色中所有 reach 不到空点的点。
5. 从空盘开始，双方轮流行棋，黑先。
6. 一手棋是 pass，或者一个**不重复此前任何盘面着色**的落子。
7. 落子 = 把一个空点染成己色；然后 clear 对方色；然后 clear 己方色。
8. 连续两次 pass 则终局。
9. 一方的得分 = 己色点数 + 只 reach 到己色的空点数。
10. 得分高者胜。

**十句话，零随机，零隐藏信息。** 状态空间 10^170。

（国际象棋的规则量级相当：FIDE 规则里真正定义博弈的部分——棋盘、六种子的走法、
吃子、王车易位、吃过路兵、升变、将军、将死、逼和、重复局面与 50 步——大约二三十条。）

### 3.2 复杂度对照表【学术，Wikipedia *Game complexity*，转引 Allis 1994 等】

| 游戏 | 盘面大小 | 状态空间 log₁₀ | 博弈树 log₁₀ | 平均步数(ply) | **平均分支因子** | 复杂度类 |
| --- | --- | --- | --- | --- | --- | --- |
| 井字棋 | 9 | 3 | 5 | 9 | **4** | PSPACE-complete |
| 四子棋 | 42 | 12 | 21 | 36 | **4** | PSPACE |
| 国际象棋 | 64 | 44 | 123 | 70 | **35** | EXPTIME-complete |
| 将棋 | 81 | 71 | 226 | 115 | **92** | EXPTIME-complete |
| 围棋 19×19 | 361 | 170 | 505 | 211 | **250** | EXPTIME-complete |
| 万智牌 | ℵ₀ | ≥ℵ₀ | 2^ℵ₀ | ∞ | ≥ℵ₀ | AH-hard |

（Shannon 1950 给出的经典下界 10^120 是"Shannon 数"，
按每对着法约 10³ 种可能、一局约 40 对着法估出。上表的 10^123 是同一个量级的现代估计。）

### 3.3 一个对本项目决定性的观察【本文推导】

**人类玩过的最深的两个游戏，动作集都落在 O(10)–O(10²) 里面：**

- 国际象棋：**35**
- 围棋：**250**
- Onitama：**≤ 10**（见 §6.2）
- 四子棋：**4** ——但它已经被完全解出，`d` 很小

**所以本项目的 C4 约束（O(10)–O(10²)）不是深度的敌人，它是一个 3000 年经验验证过的正常区间。**
`GAMEPLAY-DESIGN.md` §2.4 论证第 2 条担心"动作太少 → 强弱模型选同一个"，
这个担心的方向是对的（四子棋确实浅），但**阈值定错了**——
不是"98 条才够"，围棋 250、象棋 35 都够，问题从来不是条数。

**同时注意反例：万智牌的分支因子是无穷，它并不比围棋深，只是不可分析。**
分支因子和深度的关系在中段可能正相关，在两端都失效。

### 3.4 四条一般原理

从围棋 / 象棋 / Hive / Onitama 的共性里抽出的、可以直接当设计规范用的四条【本文推导】：

**原理一：少量元件，稠密交互。**
围棋只有一种子，但**每一个子同时是四种东西**：占地的、造眼的、断的、劫材。
象棋六种子，但每种子的走法与其他五种在**同一张棋盘上互相约束**。
判据：**删掉任意一个元件/规则，是否有大量策略同时消失？** 是 → 交互稠密；否 → 那条规则是加法不是乘法。

**原理二：局部动作，全局后果。**
围棋一手棋落在角上，可能决定中央大龙的死活。
象棋一个兵的推进，可能永久改变王翼的安全性。
**这条产生的是"长程信用分配"深度**——也是最难 AI 化、最能区分推理强弱的一类。
判据：**是否存在"看起来局部、实际全局"的动作？**

**原理三：没有可回收的资源。**
围棋落子不能悔，象棋吃掉的子不回来。
**不可逆性是时机深度（tempo）的前提**：如果所有动作都能撤销，"什么时候做"就不重要了。
判据：**动作是否不可逆？是否存在"用错了就永久损失"的资源？**

**原理四：零随机 + 零隐藏 = 全部误差归因于推理。**
这条对本项目是 C5 的极限形式。围棋和象棋把**所有**不确定性都放在"对手会怎么下"上。
海德堡的数据说明了代价：一旦掺入随机，Elo 离散度从 170 掉到 45。

## 四、《文明》：核心循环 vs 后期操作膨胀

### 4.1 核心循环有多小

Civ 的核心循环其实只有三条：

1. **一格地块分配给一个市民**（产出粮/锤/金）
2. **一座城生产一样东西**（单位/建筑/奇观）
3. **全国研究一项科技**

三条规则，加上"城市可以建更多城"，就是整个 4X 的引擎。
Sid Meier 的名言"a series of interesting decisions"（GDC 1989，2012 年 GDC 又专门讲了一次）
在 Civ 里就是这三条循环反复出现。

他 2012 年给出的"什么算 interesting decision"的判据（Game Developer 报道）：

- **有权衡**（tradeoff）
- **随情境变化**：*"Good decisions are situational. ... when the decision is presented to the player,
  ideally it acts in an interesting way with the game situation."*
- **能表达个人风格**
- **有持续影响**且玩家有足够信息
- **风险-收益**
- **时间尺度有长有短**

反面：*"If a player always chooses the first from among a set of three choices,
it's probably not an interesting choice; nor is a random selection."*

**"总是选第一个"和"随机选"是同一种失败。** 前者是支配策略，后者是无信息。
两条都直接指向 Lantz 的 `d` = 1。

### 4.2 Civ IV（2005）：Soren Johnson 的减法

Civ IV 团队把"去掉不必要的微操"当成一条**高层设计目标**，
系统性地检查 Civ 1–3 的每一处微操，找办法在**不改变底层博弈动态**的前提下删掉它。
删掉的包括：**腐败、污染、城市暴乱**，以及一堆琐碎系统。

Johnson 还举过一个例子：Civ IV 的宗教原本通过贸易路线与接触复杂传播，
但玩家看不见这个机制在运作，于是改成了直接得多的做法。

**教训一条：看不见的复杂度是纯负担。**
它吃状态空间、吃 UI、吃学习成本，但因为玩家（模型）无法把它纳入推理，`d` 贡献为 0。
**对本项目**：任何不进观测的机制，等于不存在，但仍然要付实现成本。
`GAMEPLAY-REVIEW.md` §7.2"收益配不上成本的设计"那一节该按这条重查一遍。

### 4.3 Civ V（2010）：1UPT——加深了战术，毁掉了动作集和 AI

一格一单位（1UPT）是 Civ V 最大的规则改动，主设计师 Jon Shafer。
他后来在 At the Gates 的 Kickstarter 更新里做了大篇幅自我批评（2013 年 2 月，
经 spacesector / PC Gamer / Quarter to Three 转述）：

- 承认 1UPT 的战斗**确实比之前允许叠单位的 Civ 更好**
- 但产生了 **"carpet of doom"**：单位地毯能轻易铺满半块大陆，**每回合都要一个一个挪**
- **"one of the biggest challenges unearthed by 1UPT was writing a competent combat AI"**
- 地图瓶颈太多，无法做出像样的机动
- Shafer 的自评被 Ed Beach（Gods & Kings 主设计）认为 *"a little harsh on it"*

**这是本文最重要的反面案例。【本文推导】**
1UPT 是一条**真正增加了策略深度**的规则——它把战斗从"堆数值"变成了"位置博弈"。
但它同时做了两件对本项目致命的事：

| 后果 | 违反的约束 |
| --- | --- |
| 动作数 ∝ 单位数 ∝ 领土面积，无上界 | **C4** |
| 决策颗粒度掉到"这个单位这一格" | **C1** |
| 写不出胜任的 AI | **C5**（对手不会玩，测不出强弱） |

**结论：一条规则可以同时提高 `d` 和摧毁可评测性。**
判断一条机制不能只问"深不深"，要问"深度增量 / 动作空间增量"这个比值。
1UPT 的这个比值很差。

### 4.4 Civ VII（2025）：用"重置"对付膨胀

Ed Beach（创意总监）在发售前访谈里的原话：

> "The number-one issue that the Ages system solves for us is it helps you to get towards the end
> of a game and not feel like you're overwhelmed with too many things to manage,
> too many decisions to make to get through each turn."
> —— GamesRadar 访谈

> "the Ages system gives us points where we reset the game a little bit,
> and players get a chance to get a little bit of calm and to breathe
> and to get that scale back down."
> —— GGRecon 访谈

Firaxis 团队还发现玩家**普遍不把一局玩完**——
"I'd have more fun starting a new session than trying to finish it!"

**三十年三代人在打同一个敌人：动作数随棋盘规模单调增长。**

| 世代 | 解法 | 代价 |
| --- | --- | --- |
| Civ IV | **删**（腐败、污染、暴乱） | 一次性，删完还会再长回来 |
| Civ V | **不解**，改成 1UPT 后更糟 | AI 崩、后期 tedium |
| Civ VII | **周期性重置**（Ages） | 破坏了叙事连续性，是 Civ VII 争议最大的改动 |
| **霸王的大陆 / Old World** | **从第一回合就设预算** | 后期决策空间也一起缩（§2.11） |

**对本项目：走第四条路。** 我们不需要"重置"这种破坏性手术，
因为我们从设计第一天就可以把预算写死（`GAMEPLAY-DESIGN.md` §2.2 的 SP 已经是这个方向）。

### 4.5 Old World（2021）：命令书的现代重发明

见 §2.2。要点重申：Soren Johnson 明确说灵感来自 Facebook 页游的体力系统。
**这个机制在 1992 年的 Namco 和 2021 年的 Mohawk 各被独立发明了一次**，
中间隔着三十年和整个 4X 品类对微操膨胀的挣扎。

**Old World 与霸王的大陆的关键差异**：

| 项 | 霸王的大陆 | Old World |
| --- | --- | --- |
| 预算 | 3–12，**硬上限** | 基础 10（最难 5），随人口/正统性/资源**平滑增长** |
| 计价 | **全部 1 枚**（任命免费） | 不同动作不同耗 |
| 与领土 | 超过某点后**完全脱钩** | 始终正相关 |

**本项目该取霸王的大陆那一边，理由见 §10 手法 1 与手法 2。**

## 五、Diplomacy：规则一页纸，深度全在意图

### 5.1 规则【原始规则，Calhamer 1954 设计，1959 商业发行】

| 项 | 值 |
| --- | --- |
| 玩家 | 7 家（英、法、德、意、奥匈、俄、土） |
| 补给中心 | **34** |
| 胜利条件 | 年末持有 **≥ 18** 个补给中心 |
| 单位类型 | **2 种**：陆军（Army）、舰队（Fleet） |
| 命令类型 | **4 种**：Hold、Move、Support、Convoy |
| 随机 | **零** |
| 隐藏信息 | 棋盘全公开；**只有"这一轮谁下了什么令"是隐藏的** |
| 阶段 | 春季行军 → 秋季行军 → 补给中心清点 → 冬季建军/裁军 |

**裁决规则（全部）**：
- Hold 的强度为 1
- 进攻方支援数 **必须严格大于** 防守方，否则 standoff（双方都不动）
- **支援被打断**：支援单位若在本回合被其他单位攻击，其支援作废（cut support）
- 被击退的单位进入 retreat 阶段，无处可退则解散
- 冬季按补给中心数补齐/裁减单位，只能在本国原始补给中心建军（各国 3 个，俄国 4 个）

**这是一份可以完整写进 4000 token 的规则集。**

### 5.2 深度从哪来【本文推导】

**全部来自三条规则的乘积：**

1. **同时下令**（所有人的命令同时提交、同时揭示）
2. **支援机制**（一个单位无法独立突破，必须有第二个单位支援）
3. **支援可以来自任何人的单位**（包括你没有正式盟约的人）

规则 2 制造了**强制合作**：你必须有盟友才能推进。
规则 3 让盟友是**任意的、临时的、无约束力的**。
规则 1 让"这次他会不会背叛"成为**不可验证的赌注**——你在下令时不知道他的令。

于是最优策略必须包含**对手模型**：
"他这一轮支不支援我"不是概率问题（没有随机），是**心理与信誉问题**。
**这是 Diplomacy 的全部深度，一个骰子都没有。**

Diplomacy 也是本文里唯一一个**深度主要来自 S5（对手建模）**的例子。
其他所有游戏的深度都来自棋盘。

### 5.3 唯一的越界：联合动作空间【本文推导】

Diplomacy 的**单个单位**命令数很小：4 种命令 × 相邻地区，通常 < 20。
但一方要**同时给全部单位下令**，联合动作空间是各单位命令集的**笛卡尔积**。
一个 10 单位的强国，联合动作数轻松过 10^10。

**这正是霸王的大陆的命令书要治的病。**
把"每个单位都要下令"改成"全国这个月只有 12 次操作机会"，
联合动作空间从 ∏(每单位选项) 降到 C(总条目数, 12) × (参数域)。

**这是本文最实用的一条综合：把 Diplomacy 的意图博弈，套在霸王的大陆的动作预算里。**

### 5.4 CICERO 的证据【学术】

Meta FAIR，*Science*，2022。CICERO 在 Full-press 七人 Diplomacy（Blitz 版，每轮 5 分钟谈判）
的匿名在线联赛里：

- **40 局**
- 得分**超过人类平均分的两倍**
- 在"打过一局以上"的参赛者中**排前 10%**
- 与 82 名其他玩家沟通
- 架构：**2.7B 参数**语言模型 + 策略规划算法

**两条对本项目的读法**：
1. 2.7B 参数就能在这个环境里打到人类前 10% —— **这个环境本身的区分度很好**，
   因为规则简单、随机为零，模型能力可以完整表达。
2. 但也说明：**如果本项目的规则复杂到 2026 年的前沿模型都读不明白，
   我们测的就不是推理，是阅读理解。**

## 六、Hive 与 Onitama：极简抽象的两种做法

### 6.1 Hive（John Yianni，2001）【原始规则，Wikipedia】

| 项 | 值 |
| --- | --- |
| 棋盘 | **没有棋盘**。棋子本身构成棋盘，落在无限六边形平面上 |
| 每方棋子 | **11 枚**：蜂后 ×1、蜘蛛 ×2、甲虫 ×2、蚱蜢 ×3、蚂蚁 ×3 |
| 随机 | 零 |
| 隐藏信息 | 零 |
| 胜利 | 对方蜂后被**六面全部包围**（不论包围的子属于谁） |

走法：

| 子 | 走法 |
| --- | --- |
| 蜂后 | 每次一格 |
| 甲虫 | 每次一格，**可以爬到任何相邻棋子之上**；被压住的子不能动 |
| 蜘蛛 | **恰好沿边缘走三格** |
| 蚱蜢 | 沿直线跳过任意数量的棋子，落在对面第一个空位 |
| 蚂蚁 | 沿边缘走**任意格数** |

两条约束规则是全游戏的核心：

- **One Hive Rule**：任何时候所有棋子必须连成一个整体。
  **一个子若移走会把蜂巢断成两块，就不能动。**
- **Freedom to Move**：棋子不能移入或移出被（几乎）完全包围的格子（甲虫和蚱蜢例外）。
- 蜂后**必须在前四手内落下**。

**深度从哪来【本文推导】**：
**One Hive Rule 让每一个棋子同时是攻击者和承重结构。**
你把蚂蚁放到那个位置，既威胁了对方蜂后，也可能把自己的甲虫钉死（它一动蜂巢就断）。
**11 枚子，但每一枚都身兼两职，交互对是 C(22,2) 的量级。**

这是**原理一（少量元件稠密交互）的极致形式**：
一条规则（连通性）就把"位置价值"和"机动性代价"绑在了一起。

**可搬的手法**：找一条**全局结构约束**，让每一个局部动作都必须顾及它。
本项目的候选：**补给线连通性**——每支军团必须与己方领土保持连通的补给路径，
拔掉中间任何一个郡都会导致断补。这一条规则同时产生：
纵深防御的价值、切断补给的战术、以及"占了但守不住"的取舍。

### 6.2 Onitama（Shimpei Sato，2014）【原始规则】

| 项 | 值 |
| --- | --- |
| 棋盘 | **5×5** |
| 每方棋子 | 5 枚（1 师父 + 4 弟子），走法完全相同 |
| 走法牌 | 总共 **16 张**，开局随机抽 **5 张**：双方各 2 张明牌，第 5 张放旁边 |
| 一手 | 选一张自己的牌 → 按牌上的图案移动任意一枚己方棋子 → **把用过的牌交给对手**（换回旁边那张） |
| 胜利 | 吃掉对方师父，或己方师父走到对方师父的起始格 |

**分支因子【本文推导】**：2 张手牌 × 最多 5 枚棋子 = **上限 10 个合法着法**，实战通常更少。
**开局配置数**：C(16,5) = **4,368** 种。

**深度从哪来【本文推导】——三条**：

1. **走法本身是可交易的资源。** 你用了一张牌，牌就到了对手手里。
   所以"这一手强不强"要同时算"我把什么武器交给了他"。
   **这是把 tempo（时机）显式做成了物件。**
2. **规则集在每局开始时随机重排，但局内完全确定。** 这正是
   `GAMEPLAY-AI-FRIENDLY.md` 原则 7 说的"随机只放在决策之前"的教科书实现：
   4368 种开局，每一种都是一个全新的、确定的谜题。
   **随机制造了变化，但没有制造方差。**
3. **分支因子 ≤ 10，但没有一个 dud。** 每一张牌都在某个局面下是最优解。

**可搬的手法**：
- 把"能做什么"做成有限的、会流转的手牌，而不是永久解锁的能力表
- 局间随机（开局配置）+ 局内确定，是提高样本多样性又不牺牲区分度的唯一干净做法

## 七、EU4 的 mana vs 维多利亚 3 的市场：两种相反的复杂度取向

### 7.1 EU4（Paradox，2013-08-13）：把一切接到三个标量上

**君主点数（monarch power）**三种：行政（ADM）、外交（DIP）、军事（MIL）。

生成【Paradox 官方 wiki】：基础每月 **+3**；上限约每月 20
（君主 +6、顾问 +5、国策焦点 +2、势力投射 +1、庄园 +1、特殊 +1、基础 +3）。
存量上限 **999**。

支出（这份清单本身就是论证）：

| 类型 | 花在什么上 |
| --- | --- |
| **行政** | 省份开发(50)、理念(400)、政策、原生理念(500)、**科技(600)**、**核心化(10/开发度)**、迁都(200–500)、**稳定度(100+)**、通胀削减(75)、关税(25–50)、基础设施(50)、贸易站(50)、教会领(50) |
| **外交** | 文化转换(10/开发度)、文化推广(100)、海军将领(50)、少数民族(50)、厌战(75)、宿敌(100)、重商主义(100)、贸易港(200)、**附庸吞并(8/开发度)**、外交关系维护(1/月)、无理要求(50) |
| **军事** | 夺取殖民地(25)、焚毁殖民地(5)、严酷镇压(50–200)、炮击(50)、强攻(5)、原住民攻击(10/千)、强行军(2/省)、焦土(5)、出击(5)、战争税(2/月)、陆军将领(50)、将领维护(1/月)、军事化(50)、圣战(50)、政府强化(100) |

**社群把它叫 "mana"**：点一下按钮，花掉点数，然后"魔法般"地发生一件事。
批评的核心不是"它抽象"，是"它**不区分**"——科技进步、文化同化、士兵强行军、
镇压叛乱，全都是同一种点数。

**代价【本文推导】**：
交互密度很高（所有子系统都竞争同一个池子），但**交互全部经过一个瓶颈**。
决策退化成"这 600 点买科技还是买核心化"——一个一维的兑换率问题。
**它有 S3（机会成本）深度，但几乎没有 S1（交互）深度**，
因为子系统之间不直接互相作用，只通过点数间接竞争。

**与霸王的大陆命令书的关键区别**：
命令书是 **3–12 的小整数**，逼出"这个月只能做三件事"的取舍；
mana 是 **999 上限的连续存量**，逼出的是"攒够了再花"——
**存量足够大的时候，机会成本就消失了。** 一个 3000 点存量的玩家不面对任何取舍。

### 7.2 维多利亚 3（Paradox，2022）：把一切做成显式模拟

核心是**商品市场**：

- 商品**不在生产者与消费者之间直接交易**，而是全部汇入一个国家市场，
  由**买单（Buy Orders）与卖单（Sell Orders）**决定价格【社群资料，需以当前版本为准】
- 每种商品有基础价格，实际价格随买卖单差额浮动，**区间为基础价的 25% ~ 175%**【Paradox 官方 wiki】
- 商品种类：wiki 按类目列出 staple 13 / luxury 16 / industrial 20 / military 4，**合计 53**；
  抓取摘要另处给出"67 种标准商品"。**两者对不上，我未能核实哪个对应当前版本，此处只用量级：数十种**【查不到】
- Pop 有生活水平（SoL），按财富档次决定需求；带替代品的需求，
  按市场上各替代品的相对卖单量分配购买

**代价**：
系统的因果链非常长（关税 → 进口价 → 工厂利润 → 工资 → Pop 生活水平 → 政治派系支持度 → 法律 → 生产率），
玩家**看不见中间环节**。Paradox 论坛长期有"Victoria 3 的经济学是根本性坏的"这类争议帖。
**这正是 Civ IV 教训的反面：看不见的复杂度是纯负担。**

### 7.3 两种取向的代价对照

| 维度 | EU4 mana | Vic3 市场 | 本项目该怎么办 |
| --- | --- | --- | --- |
| 状态量 | 3 个整数 | 数十种商品 × 每个市场 × 每个 Pop | **靠 EU4 这边**（C2 观测预算） |
| 因果链长度 | 1 步（花点数 → 立即生效） | 5–8 步 | **中间：2–3 步** |
| 可解释性 | 极高，但"不像历史" | 极低，玩家读不懂 | **必须高**：模型要能写出"我为什么这么做" |
| 交互密度 S1 | **低**（全走同一瓶颈） | **高** | 要高 |
| 机会成本 S3 | 高，但被 999 存量稀释 | 中 | 要高**且不可囤积** |
| 可枚举性 C4 | 好 | 差（连续量） | **必须好** |
| 长程信用分配 S6 | 弱 | 强 | 中等 |

### 7.4 本项目该站哪边【本文推导】

**站 EU4 这边，但修掉它的两个病：**

**病一：单一瓶颈。**
EU4 只有三种点数，且三种点数之间的分工不完全（很多东西 ADM 和 DIP 都能做类似的事）。
本项目应该：**动作预算只有一个池子（命令书），但动作本身分成互相不可替代的种类**。
即：**预算一维，效果多维**。取舍的张力来自"效果不可互换"，不是来自"预算种类多"。

**病二：可囤积。**
999 的上限意味着强国不面对取舍。
`GAMEPLAY-DESIGN.md` §2.2 的 SP 允许"上季结转 ≤4"，加上爵位 +2，
名义 12 的上限实际能到 18——**这是同一个病的轻症版**。
建议：**结转上限压到 ≤2，或者干脆取消**。理由见 §10 手法 1。

## 八、结论一：策略深度的七类来源

每一类给出：定义、判据（可以拿去检查任何一条机制）、正例、
以及**本项目当前设计在这一类上的得分**（对照 `GAMEPLAY-DESIGN.md` 与 `GAMEPLAY-REVIEW.md`）。

| 代号 | 类别 | 一句话定义 | 判据 |
| --- | --- | --- | --- |
| **S1** | **交互 / 组合** | n 个元件产生远多于 n 的有意义组合 | 删掉任一元件，是否有**大量**策略同时消失 |
| **S2** | **时机 / 序（tempo）** | 同一动作在不同时刻价值不同；先手是可争夺的资源 | 是否存在"现在做 vs 下季做"的非平凡权衡 |
| **S3** | **资源权衡 / 机会成本** | 动作预算稀缺且不可囤积 | 是否存在"什么都做"的路径。有 → 这一类得分 0 |
| **S4** | **不完全信息** | 分两种：**状态不可见** vs **意图不可见** | 未知量是否可以通过推理（而非掷骰）收敛 |
| **S5** | **对手建模** | 最优解依赖于"对手是谁" | 换一个对手，最优解是否改变 |
| **S6** | **长程信用分配** | 现在的动作 N 步之后才结算 | 最优动作是否需要 ≥3 步前瞻 |
| **S7** | **正交差异化** | 元件在**质**上不同而非量上不同 | 能否把所有元件排成一条"谁更强"的序。能 → 这一类得分 0 |

### 逐条展开

**S1 交互 / 组合。** 正例：围棋（一子四职）、Hive（One Hive Rule 让每子身兼两职）、
霸王的大陆的计略（地形 × 相邻 × 智力 × 机动力 × 射程五维耦合）。
**这是深度密度最高的一类**，因为它的收益随元件数**超线性**增长而状态空间只线性增长。

**S2 时机。** 正例：Onitama（用过的牌交给对手，所以"什么时候用"就是"什么时候武装对手"）、
Diplomacy 的春秋两季（秋季结束才清点补给中心，所以秋季的一格比春季的一格值钱）、
霸王的大陆的 4 月收金 / 10 月收粮（内政投资必须赶在结算月之前）。
**它是最便宜的深度来源**：加一个"结算时点"，零新状态量。

**S3 机会成本。** 正例：命令书、Old World 的 Orders、EU4 的 mana（打折版）。
**判据严格**：如果存在一条"什么都做"的路径，这一类的深度就是 0，不管选项有多少。

**S4 不完全信息 —— 必须拆成两种。**
- **状态不可见**（战争迷雾、Stratego 的暗棋）：**多数情况下只产生方差不产生深度**。
  因为未知量往往无法通过推理收敛，只能猜。猜错 = 运气。
- **意图不可见**（Diplomacy 的密封下令、扑克的手牌范围）：**产生深度**。
  因为意图是可以通过对手的历史行为、当前局势、语言承诺来**推理**的。
  `GAMEPLAY-AI-FRIENDLY.md` 原则 8 已经采纳了这个区分，本文只是给出它的深度学理由。

**S5 对手建模。** 正例：Diplomacy、狼人杀、扑克。
**这是 LLM 之间最可能拉开差距的一类**，但也是最难稳定测量的
（`GAMEPLAY-REVIEW.md` D1/D3 关于围殴与众怒的三条问题都在这一类）。
学术侧的现成基准：**MINDGAMES**（arXiv:2605.29512，2025 年竞赛周期，
论文原文只说"hosted at a major AI conference"，**未点名会议**——本文不替它认定是 NeurIPS）。
TrueSkill 评分，**944 个提交智能体 / 76 支队伍**，公开了 **29,571 局**带回合级观测-动作-回报的对局数据。
四个游戏是具名的，值得逐个对照本项目要测的维度：

| 游戏 | 测什么 | 与本项目的关系 |
| --- | --- | --- |
| **Colonel Blotto**（兵力分配博弈） | 隐藏信息下的对手建模 | **最接近本项目**：同时下令、资源在多个战场间分配、零随机 |
| **Iterated Prisoner's Dilemma** | 重复博弈中的信任与背叛 | 对应盟约与背盟 |
| **Codenames** | 知识不对称下的协作推断 | 本项目暂不涉及 |
| **Secret Mafia** | 社会推理中的持续欺骗 | 对应谈判通道的欺骗成分 |

**Colonel Blotto 尤其值得看**：它是"同时密封下令 + 确定性裁决 + 资源互斥分配"的最小形式，
和本文手法 1（命令书预算）+ 首轮方案的 WEGO 骨架是同一个结构。
**如果本项目需要一个可以先跑起来的、极小的预演环境，Blotto 的多战场变体是现成的。**

**S6 长程信用分配。** 正例：Civ 的科技树、霸王的大陆的内政复利（投资 4 月才回本）。
**风险**：太长会稀释归因，模型学不到；太短就没有规划。
`GAMEPLAY-DESIGN.md` 的工程 4–12 季、`GAMEPLAY-REVIEW.md` §7.2 建议砍到 2 种——砍是对的，
但**要保留至少一条 3–5 季回报期的投资通道**，否则 S6 归零。

**S7 正交差异化。** 出处：Harvey Smith，GDC 2003（"orthogonal unit differentiation"）。
正例：象棋六种子、霸王的大陆的兵种 × 地形矩阵与等级 × 部队构成表。
**判据是最锋利的一条**：如果 578 名武将可以排成一条"谁更强"的序，那这 578 个数据点的深度贡献 ≈ log(578)。
如果每名武将有一个离散适性标签，让"带谁"取决于"打哪"，深度贡献是一个匹配问题的规模。

### 两类伪深度（必须点名）

| 伪类别 | 表现 | 反证 |
| --- | --- | --- |
| **F1 数值广度** | 更多单位类型、更多建筑、更多资源、更多属性维度 | Lantz 的"翻牌"思想实验：状态空间翻倍，深度不变 |
| **F2 结算随机性** | 战斗掷骰、事件掷骰、成功率 | 海德堡实验：一半对局换成掷硬币，Elo 离散度从 170 → 45 |

**F2 要特别强调**：随机性**看起来**像深度，因为它让局面难以预测。
但"难以预测"和"需要更好的推理"是两件事。
随机性让**任何**推理水平的玩家结果都变得难以预测——**它同等地惩罚强弱双方**，
所以它降低而非提高区分度。

## 九、结论二：规则数量与策略深度的关系

### 9.1 正确的自变量是交互密度，不是规则数【本文推导】

设规则数 n，其中**实际发生非平凡交互的规则对数** m ≤ C(n,2)。

**假说：`d` 主要由 m 决定，与 n 只有弱相关。**

三个数据点：

| 游戏 | n（规则条目量级） | m/C(n,2) | `d` |
| --- | --- | --- | --- |
| 围棋 | **10**（Tromp–Taylor） | 接近 1。劫争 = 规则 6×7×8 的三重交互；死活 = 规则 3×4×7；官子 = 规则 9 与 6 | 极大 |
| 霸王的大陆 | ≈ 75 | 中高。计略一块就是六维耦合 | 中大（30 年社群） |
| EU4 | 数千 | **低**。mana 把几十个子系统接到同一个标量上，交互全走瓶颈 | 中 |
| Vic3 | 数千 | 高，但**不可观测**（因果链 5–8 步，玩家读不到） | 主观上低（论坛长期争议） |

**推论：少而密 > 多而疏。** 这不是"简约的美德"，是算术：
n 条规则最多产生 C(n,2) 个交互对，而**观测成本和实现成本随 n 线性增长**。
所以**每条规则的深度产出 ∝ 它参与的交互数**。

**一条可以直接用的设计规范：**
> 一条新规则如果**不能改变至少两条既有规则的最优用法**，
> 它只增加 complexity，不增加 depth。删掉它。

### 9.2 加规则反而降低深度的七个条件

| 编号 | 条件 | 机制 | 出处 / 实例 |
| --- | --- | --- | --- |
| **R1** | 新规则提供了**支配策略** | `d` 塌成 1 个台阶（Lantz 的 "one weird trick" 失败模式） | 霸王的大陆的学问所刷智力；`GAMEPLAY-REVIEW.md` §3.2 的"苟活" |
| **R2** | 新选项是 **dud**（明显劣解） | 只涨分支因子不涨 `d` | Lantz 的 dud 思想实验；Sid Meier"总是选第一个" |
| **R3** | 新规则是**加法不是乘法**（与既有元件不交互） | 状态空间涨，`d` 不涨，观测预算被吃掉 | Lantz 的翻牌思想实验；§9.1 的规范 |
| **R4** | 新规则引入**结算随机** | 稀释技能信号 | 海德堡：Elo 离散度 170 → 45 |
| **R5** | 新规则把**决策变成执行** | 对人是 tedium，对 AI 是动作空间爆炸 | Civ V 的 1UPT / carpet of doom；Shafer 自陈 AI 写不出来 |
| **R6** | 新规则**打破可枚举性**（连续量、自由文本、笛卡尔积展开） | 模型只能猜，推理无法转化为动作 | Vic3 的市场；Diplomacy 的联合动作空间 |
| **R7** | 规则总量**超过工作记忆 / 上下文预算** | 玩家（模型）退回到少数启发式，等价于新规则不存在 | Civ VII 的 Ages 动机（Beach："overwhelmed with too many things to manage"）；Civ IV 的宗教传播改版 |

**R7 对本项目有一个特殊形式**：
如果观测超过模型的**有效**上下文（不是名义上下文），
多出来的规则不只是无效，它还会**挤掉**有效规则的注意力。
`GAMEPLAY-REVIEW.md` B1 判定 token 预算低估 1.7–3 倍，本质上是 R7 的一次触发。

### 9.3 用这七条回看本项目：三处已经中招【本文推导】

**（一）R2 + R3：`C(98,5) ≈ 6.7×10⁷` 不是深度的证据。**

`GAMEPLAY-DESIGN.md` §2.4 论证第 3 条写：
"SP 预算让模型每季从 ~98 条里选 4–7 条，组合数 C(98,5) ≈ 6.7×10⁷ ... 深度完全够"。

**这个论证有两个漏洞，都是 Lantz 已经排除过的形式：**

*漏洞 a（R2）*：C(98,5) 里绝大多数组合是 dud。
98 条里 `fortify` 8 条 + `levy` 8 条 + `scout` 9 条 = 25 条是"逐郡展开的同类动作"。
**这 25 条之间没有任何交互**，选哪个郡去 fortify 基本由"哪个郡最靠前线"单一决定。
它们对 `d` 的贡献接近于 log(8) 而不是 C(8,k)。

*漏洞 b（R3）*：组合数 ≠ 有意义组合数。
真正产生深度的是"这 5 条之间互相影响"的组合。
`campaign` + `scheme:断粮` 是有交互的（断粮改变攻城结算）；
`fortify 郡A` + `levy 郡B` 之间**没有任何交互**，它们只是同时发生。

**建议的替代论证**：不要用组合数论证深度，用**交互对计数**：
数一数 20 个模板里有多少对模板的**联合效果 ≠ 各自效果之和**。
如果这个数低于 20（即平均每个模板只与 2 个模板交互），深度就不够，
要加的不是模板数，是**模板之间的耦合**。

**（二）R1：SP 差别定价创造了支配策略。**

`GAMEPLAY-REVIEW.md` 已经独立发现了三个实例：
- F4：`scheme:断粮` 花 2 SP 删掉一支军团
- F5：`abrogate` 废约 与 `respond` 复议 标价 **0 SP**
- F1：`requestWakeAt` 没有预算，模型可以自选调用次数

**这三条是同一个病**：**价格表本身就是一条规则，而且是一条极容易出错的规则。**
定价表编码的是设计者对"什么强"的判断。判断错一格，模型就找到一条最优通路，`d` 塌一层。

**霸王的大陆的做法是把这条规则整个删掉**：所有命令一律 1 枚（任命免费）。
这样**深度只能来自"做什么"，不能来自"钻价格表"**。

**（三）R4：结算随机。**
`GAMEPLAY-DESIGN.md` 的骨架已经是确定性结算，这一条**没有中招**，
但 `GAMEPLAY-REVIEW.md` §3.5 提出的"确定性 ≠ 可区分"是同一个问题的另一面：
确定性但**分档太粗**（情报档宽比决策阈值还大）等价于掷骰。
建议按审查的 13 档等比 1.4 改。

## 十、结论三：O(10²) 动作集下，深度从哪里来 —— 八条设计手法

每条给：**出处 → 机制 → 本项目怎么落 → 对照六约束 → 适配度 ★ → 与既有文档的接口**。

---

### 手法 1：全局动作预算，硬上限，与领土脱钩，且不可囤积

**出处**：《三国志Ⅱ 覇王の大陸》命令书（Namco，1992）：下限 3、上限 12，与城池数挂钩但封顶；
Old World Orders（Mohawk Games，2021，Soren Johnson 自陈灵感来自 Facebook 页游体力系统）。

**机制**：一个月/一季全国只有 N 次操作机会。每次操作 = 一个 (据点, 命令) 二元组。

**为什么产生深度**：**深度来自互斥，不来自数量。**
无预算时最优解是"全下"，98 条动作的深度贡献是 0；
有预算时问题变成背包问题，且每条的价值依赖于你选了哪些别的（§2.2）。

**本项目怎么落**（在 `GAMEPLAY-DESIGN.md` §2.2 现有 SP 基础上改三处）：

| 现状 | 改成 | 理由 |
| --- | --- | --- |
| `SP = 5 + ⌊√n⌋ + 爵位(0–2) + 结转(≤4)`，实际可达 18 | **`SP = min(5 + ⌊√n⌋, 12)`，结转上限 ≤2，爵位加成移出 SP** | 硬上限治 C4；结转治 EU4 的"可囤积"病（§7.4） |
| 每条命令 SP 价 0–3 | **一律 1 SP**，只保留 `campaign` = 2 一个例外（因为它是唯一带走部队的动作） | 删掉价格表这条规则本身（§9.3 之二）。爵位加成改成"多一枚 SP"而不是"某类命令打折" |
| 无"每郡上限" | **加一条：同一郡国一季最多 2 条命令** | 防止把 12 枚全砸一个郡产生的退化打法；也让第一级枚举天然分散 |

**对照六约束**：C1 ✓（预算稀缺 → 被迫战略取舍）；C2 ✓（不增加状态量）；
C3 无关；**C4 ✓✓（联合动作空间从 2^98 降到 C(98,≤12)）**；
C5 ✓（每一枚 SP 的错配可归因）；C6 ✓（反滚雪球）。

**适配度：★★★★★**
**接口**：替换 `GAMEPLAY-DESIGN.md` §2.2 的 SP 公式与 §2.3 表格的 SP 列。
同时解决 `GAMEPLAY-REVIEW.md` 的 F1、F4、F5 三条。

### 手法 2：一级动作枚举，二级参数全部离散到 ≤3 档

**出处**：霸王的大陆的赏赐**只有 10 / 100 两档**、征兵下限 100 且按 100 为单位、
运送只能到相邻己方城；Onitama 的走法只能来自手上两张牌。
反面出处：`GAMEPLAY-REVIEW.md` §1.2 实测 `campaign` 一条的第二级填法达 **10⁵–10⁶** 量级。

**机制**：动作的第一级（做什么、对谁）枚举给出；第二级（多少、谁去）**必须是小的离散域**。

**为什么产生深度**：连续参数不产生决策，只产生"取边界值"。
`strength ∈ [0,1]` 的最优解永远在端点或某个由公式决定的点上——**这是计算不是决策**。
`strength ∈ {半, 主力, 全}` 才是权衡。

**本项目怎么落**：

| 参数 | 现状 | 改成 |
| --- | --- | --- |
| `campaign.strength` | 4 档 | **3 档**：偏师 / 主力 / 倾国 |
| `campaign.deputies` | `≤2 任选`（C(24,2) = 276 种） | **`≤2 且必须与主将同驻地`**（审查已提，采纳） |
| `campaign.posture` | 6 档 | **4 档**（审查第三梯队已提） |
| `levy.scale` | 轻/重 2 档 | 保持 |
| `reward.kind` | 4 种 | **改成 3 档金额（少/中/厚），种类归一** |
| 一切贡赋、条款数量 | 连续量（审查 F6 已点名） | **一律 3 档** |

**额外一条【本文推导】**：
参数域的每个取值挂 1 token 的**确定性提示位**（审查 §1.3 已提出，本文完全支持）。
理由是 Lantz 的判据：**藏起来的信息如果无法通过推理收敛，它产生的是方差不是深度。**

**对照六约束**：C1 ✓；C2 ✓；C4 ✓✓；C5 ✓（第二级填错的 IAR 下降）。
**适配度：★★★★★**
**接口**：`GAMEPLAY-DESIGN.md` §2.3 参数表逐行改；解决 `GAMEPLAY-REVIEW.md` A1/A3/F6。

### 手法 3：离散门槛，不要连续曲线

**出处**：霸王的大陆的智力门槛（85 / 93 / 95 / 98 / 99 五档解锁计略）、
战术门槛（挑発需智 ≥ 38，爆炎需智 ≥ 93）、忠诚门槛（≥90 不能离间，<40 可劝降，≤25 容易）、
武力封顶 90 且分段成长。

**机制**：能力用**阈值开关**表达，不用连续加成表达。

**为什么产生深度**（三条，都直指 C5）：

1. **阈值就是 Lantz 的 step。** 跨过阈值得到的是**离散的、非边际的**回报。
   模型正确推理"我需要把这个人的谋略提到 93"，回报是可见的一整类新动作，
   而不是一个 3% 的数值提升。**这正是"strategy ladder 的台阶"在规则层的直接实现。**
2. **阈值把浮点变成布尔。** 模型不必算 `0.87 × 1.2 × (1 - 0.15)`，只需判断"过没过 93"。
   这大幅降低了**算术错误**污染**推理质量**测量的风险
   （lmgame-Bench 的核心发现：不加脚手架时几乎所有模型都聚在随机水平附近，
   因为感知/算术的噪声淹没了推理信号）。
3. **阈值创造"差一点"的紧张。** 智力 92 的钟会与智力 93 的差距，
   比智力 60 和 80 的差距重要得多。**这是一个规则免费送的、可推理的局部结构。**

**本项目怎么落**：

- `OFFICER-STATS-DESIGN.md` 的五维**保留数值**（用于计算），但**所有能力开关改成阈值**：
  统率 ≥ X 才能领 N 个军团；谋略 ≥ Y 才能用某类计；政务 ≥ Z 才能主持某类工程
- 忠诚**直接照搬**：≥90 不可离间，<40 可招降，<25 高概率
  （治 `GAMEPLAY-REVIEW.md` F8"忠诚公式四个分项全是空的"）
- **离间的效果是确定性的固定降幅，不掷骰**（对照 F2 判据）
- 阈值的数量控制在**每维 2–3 个**，全部写进系统提示

**对照六约束**：C1 ✓；C2 ✓（阈值表比公式表短）；**C5 ✓✓✓**（这是本手法的主战场）；C4 ✓。
**适配度：★★★★★**
**接口**：`OFFICER-STATS-DESIGN.md` §能力映射；`GAMEPLAY-DESIGN.md` §4.3 忠诚、§5.7 计略。

### 手法 4：正交差异化 —— 把 578 名武将从"排序"变成"匹配"

**出处**：Harvey Smith，GDC 2003，"orthogonal unit differentiation"；
霸王的大陆的兵种 × 地形机动力矩阵（三行三个不同凹陷）与
**等级 × 部队构成表**（L1 步5弩4骑1 → L8 步0弩4骑6，8 级武将一个步兵都没有）。

**机制**：元件在**质**上不同，不在量上不同。判据：**能否排成一条"谁更强"的序？能，则深度为 0。**

**为什么产生深度**：把"选人"从 `argmax(score)` 变成 `argmax(match(officer, mission))`。
前者的最优解与局面无关（一次性算出来，此后照抄）；
后者的最优解**随目标变化**，无法被单一启发式吃掉——正是 Lantz 说的"防 one weird trick"。

**本项目怎么落**：

给每名武将一个**离散适性标签集**，与五维数值**正交**：

| 维度 | 取值 | 效果 |
| --- | --- | --- |
| 地形适性 | 平 / 山 / 水（可兼 2） | 行军速度、野战修正 |
| 战役角色 | 攻城 / 野战 / 守备（可兼 2） | 对应结算分支的修正 |
| 治所适性 | 边郡 / 腹地 / 都邑 | 太守任期内的产出修正 |

**关键设计约束【本文推导】**：
标签**不是加成的堆叠**，而是**修正的符号**——
不适配时**为负**，否则模型会退化成"选标签最多的人"（那又变回排序题了）。
霸王的大陆的兵种就是这样：山军在河道要 6 点机动力，是明确的惩罚。

**为什么这条对本项目特别重要**：
`officers.json` 有 578 名武将。如果他们只有五维数值，
**这 578 个数据点的深度贡献大约是 log₂(578) ≈ 9 bit**——一次排序。
加上三个正交标签维度后，"派谁去哪打"变成一个二部图匹配问题，
且匹配的最优解**每一季都随目标变化**。

**对照六约束**：C1 ✓；C2 ✓（三个标签 ≈ 6 token/人，只对在册武将展开）；
C4 ✓（标签不增加动作条目，只改变参数域的价值）；**C5 ✓✓**（错配是可归因的错误）。
**适配度：★★★★★**
**接口**：`OFFICER-STATS-DESIGN.md` 需要新增一节；`OFFICERS-AUDIT.md` 的数据补全清单加三列。

### 手法 5：周期性确定冲击 + 可投资的防护，取代随机事件

**出处**：霸王的大陆的年历——4 月收金、10 月收粮、**5–6 月必发水灾**（损钱粮）、
**8–9 月必发旱灾**（损兵，每将 150 人），防灾值 0–99 可用命令书投资；
Diplomacy 的春/秋/冬三阶段固定循环。

**机制**：把"事件"从随机抽取改成**日历上写死的周期**，只让**损失幅度**受可投资的防护值调节。

**为什么产生深度**（这是 C5 的直接手术）：

- 随机事件让强弱模型**同等地**遭殃 → 降低区分度（海德堡：170 → 45）
- 周期性确定事件让"有没有提前投保"成为**可归因的决策差异** → **提高**区分度
- 而且**零额外状态量**：日历是常数，防护值是一个整数

**本项目怎么落**：

| 时点 | 事件 | 可投资的防护 |

### 手法 6：硬时钟 + 双向消耗 —— 给每个僵局一个到期日

**出处**：霸王的大陆的**战役 30 日上限，超时判守方胜** + 出征必须自带粮 +
守方也消耗粮草 + 机动力随兵力变化（四条规则的乘积产生了"耗粮不战而胜"的涌现打法，§2.10）。

**机制**：任何"两方对峙"的状态都必须有**硬时限**和**双向的资源消耗**，
且时限到期时的判定要**偏向一方**（霸王的大陆偏守方）。

**为什么产生深度**：
- 偏向守方的超时判定 → **进攻方在和时钟赛跑**，制造 S2（时机）深度
- 双向消耗 → **"围而不打"是有代价的真实选项**，而不是免费的
- 两条叠加 → 攻方要算"我的粮能撑几旬 vs 他的粮能撑几旬"，
  这是一个**双方都能心算、且答案唯一**的问题 —— 完美的 C5 载体

**本项目怎么落**（这条直接治 `GAMEPLAY-REVIEW.md` 的致命项 C1"攻城死锁 / 地图冻结"）：

| 规则 | 取值 |
| --- | --- |
| 围城时限 | **6 旬**（约 2 个月）。超时自动解围，攻方按残粮撤回最近己方郡 |
| 攻方粮耗 | 基准 × 1.0 |
| **守方粮耗** | 基准 × **0.7**（审查 §9 第 2 条已建议，本文支持） |
| 破城门槛 | A/D ≥ **1.6**（审查建议，替代原 2.2） |
| 跨郡集兵 | 新增 `muster` 模板（审查建议） |
| 断补给 | 若围城军团与己方领土的连通路径被切断，粮耗 ×2 且不能补充 |

**最后一条是 Hive 的 One Hive Rule 的移植**（§6.1）：
**补给连通性让每一个局部动作都必须顾及全局结构。**
它零成本地同时产生：纵深防御的价值、切断补给的战术、"占了但守不住"的取舍。

**对照六约束**：C1 ✓；C2 ✓（连通性可用一个布尔位表达）；
**C5 ✓✓**（粮耗赛跑是确定性的、可心算的）；C6 ✓（僵局有到期日 → 局长可控）。
**适配度：★★★★☆**（扣一星：连通性判定需要邻接图正确，而 `GAMEPLAY-REVIEW.md` G5 说邻接图还没有）
**接口**：`GAMEPLAY-DESIGN.md` §5.5 攻城结算全节重写；依赖 G5 的邻接图数据。

### 手法 7：把对手的资产变成可操作的公共资源

**出处**：霸王的大陆的离间（忠 < 90 可降）与劝降（忠 < 40 可招）+
**这两条都要花命令书**（所以挖人和垦田在同一个预算里竞争）；
战斗中的「笼络」计（耗 10 机动力，直接拉走敌将）。

**机制**：让对手的一部分资产（武将忠诚、附庸关系、声望）**可以被你用动作直接影响**，
且影响是**确定性的固定幅度**。

**为什么产生深度**：这是 **S1（交互）× S3（机会成本）× S5（对手建模）的三重乘积**——
本文列出的所有机制里深度密度最高的一条。

- S1：你的武将不只是你的，是一个**双方都能操作的状态量**
- S3：花一枚命令书去离间 = 少一次垦田，跨维度取舍
- S5：要不要花钱赏赐提忠诚，取决于**你判断对手会不会来挖**

**本项目怎么落**：

| 规则 | 取值 |
| --- | --- |
| `scheme:离间` 门槛 | 目标忠诚 **< 90** |
| 效果 | **确定性固定降幅**（如 −12），受执行者谋略与目标"德"分档修正，**不掷骰** |
| `enlist:招降` 门槛 | 目标忠诚 **< 40** |
| `reward 赏赐` | 3 档金额，**忠诚 ≥ 90 不可赏赐**（照搬霸王的大陆，防止把忠诚刷满锁死） |
| 可见性 | 敌方武将的忠诚**分 3 档模糊显示**（安/摇/离），精确值需 `scout:细作` |

**最后一条是关键**：忠诚必须**部分可见**。
全可见 → 退化成算术；全不可见 → 退化成掷骰（S4 的"状态不可见"陷阱）。
**分档 + 可花代价精确化**，才是 S4 的"意图不可见"形式。

**对照六约束**：C1 ✓；C2 ✓（3 档 = 1 token）；C4 ✓（target 域限制在"已知的敌方太守与主帅"，
审查 §1.3 已提）；**C5 ✓✓**（确定性降幅）；C6 ✓。
**适配度：★★★★☆**（扣一星：需要与 `enlist` / `reward` 的数值一起标定）
**接口**：治 `GAMEPLAY-REVIEW.md` F8；`GAMEPLAY-DESIGN.md` §4.3 / §5.7 改写。

### 手法 8：把 `d` 的"台阶"直接写进胜负判据

**出处**：Lantz et al. 2017 的 step 定义（相对上一档胜率提升 60–75% 才算一个台阶）；
CivBench（arXiv:2604.07733，2026-04）——
在数百回合、多对手的对局里，**终局胜负是过于稀疏的信号**，
所以他们改用**逐回合的胜率估计**作为评价信号；
Jaffe 的 **restricted play**（AIIDE 2012 / PhD 2013）——用"限制某类动作后胜率掉多少"测量该维度的重要性。

**机制**：不要只在第 60 季给一个名次。
**每一季都产生一个可测的、单调的、可归因的进度量**，让 strategy ladder 的台阶**在观测中直接可见**。

**为什么这是最后一条也是最重要的一条**：
前七条手法都在提高 `d`。这一条保证**我们能看见 `d`**。
`GAMEPLAY-REVIEW.md` 的致命项 C2（"综合分把苟活定为最优解"）和 C3（"终局分级在开局就锁死"）
说的都是同一件事：**评分函数本身是一条规则，而它现在是那条创造支配策略的规则（R1）。**

**本项目怎么落**：

**（一）把综合分改成"相对开局的增量档位"**（审查 §9 第 1 条已建议，本文完全支持并给出理由）：
绝对量的评分让开局强的席位永远领先，`d` 观测不到；
增量评分让"从 1 郡打到 8 郡"和"从 13 郡打到 30 郡"是**同一个台阶**。

**（二）每季记录三个过程指标**（不进胜负判定，只进评测报告）：

| 指标 | 定义 | 测什么 |
| --- | --- | --- |
| **SP 配置熵** | 这一季 12 枚 SP 分布在几类模板上 | 是否退化成单一循环（R1 的探测器） |
| **阈值命中率** | 提交的动作里有多少条踩在了门槛的正确一侧 | 手法 3 是否在起作用；也是最干净的推理质量代理 |
| **前瞻兑现率** | 上一季声明的中间目标，这一季达成的比例 | S6（长程信用分配）的直接测量 |

**（三）用 restricted play 做验收**：
跑三组消融——(a) 禁用 `scheme` 全类、(b) 禁用谈判通道、(c) SP 固定为 6 不随规模增长。
**每一组的胜率下降幅度，就是那条维度的深度贡献。**
如果某一维禁用后胜率几乎不变，那条维度对 `d` 的贡献是 0，应该删掉（省实现成本、省 token）。

**每组要跑多少局？用 §1.4 的 Rep. 列定标【本文推导】**：

Rep. 的定义正是"要多少局才能以 >75% 把握确认强者更强"，
而消融实验问的是同一个问题（"禁用这一维之后，是否**确实**变弱了"）。
所以：

| 结算性质 | 每组消融的最小局数 | 三组消融 + 对照的总预算 |
| --- | --- | --- |
| **确定性结算**（本项目应有的状态） | **5–10 局** | **20–40 局** |
| 掺了结算随机 | 70+ 局 | 280+ 局 |

**这条把 §1.4 的论证闭环了**：确定性结算不只是"测得准"，
它让**整套验收方法本身变得负担得起**。
一个 60 季的对局若要跑 280 局才能验收一条机制，这套方法论就废了；
跑 20–40 局，它就是每次改动都能用的常规工具。

**建议**：把这三组消融固化成 CI 里的一个 `depth-ablation` 任务，
每次改动 SP 公式、阈值表或模板集之后跑一次。
**这是把"深度"从设计口号变成回归测试的唯一办法。**

**对照六约束**：C5 ✓✓✓（这条手法的全部意义）；C6 ✓（增量评分让局长与结局脱钩）。
**适配度：★★★★★**
**接口**：`GAMEPLAY-DESIGN.md` §9.3 过程指标体系扩充（审查说这一块"一个字都不要砍"，
本文建议**再加三个指标**）；`GAMEPLAY-REVIEW.md` §9 第 1 条的执行方案。
