# 界面双语化：能做到哪一步，以及哪一步不该做

文档已经有英文平行本了。这份记的是另一件事：**让跑起来的游戏界面也能说英文**，
要付什么代价，哪些地方付了代价也换不回东西。

结论先写在前面：

1. 界面里真正属于「静态文案」的只有三分之一，剩下三分之二是引擎实时拼出来的；
2. **给模型看的那一层（`prompt.ts` + `observe`）必须留在中文**，不是因为懒，是因为
   换了语言榜就不可比了，而且 key 本身就是中文；
3. 界面与模型今天读的是**同一批字符串**，不拆开这层共享，翻译界面就等于改评测；
4. 只做第一阶段（按钮和标题）比不做更糟——那会得到一个按钮是英文、战报是中文的
   半成品。要么做到第三阶段，要么就停在文档双语。

## 二、引擎实时拼出来的那一半

| 文件 | 片段（去重） | 角色 |
|---|---:|---|
| `lib/game/engine/actions.ts`（1582 行） | 331（260） | 候选 label：约 40 处 `label:` + 约 30 处拒绝原因 |
| `lib/game/engine/resolve.ts`（1546 行） | 320（241） | 事件日志：54 处 `text:` |
| `lib/game/engine/params.ts` | 439（221） | **不是文案**，是内容包的中文键路径 |
| `forecast.ts` / `victory.ts` / `officers.ts` / `bot.ts` / `order-budget.ts` / `combat.ts` / `intel.ts` / `observe.ts` | 合计约 180 | 判词、档位名、阵型名、拒绝信息 |
| `lib/game/decision-review.ts` / `strategy-plan.ts` / `replay.ts` / `content/schema.ts` | 合计约 130 | 复盘标签、计划描述、规则摘要骨架 |

**它们几乎全是碎片拼接，不是整句。** 这是整件事里最贵的一项。举例：

- `actions.ts:662–667` 一条征伐 label 由 **6 段模板串接**，中间插郡名、兵力、
  武将名、阵型名、预告文字，末尾还挂一个条件化的破城预告。
  `721–726`、`752–757`、`920–923`、`1083–1084`、`1098–1099`、`1184–1188`、
  `1227–1230`、`1296–1300` 都是同一个形状。
- `resolve.ts:943`：`` `自 ${army.home} 取 ${army.target}${loser ? `（原属 ${loser}）` : "（无主）"}` ``

语法胶水是焊死在拼接里的：`自…征…`、`于…集结`、`以朝廷之名授…为…牧`。
没有任何 message-format 层，**语序是硬编码的**。英文的语序不同，不先引入一个
带命名参数的格式化层，这 95 处拼接点改不动。

### 翻了就会改行为的地方（这一列是风险清单）

下面这些中文不是显示用的，是逻辑：

1. `lib/game/engine/observe.ts:407-408` —— 以中文做 `Record` 键：
   `a["缺口"] !== undefined && a["可防守"] !== undefined`
2. `lib/game/engine/bot.ts:160,161,184,200` —— 机器人按判词的中文字面量分支：
   `!== "可解围"`、`=== "解不了"`、`=== "破城"`。判词在 `forecast.ts:92,293,366`
   产出，类型是 `"破城" | "不破" | "未知"`
3. `app/play/PlayClient.tsx:2335,2342` —— `const RANK: Record<string, number> =
   { 破城: 0, 未知: 1, 不破: 2 }` 用来给候选排序；3319–3357 还按 `=== "不破"` 过滤
4. `lib/game/engine/officers.ts:251,254,262,270,274,338` 与 `actions.ts:1252,1253`
   —— 适性是中文数据值，参与判断：`o.aptitudes.includes("攻城")`
5. `lib/game/engine/victory.ts:301,306` —— `?? "无主"` 之后再 `=== "无主"`：
   一个既是哨兵值又是显示文字的东西
6. `lib/game/content/schema.ts:205-206` —— 两条中文正则决定什么能进提示词：
   `/说明|依据|理由|为何|意图|意义|教训|代价|出处|注$/` 与
   `/实测|自对局|首版|…/`。这是 ARCHITECTURE 里「规则摘要不含开发者旁白」那条闸
   的实现，换语言它就失效
7. `app/play/PlayClient.tsx` 的 `cnText`（复核时在 766–767 行）—— **全仓库最脆的一行**：
   `text.replace(/[a-z]+/g, (m) => engineRef.current?.nameOf.get(m) ?? m)`
   引擎日志里嵌的是裸的拉丁势力 id，界面靠「把每一段小写 ASCII 都拿去查表」换成
   中文名。引擎文字一旦出现英文单词，**每个英文单词都会变成查表候选**
8. `lib/game/replay.ts:294,313` —— `[["ally","起结盟"],…]` 拼成
   `本季天下另有 N 起结盟、M 处集结`，中文量词是数据
9. `tests/backup-orders.test.mjs:48` 断言 `/备选补位/`；
   `tests/comparison-budget.test.mjs:14-27` 断言 `/触顶/ /输入/ /价格/ /重复/`。
   **测试在断言中文子串**，翻译会让它们红，而红的原因与对错无关

另外两条与本地化直接冲突的既有决定，不要碰：
`lib/game/engine/cmp.ts:14` 明确拒用 `Intl.Collator`（排序会绑到宿主 ICU 版本，
而排序结果进提示词）；`resolve.ts:289` 把 `toLocaleString("en-US")` 钉死。
**引擎路径上的排序与数字格式不许引入 locale 依赖。**

## 三、给模型看的那一层必须留在中文

这一条我想清楚了，结论是**不要翻**，理由不是一条而是五条叠在一起。

`lib/arena/seat/prompt.ts` 158 行，262 个中文片段（247 去重）、101 条字面量，
是全仓库中文字面量最密的文件。`renderSystem(pack)` 就是把约 100 条中文串
`join("\n")`，十五节 Markdown（`## 怎么下令`、`## 补给`、`## 粮：围城两头各有一只钟`、
`## 三阵各有所长`、`## 名器`、`## 势孤时怎么打`、`## 怎么算赢`、`## 跨季方略`、
`## 输出`、`## 规则细则`），实质是一本约四千字的兵法手册；最后一个元素是
`toRulesDigest(pack as never)`（`:151`）。`renderUser(o)` 只是
`JSON.stringify(o)`——但 Observation 的**值**是中文。

1. **候选 key 里就带着中文郡名。** `actions.ts:645` 生成
   `` key: `campaign:${e.from}>${tid}:${strength}` ``，实际形如
   `campaign:济阴郡>陈留郡:main`，模型要原样回抄。
   `strategy-plan.ts:66` 更直接：`s.commanderies[plan.target]`——模型写的自由文本
   被当成键去查。而 `commanderies.json:3` 的 `"id": "河南尹"` 本来就是中文，
   `types.ts:315` 是 `Record<CommanderyId, CommanderyState>`。
   **换提示词语言不等于换 key；key 换不了，因为它是数据主键。**
   于是「英文提示词 + 中文 key」是一种更坏的组合：模型在英文语境里被要求
   逐字复现中文标识符。顺带说，`admit.ts:35-41` 的 `repairMojibake()` 就是为此
   存在的——某提供方在一次 48 局跑里产出 2806 个乱码 key，把非法率抬到 50.9%。
2. **换了就不可比。** `build:board` 已经拒绝混合不同规则指纹的对局方
   （`app/board/page.tsx:45-50` 按 `board.packVersion` 把关）。提示词语言的影响
   不比规则数值小：它同时改变 token 数、推理路径、以及「模型在哪种语言里更强」
   这个与战略能力正交的维度。一份混了两种语言的榜，量的是别的东西。
3. **观测预算是按中文标的。** `npm run obs:budget` 是逐席位的硬闸，EVAL 里记着
   mine 段随疆域线性长（95 tok/郡）、方略中位 173 tok，而 27/341 席·季曾经超顶。
   同样内容的英文通常更费 token。**翻译会直接撞这道闸**，而撞闸的后果是观测被裁，
   也就是第 9 条说的「模型在按错的规则思考」。
4. **前缀缓存按字节稳定。** `prompt.ts` 的注释写明它是刻意字节稳定的，约 3.8k
   token 每季重发。两种语言就是两条前缀，冷缓存成本翻倍；而 EVAL 第 7 条实测过
   提供方漂移时命中率掉到 2%。
5. **散文已经被明确拒绝过。** `prompt.ts:155` 的注释：「散文会引入措辞变量，
   评测不可比」。这正是同一个判断在同一层的另一次应用。

**那什么时候可以有英文提示词？** 只有一种情形：把它当成一条**显式记录的轴**，
和 `--reasoning` 同等对待——写进 run 的元数据、参与指纹、榜上单独成列，
且**跨语言的局永远不并进同一份榜**。那时它回答的问题也换了：不是「谁更会下棋」，
是「同一个模型在中文和英文里差多少」。那是个好问题，但它是另一个实验。

## 四、界面与模型今天读的是同一批字符串

这是整份计划里最要紧的结构事实。已核对的调用点：

| 共享函数 | 定义在 | 模型路径 | 界面路径 |
|---|---|---|---|
| `listActions()` | `engine/actions.ts` | `observe.ts:270`、`model-seat.ts:142` | `PlayClient.tsx:919` |
| `briefFor()` | `engine/victory.ts:247` | `observe.ts:370` → `Observation.brief` | `PlayClient.tsx:2200` |
| `forecastSiege()` / `forecastCampaign()` | `engine/forecast.ts` | `observe.ts:235` | 经 `listActions` 的候选 |
| `visibleLog()` | `engine/intel.ts` | `observe.ts:271` | `PlayClient.tsx`（:18 导入） |
| `GRADE_CN` | `victory.ts:190` | `observe.ts:350` | `PlayClient.tsx:38` |
| `FORMATION_CN` | `combat.ts:128` | `observe.ts:294` | `PlayClient.tsx:20` |
| `BUILD_CN` | `actions.ts:58` | `observe.ts:298` | 被复制成 `BUILD_CN2`（:444） |
| `POLICY_CN` | `actions.ts:347` | 经 label | `PlayClient.tsx:15` |
| `admit()` | `arena/seat/admit.ts` | `model-seat.ts` | `PlayClient.tsx:21` |
| `unitName()` | `combat.ts` | `observe.ts:238,292` | 经 label |

**今天不存在「界面字符串」与「模型字符串」之分。** 所以：翻译界面候选表，就是在
翻译模型提示词。要么接受这一点（不可接受，见上一节），要么先把 locale 作为显式
参数穿过 `listActions` / `briefFor` / `forecast` / `visibleLog`，并且**给模型路径
钉一条闸**：观测与提示词只接受 `zh`，传别的直接抛。

这条闸按四方对账那套写法加进 `tests/engine.test.mjs` 即可，它拦的是
「有人顺手把界面语言透传给了模型」——那种改动不会报错，只会让下一份榜悄悄变成
另一种东西。

## 五、还有一笔经常被漏掉的账：专名

界面真要说英文，105 个郡、31 家势力、808 名武将、61 个据点的**显示名**都得有
英文或拼音——约 **1000 条新字符串**。这不是翻译，是一次考订：同名异写、郡名与
治所名的对应、历史习惯译法（Guandu / Kuan-tu）得统一。而且 id 必须仍是中文
（见第三节第 1 条），所以这是一张**额外的 id → 显示名映射表**，数据层只增不改。

不做这张表，英文界面上满屏仍是「济阴郡」「陈留郡」，那不叫英文界面。
做这张表，它本身就是一个独立的小项目，而且需要有人判断，不能机器直出。

路由与开关：`app/layout.tsx:26` 的 `lang="zh-CN"` 是写死的，`next.config.ts` 没有
`i18n` 段，没有 locale 路由、没有中间件。对局页是客户端单页，用一个 context +
`localStorage` 就够；但落地页 `/` 和榜单 `/board` 想被英文搜索到，得有真路由
（`/en/...`）。建议只给这两页做真路由，其余跟 context 走。

## 七、我的建议

**做 0 + 1 + 2，先停在那儿，把 3 和 4 当成一次单独立项的决定。**

理由是第一节末尾那句：只做 1 得到的是按钮英文、候选表与战报中文的半成品——
而候选表与战报占着对局页三分之二的屏幕。那个状态比纯中文更难用，因为读者会
以为自己能读懂。阶段 2 做完至少「说明文档 + 落地页 + 榜单」整套是通的，
这对一个开源项目是完整的价值；对局页维持中文，并在界面上**说清楚它是中文的**。

阶段 3 真要做，先决条件有两条，缺一条就别开工：
一是阶段 0 的那条闸已经在跑，二是金样回放已经能证明 `zh` 输出逐字节未变。
没有这两条，这次改动会以「榜还能跑、数字还出得来、只是模型看的东西变了」的方式
出错——EVAL 第 9 条列的十五种缺陷，全是这个形状。

过程中撞出三处**真的不一致**，都不是英文化引入的，是本来就在的：

1. 内容包里 `campaign.siegeGear` 的 `none` 标作「无」，而 `GEAR_CN` 是「无械」。
   规则摘要取包里的 label，候选标签取 `GEAR_CN`——**模型读到的名字和它挑的候选
   对不上**。改包为「无械」（纯文字，指纹不动），`PROMPT_VERSION` 升 1.24.0。
2. 据点名三套：引擎「谷道/港/仓」、地图页「道/港口/仓城」、对局页「谷道/港口/粮仓」。
   两份界面副本删掉，一律从 `KIND_CN` 来。
3. 动作名两套：`panels.ts` 的 `TYPE_CN` 与 `SessionPanel` 自己写的一份，
   `relief` 一个作「赴援」一个作「解围」。一比四，后者是孤例。

第 1 条尤其值得记：它不是「翻译时会出错」，是**今天就在错**，而四方对账里
恰好没人去对「包里的 label」与「引擎的表」。英文化只是把它照了出来。

### 阶段 1 · 静态文案：进行中

已迁（棘轮名单见 `tests/i18n.test.mjs`）：

- `/` 落地页 + 对局实验室 + `/en` 真路由
- `/board` 排行榜 + `/en/board`
- 规则速览（阶段 2 的一部分，提前做了——它是对局页里最独立的一块）
- SessionPanel、MatchSetup、StrategyPlanView、DecisionReviewView、SeasonReviewView

机制上与上面第六节的设想有两处不同：

- **`<html lang>` 用的是路由组，不是 context。** 单根布局下 `/` 与 `/en` 共用
  一个 `<html>`，客户端改 `document.lang` 是改在首屏之后，读屏软件与爬虫拿到的
  仍是 `zh-CN`。改成 `app/(zh)` 与 `app/(en)` 各带一个根布局，代价是所有路由
  都得进组。vinext 是 beta，这条实抓验过。
- **强调用 `**` 标记，不是 `{b}` 洞。** 一段话里强调两处以上时，洞的办法逼着
  两种语言共用一个结构，而中英的强调位置和数量本来就不同。解析与渲染拆成
  `marks.ts` / `rich.tsx` 两个文件，因为 `node --test --experimental-strip-types`
  不认 .tsx，不拆就测不了。

### 一处要改的判断：`PlayClient` 不是阶段 1 的文件

第六节把 `PlayClient` 的「按钮/表头/状态条」放在阶段 1、图例放在阶段 2。实际数下来
它有 **250 个可翻译单位**，其中：

- 约 180 条是短文案（按钮、表头、档位提示），确实是阶段 1；
- 约 70 条是**语序拼接**——`` `自${a.from} 征 ${a.target}` ``、
  `` `${a.at} 改${FORMATION_CN[a.to]}阵` `` 这一类。它们与 `actions.ts` 里那
  95 处是同一类东西，只是写在了界面侧。

也就是说这一页跨在阶段 1 与阶段 3 之间。先迁那 180 条、把拼接那 70 条留到阶段 3
是可以的，但**不能在迁完 180 条就给它接上语言开关**——那正是第七节警告的半成品。
所以 `PlayClient` 现在 `makeT("zh")` 钉死中文，`/en/play` 不存在。

### 口径说明：1100 条还是 632 条

上面第一节数的是「中文连续串」（按中文标点切），`app/` 约 1100 条；这一节数的是
「可翻译单位」（一个字符串字面量或一个 JSX 文本节点），`app/` 共 **632 条**。
两个数不矛盾，一个单位平均约 1.7 个串。迁移按单位算工作量更准，因为一个单位
就是目录里的一条 key。
