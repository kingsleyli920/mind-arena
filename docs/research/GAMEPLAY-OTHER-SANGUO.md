## 零、这份文档怎么读

### 0.1 三类来源必须分开

调研中反复出现的一个陷阱：把游戏的原创设定当成史实，或者把演义当成史书。本文对每一条机制标注来源类别。

| 标记 | 含义 | 例子 |
| --- | --- | --- |
| **史实** | 有正史或同时代文献依据 | 《续汉书·郡国志》105 郡国；东汉黄河走东汉故道 |
| **演义** | 出自《三国演义》及后世通俗叙事 | "五虎大将"之称；阵前单挑决定战役胜负 |
| **游戏原创** | 某款游戏为了可玩性发明的设定 | 三国杀的"内奸"身份；率土之滨的"土地 1–10 级"；把洛阳设为赛季终局目标 |

最容易搞混的两条，先说清楚：

- **"五虎将"是演义**。《三国志》卷三十六是关羽、张飞、马超、黄忠、赵云的合传，陈寿没有"五虎大将"这个称号，那是《三国演义》的说法。**《全面战争：三国》里也没有"五虎将系统"**——"Party of Five"（麾下集齐五人）是一个 Steam 成就，不是一套机制。任务书里提到的"五虎将/性格系统"，在该作里对应的实际是**五种人物职业（对应五行）+ 特质/关系网**，下文 §2 详述。
- **阵前单挑决定战役归属，是演义**。史书里主将阵前搏斗的记载极少（《英雄记》载吕布与郭汜阵前相斗算是罕例），绝非战争常态。凡是把单挑做成战役主判据的游戏，都属游戏原创的戏剧化处理。

### 0.2 两类可借鉴物必须分开

- **可借鉴：机制思路**。"只能进攻与自己领地相邻的地块"是一条规则思想，任何人都可以用。
- **不可复制：具体数值表与美术表达**。《率土之滨》9 级地守军 60000 兵、《新三国志曹操传》克制加伤 30% / 被克减伤 25%、光荣的武将数值表、任何一家的地图与立绘——这些是具体表达，不抄。本文引用它们只为说明"这个机制大致跑在什么量级上"，落地时全部原创。

### 0.3 评分标尺：六条硬约束

Mind Arena 不是给人玩的三国游戏，是模型竞技场。任何机制都要过这六关：

| 编号 | 约束 |
| --- | --- |
| **C1** | 决策是高层战略，不是微操 |
| **C2** | 状态可序列化，且能分层摘要、按相关性裁剪后塞进上下文 |
| **C3** | 决策频率与模型调用成本解耦，不能每个时间单位都强制全量调用 |
| **C4** | 合法动作集可枚举，模型从中选择而非自由生成 |
| **C5** | 能分出高下：更强的推理稳定转化为更好的结果，不被随机性淹没 |
| **C6** | 局长可控，一局不能几百回合 |

**适配度定义**：

- **高** —— 满足其中 4 条以上且不与任何一条冲突，改造成本小，可以直接进第一版。
- **中** —— 方向正确，但必须显著改造（裁剪状态规模 / 降低决策频率 / 限制实体数量）才能满足约束。
- **低** —— 与至少一条硬约束正面冲突，或者它的价值主要在"给人玩的手感、养成、收集"上，对模型无意义。

## 一、《三国群英传》系列（宇峻奥汀 / 奥汀科技，1998–2021，共 8 代单机）

### 1.1 它解决了什么问题

同期光荣《三国志》系列的内政越做越细，一座城要管农业、商业、治安、技术、巡查、征兵、训练……城池一多，玩家后期就是在做重复的表格填空。群英传走了反方向：**把内政压成一年一次的批处理，把绝大部分游玩时间还给战斗**。它是华语区最成功的"轻内政 / 重战场"三国战略游戏。

### 1.2 用了什么机制

**（1）内政的年度批处理**

第一代到第三代，内政**每年一月执行一次**（第五代起改为"季内政"，即一季一次）。一个内政窗口里能做的事就那么几项：城市开发（人口 / 防御）、搜索武将、搜索宝物（武器、兵符、阵型）、征兵、升迁、招降俘将、给武将配装备。开发效率由武将智力决定。

关键在于：**内政不是每回合都要处理的事，而是一年打开一次的批量决策面板**。其余月份，玩家只做行军与作战。

**（2）战争模式是"武将逐个淘汰"，不是兵力比大小**

部队接触或攻城即进入战争模式，**以淘汰形式进行：某一方武将全部败北即判负**。判据是武将能力、武将技、部队质量、兵种相克。也就是说，一场会战被拆成若干轮"以武将为单位"的对抗，而不是一次总兵力的加权比较。

**（3）双层石头剪刀布：兵种相克 + 阵型相克**

- 兵种按"长兵 / 短兵 / 远程"三系循环相克。
  **注意：查到的两处中文资料对循环方向说法相反**（一处说"远克长→长克短→短克远"，一处说"长克短→短克远程→远程克长"）。方向我无法确认，但**"三系单循环"这个结构是确定的**，而方向对本项目也不重要。
- 阵型另有一套三系循环："平形克凹形→凹形克尖形→尖形克平形"。
- 两套克制叠加，构成一个 3×3 的选择空间。

**（4）武将技随成长解锁，单挑可"掠夺"技能**

武将打胜仗积累经验升职，每升一职获得一项更强的必杀技，最多升 3 次、持有 4 项。在战场上单挑一名带必杀技的武将并取胜，可以学到对方的一项必杀技。

**（5）系列演进（用于定位"哪一代的什么系统"）**

- 一代（1998）：回合制，内政 / 战略 / 战争三大模式。
- 四代（2003）：系列首次转为即时战略。
- 五代：引入"季内政"简化管理。
- 六代：新增"冲阵"。
- 七代：引入"斗智单挑"。
- 八代（2021，Steam）：战场与大地图全面 3D。

### 1.3 对 LLM 对战的迁移价值

**高价值：内政的年度批处理，直接命中 C3。**

这是本次调研里对本项目最立竿见影的一条。现有 `lib/game/strategy.ts` 是"每势力每季一道命令"，把军事和内政挤在同一个决策槽里，既让内政沦为一次 `develop` 调用，又让模型每季都必须被调用一次。群英传的结构给出了更好的切分：

- **年度国策窗口**（每年一次调用）：模型决定这一年的资源分配路线——扩军 / 农桑 / 通商 / 安民 / 求贤，以及要不要开启某项长期工程。产出是一组会持续生效一年的参数。
- **旬/月级军事窗口**（按需调用）：只有当局势发生"值得打扰模型"的变化时才调用（敌军进入视野、盟约被提出、围城结果出炉、粮道被断）。其余时间由本地执行层按既定方略推进。

这样一局 194→200 年（约 6 年、216 旬）里，内政调用只有 6 次，军事调用由事件驱动，总调用量可控。

**高价值：低维循环克制，命中 C4 与 C5。**

三系循环是**最小的非平凡博弈结构**。它对模型竞技场有三重好处：

1. 合法动作集极小且完全可枚举（选兵种 3 选 1、选阵型 3 选 1）。
2. 它是**可测的元博弈能力**：模型能不能从对手的历史选择里推断偏好，再做反制？这是一个干净的、可统计的指标，而且不需要额外的评测装置——胜率本身就是指标。
3. 它天然抗"堆数值"：没有任何一种兵种是绝对最优的，纯靠资源领先无法碾压，符合 C5"更强推理→更好结果"。

建议不要照抄"长/短/远"这套命名，用本项目已有的地形与史实兵种：**弩阵 / 长戟 / 突骑**三系，配合本项目已有的 `terrain-grid.json`，让地形修正循环关系（山地削骑、水泽削弩），这样克制关系就不是纯抽象的 RPS，而是和地图耦合的——考验的就从"猜拳"升级成"读地图"。

**中价值：会战按武将逐轮淘汰。**

比现有"一行公式比大小"好得多，理由是**日志可读**。回放层（replay）需要给人看"这一仗发生了什么"，一次公式比较写不出任何东西，而"第一轮：夏侯惇率突骑冲阵，遭高顺陷阵营正面挡下，折兵三千"是可以写的。同时，"派谁上、按什么顺序上"是一个天然可枚举的决策（从我方在场将领的排列里选）。

改造要点：**必须防止"单将无双"**。群英传里一名超强武将可以清场，这在模型竞技场里是灾难——它把胜负押给了初始武将分配而不是决策质量，违反 C5。做法是给每轮淘汰加上"兵力/士气/地形"的权重，武将属性只作为修正项而不是决定项。

**低价值 / 建议拒绝：**

- 实时战场、气力槽、手动放必杀技（四代起）：违反 C1，模型不该逐帧操作。
- 单挑胜者习得对方必杀技：强滚雪球（赢的越赢），且是养成收集向，违反 C5。

## 二、《全面战争：三国》（Creative Assembly / SEGA，2019）

### 2.1 它解决了什么问题

大战略游戏里，"人"通常只是挂在城池上的数值容器：属性、技能、忠诚度一个数。TW3K 的核心野心是**让人物成为有独立利益的行为体**，从而让每一局自己长出人物故事；同时把外交从"点按钮送礼"升级成一套可以谈判、可以背叛、且背叛有代价的系统。

### 2.2 用了什么机制

**（1）Guanxi（关系网）——玩家不能直接操纵**

Guanxi 是追踪游戏内所有人物之间关系的系统：友谊、结义、竞争、仇恨都在其中，间谍网络也挂在这套系统上。**设计上的关键决定是：玩家无法直接修改两个角色之间的关系，关系只能"有机地"发生变化**——因为特质相合/相斥、因为事件触发、因为两人的历史交集。

关系有战场与战役两层后果：人物不喜欢和朋友作战、乐于和仇敌作战；同军同势力有朋友会加分，反之减分。

**（2）Satisfaction（满意度）——人物会带着部曲走人**

每个人物有一个 Satisfaction，表示他对自己在当前势力中处境的感受。影响因素包括：势力内的人际关系、职位是否称心、嫉妒、家族事务。可以用宝物、爵位（带更高俸禄）、实权职位（太守、丞相、乃至继承人）去提升。

**满意度过低且关系恶劣的人物会自动离开势力去别处求职，并把自己的部曲一起带走**。这一条让"人事分配"变成一个真实的资源分配问题，而不是摆设。

**（3）间谍：把人送进对方的招募池**

玩家可以把间谍投放进敌对势力的可招募人才池。对方一旦录用并委以高位（太守、将军、甚至继承人），间谍就能破坏、送情报、煽动内战。反过来也成立：间谍可能真的喜欢上新东家而叛变，或者被反向送回来当双面间谍。

**（4）五种人物职业 = 五行**

五维属性是 Authority（威望）、Cunning（计谋）、Expertise（专精）、Resolve（意志）、Instinct（直觉），配色对应五行（土/黄、金/紫、水/蓝、木/绿、火/红）。五种职业：

| 职业 | 五行 | 定位 |
| --- | --- | --- |
| Vanguard 先锋 | 火 | 割草型，擅长撕开步兵阵，技能压士气 |
| Sentinel 卫士 | 金 | 防守型，缠住敌将、守住防线 |
| Strategist 军师 | 水 | 战场最弱，但麾下部队可用独有阵型 |
| Commander 统帅 | 土 | 天生领袖，战场内外都有加成 |
| Champion 勇士 | 木 | 专精单挑 |

职业之间按五行相生相克，火克金、水克火之类。

**（5）外交：条款打包 + 逐项估值 + 全局可见的背信**

- 提案是**多条款打包**的：可以把领土、金钱、军事通行、附庸条件放进同一个提案，对方给出对整包的净估值。
- **同盟（Alliance）是有约束的**：军事互助是义务。**联盟（Coalition）是无约束的**：没有共同防御义务，成员之间可以各打各的私仗，主要收益是彼此外交好感上升，以及以共识方式做集体决策。两档承诺强度并存。
- **背信是全局公共信息**。毁掉盟誓、吞并你曾承诺不吞并的附庸、赖掉限期借款、攻击联盟伙伴，都会被记为背信；**惩罚不只来自被你背叛的那一方，而是所有势力都视你为背信者**，带来大幅外交评价惩罚。
- 人物关系会渗进外交：势力领袖之间的私人关系是谈判的决定性因素之一，不只是钱。

**（6）史实模式（Records）vs 演义模式（Romance）**

同一份战役数据、同一张地图，两套战斗层规则：

- **演义模式**：武将是半神级英雄单位，可以互相单挑，有区域性技能（例如许褚的 Earth Shattering Strike）。
- **史实模式**：武将带着亲兵队上场，本质就是一支比较能打的普通部队；**没有技能、没有单挑特写、不能一个人冲进上百把刀里全身而退**。单位体力消耗也快得多，英雄式的长途冲锋不成立，胜负回到"战术规划 + 对机制的理解"。

### 2.3 对 LLM 对战的迁移价值

**最高价值：结构化多条款外交提案 + 逐项估值反馈。命中 C4、C5，且是本项目目前完全空白的一整块。**

现有实现里根本没有外交。而外交恰恰是 LLM 竞技场最该有的能力测试项——它同时考验谈判、信息推断和长期信誉。TW3K 的形态几乎是为 LLM 量身定做的：

```ts
// 建议形态：提案 = 有限条款集合的组合，因此可枚举、可校验
type Clause =
  | { kind: "ceasefire"; turns: number }                 // 停战 N 旬
  | { kind: "cede"; commanderyId: string }               // 割让郡国
  | { kind: "tribute"; grain: number; gold: number }     // 岁币
  | { kind: "passage"; through: string[] }               // 借道
  | { kind: "jointWar"; against: FactionId }             // 共讨某方
  | { kind: "nonAggression"; turns: number }             // 互不侵犯
  | { kind: "recognize"; title: string };                // 承认名号

interface Proposal { from: FactionId; to: FactionId; clauses: Clause[] }
// 引擎返回逐项估值，而不是一个黑箱的 yes/no
interface Appraisal { perClause: { clause: Clause; value: number }[]; net: number; verdict: "accept" | "reject" | "counter" }
```

条款种类有限 → 动作集可枚举（C4）。逐项估值返回给模型 → 模型可以学着做"最小让步"的反提案，这是一个能稳定区分强弱推理的任务（C5）。而且外交状态极小，几十个字节就能描述一条盟约（C2）。

**最高价值：背信的全局可见性。**

这是让"背叛"这件事在博弈论上真正成立的最小机制。如果背叛只被受害者记住，那么背叛在多方局里几乎总是正收益（打完就换目标）。TW3K 的做法——**背信标记对所有势力生效**——把一次性收益变成长期成本，逼模型做真正的跨回合权衡。

落地建议：势力状态里加一个公开字段。

```ts
interface FactionState {
  // ...
  trust: number;                    // 0–100，公开可见
  treacheries: { turn: number; victim: FactionId; kind: string }[];  // 公开日志，进所有人的 observe
}
```

注意：现有 `FactionState` 里已经有一个 `trust` 字段，但没有任何机制去改动它。这条正好把它填实。

**高价值：史实模式 / 演义模式的双轨结构——但本项目要重新定义它的含义。**

TW3K 的双轨是"武将要不要超人化"。本项目照抄这个语义没有意义（`THREE_KINGDOMS_RESEARCH.md` 已经定了"不做一人击溃万人"）。**真正值得抄的是它的架构：同一份战役状态，两套 resolve 规则，玩家开局选择。**

对本项目应重新定义为**随机性与信息量的两档**：

| 档位 | 用途 | resolve 差异 |
| --- | --- | --- |
| **史实档（Records）** | 模型能力排名 | 低方差：战斗结算的随机项收窄甚至归零；无奇遇事件；情报精度固定；固定种子完全可复现 |
| **演义档（Romance）** | 展示与观赏 | 高方差：保留戏剧性事件（火攻、离间、天灾、名将奇袭）、单挑特写、更大的随机区间 |

这正好落在 observe/decide/validate/resolve/replay 协议的分界线上：**只换 resolve，observe / decide / validate 完全不变**。排行榜只认史实档成绩，演义档用来做对外展示的精彩对局。这是一条架构上很干净、且直接服务于 C5 的设计。

**中价值：Satisfaction 与人物出走。**

值得抄的是**"人物有自己的效用函数，会因为你的分配决策而离开"**——它给模型制造了一个真实的内部委托-代理问题：把最强的将放在最重要的城，可能引发另一位老臣的嫉妒；给谁封侯是零和的。这是很好的长期规划与权衡考题。

但必须大幅裁剪才能满足 C2。TW3K 一局有上百个有名人物，全量关系网塞不进上下文。建议：

- 每势力 **5–8 名有名将领**（对比现状：全游戏 18 人，一势力 1 人——现状太少，TW3K 那样太多）。
- 每人**一个 satisfaction 标量**（0–100），不做多因子分解，只在观测里给出"下降原因"的一行文字。
- 每人**至多 2 条显式关系边**（结义 / 宿怨），用史实与演义中最有名的那些（关张、刘关张、吕布与丁原/董卓、袁绍与袁术），其余不建模。

**中价值：Guanxi"不可直接操纵"这条设计原则。**

这条原则本身比关系网的具体实现更值钱。它意味着**模型不能用一个动作直接买通关系，只能通过一系列安排间接施加影响**。这天然拉长了因果链，是测长期规划的好抓手。落地时保持这个原则：没有 `improveRelation(a, b)` 这种动作，只有"把甲乙编入同一军"、"让甲给乙让功"这类间接手段。

**低价值：**

- 五行职业相克附着在人物身上：与本项目已定的五维属性（统率/武力/智力/政治/魅力，见 `RESEARCH-2026-08-31.md` §四）功能重叠，再叠一层五行只是增加状态体积。相克关系应该做在**兵种**上（见 §1），不做在人身上。
- 间谍潜入敌方招募池：需要维持几十回合的隐性状态且结果高度随机，既撑大状态（C2）又稀释因果（C5）。**情报机制要做，但走"侦察精度分档"路线（见 §6），不走"长线潜伏"路线。**

## 三、《率土之滨》（网易，2015）与《三国志·战略版》（灵犀互娱，2019）

两作同属一个玩法谱系（沙盘格子 + 同盟 + 赛季），一起分析，差异处单独标注。

### 3.1 它们解决了什么问题

问题是：**如何让上万名互不认识的玩家在同一张连续地图上，自发产生真实的地缘政治**——前线、缓冲区、合纵连横、背盟。传统 SLG 靠"随机匹配打一架"，产生不了政治。这两作的答案是用**地图规则**逼出政治。

### 3.2 用了什么机制

**（1）连地出征：只能打与自己领地相邻的地块**

这是整个体系的地基。出征目的地必须与已占领领地接壤，每名玩家有占地上限。后果是：

- 扩张必然是**连续的**，因此存在真实的"前线"与"后方"。
- 想打远处的目标，必须先**铺路**——一格一格把领地伸过去。铺路要花令牌、体力和时间，是一笔**可见且代价明确的战略投资**，而且铺出去的路自己也守不住，会成为对方的攻击面。
- 盟友之间的"铺路搭桥"成了刚需，同盟因此有了具体的合作内容，而不只是聊天群。

**（2）土地 1–10 级：单调的难度阶梯**

地块分等级，等级同时决定产出与守军强度（例：5 级地一队守军，6–9 级地各两队且兵力逐级抬升）。城内 2–4 级地可以用"开发令"永久升三级，升级后要再打赢新等级的守军才算开发完成。资源需要派人采集，等级越高每小时产出越多。

等级既是难度阶梯，也是**性价比信号**——玩家一眼能看出"这块地值不值得打"。

**（3）同盟是一等实体，国战按阶段推进**

同盟有人数上限（率土常规赛季上限 380 人）、有等级、有资源加成，打下城池会提升同盟人数上限与产量加成。战争按门槛分阶段：

> 占领州内 3 级城池 → 打下州境关卡 → 进军资源州的四战之地 → 入主洛阳

《三国志·战略版》把这一套写得更明确："发展初期 → 同盟攻城 → 同盟战斗"，城池与关卡分 3–10 级，同盟须先占关卡再合力攻城。

**（4）攻坚有时间窗：城池耐久会恢复**

城池耐久若 60 分钟内未打到 0 则立即回满，此后每小时恢复 2%。规模上：一座 45000 耐久的城需要约 56 名玩家参战；洛阳城防 20 万，需要约 250 人协同。**这条规则的作用是强制"集中兵力于一个时间窗"**，零敲碎打无效。

**（5）多前置条件的战略建筑：分城（战略版）**

建一座分城需要同时满足：名声 6000、11 块连地且呈 H 形、中心格是 6 级以上土地、木铁石粮各 10 万、建造 5 小时。这是一个**多条件与门**——每一项都要提前几天甚至几周规划。

**（6）赛季制与分级终局判据**

- 一个赛季约 2–3 个月（战略版官方节奏约 3 个月）；S1/S2/S3 逐步开放玩法，之后进入征服/PK 赛季。
- **结算按同盟占领的州府数**。战略版的档位很清楚：占 1 个州府 = 三等奖；占州府 + 洛阳 = 二等奖；占 3 个州府 + 洛阳 = 一等奖。率土的规则是：**不占洛阳，最多只按 3 州府计算奖励**。
- 赛季结束后，武将卡、战法、装备等养成资产保留跨赛季继承，其余（土地、建筑、战法等级、资源）全部重置。

**（7）玩家时间是核心稀缺资源**

体力不能付费购买；行军距离越远耗时越长且**不能加速**；资源只能靠活跃度获得。设计意图是防止无脑扩张、防止付费直接换胜负。

### 3.3 为什么这类设计**整体上**不适合本项目

必须说得很明确，因为这两作的名气最容易诱使人照抄：

**（a）真实时间等待的前提在本项目不成立。** 体力、行军耗时、耐久恢复、5 小时建造——这一整套的底层假设是"真人的时间是稀缺的、不可购买的"。LLM 没有时间成本，只有 token 成本。把这套照搬进来，对局会退化成挂机：模型不需要为等待付出任何代价，等待规则就只剩下拖长局长（违反 C6）而没有任何博弈内容。

**（b）跨赛季养成继承直接摧毁可比性。** 武将卡、战法、装备跨赛季保留，意味着账号积累会压过单局决策质量。这与 C5 正面冲突：竞技场必须让"更强的推理"而不是"更厚的家底"决定结果。**所有跨局继承的养成资产，一律不做。**

**（c）抽卡与卡牌化部队会把战略问题变成配队问题。** 率土/战略版的战斗本质是 3v3 回合制配队 + 战法搭配，战略层的胜负很大程度由"你有没有那张卡"决定。这既引入了与推理无关的方差，也让状态描述被卡牌属性撑爆（C2）。

**（d）同盟规模（几十到几百人）的社会性协作，在 6–8 个模型席位的局里没有对应物。** 铺路搭桥之所以产生"羁绊"，是因为参与者是几百个有独立意志的人。8 个席位的局里，同盟只需要一条简单的盟约状态就够了。

### 3.4 但这些是真值得借鉴的

**最高价值：连地出征约束。一石二鸟，同时解决 C4 与 C2。**

这是整份调研里性价比最高的一条机制。

- **对 C4（动作可枚举）**：进攻目标从"全图 105 个郡国"收敛为"与我方领土相邻的郡国"。中期一个势力的边界郡国通常是 3–8 个，动作集从 O(全图) 掉到 O(边界)。
- **对 C2（上下文裁剪）**：既然只能打邻接目标，observe 层就有了天然的裁剪依据——**远处的详细信息本来就不影响本回合的合法动作**，可以只给摘要。
- **对玩法**：它自动制造前线、缓冲区、走廊争夺。本项目已有 `strategic-nodes.json`（61 个关隘 / 渡口 / 港口 / 仓城）和 `terrain-grid.json`，连地约束叠加关隘，立刻就得到"要进关中必先过潼关/武关"这种真实的地缘约束——而这是**史实**，不是游戏原创。

现有 `strategy.ts` 的 `march` 动作已经用 `neighbors` 做了邻接限制，方向是对的；缺的是把这条约束提升为**观测裁剪的依据**，而不只是合法性检查。

**最高价值：分级的终局判据 + 由地图门槛内生的阶段推进。命中 C6。**

现状 `maxTurns: 20` 是一个外挂的、与玩法无关的截断。率土/战略版的做法好得多：**终局判据写成一句可判、可排序、且不需要灭国的话**。

对本项目的建议形态（注意：**洛阳在 194 年已被董卓焚毁**，把洛阳当终局目标是率土的游戏原创设定，本项目不能照抄）：

```
战役在下列任一条件达成时结束，按达成的档位排名：
  一等：控制 ≥ 3 个州的过半郡国，且据有关中或河北其一的州治
  二等：控制 ≥ 2 个州的过半郡国
  三等：控制 ≥ 1 个州的过半郡国
  或：推进到第 N 年年末仍无人达成 → 按当时的郡国数 / 户口数排名
```

好处有三：局长由"是否有人跨过阈值"决定而不是硬截断（C6）；档位给了所有席位一个**公开的、共享的目标函数**，模型知道自己在往哪打；而且没达成一等的局也能排名，不会出现平局。

**阶段推进则应该由地图门槛内生**，而不是脚本切换：早期能打的只有周边低等级郡国 → 要跨州必须先拿下关隘 → 攻州治需要的兵力远超郡国。阶段是门槛造成的自然结果，不需要额外的"第 N 回合进入第二阶段"这种规则。

**中价值：郡国分级。**

率土的 1–10 级地是纯游戏原创的数值分层，但**分层这件事本身**对模型很有用：它把"这个目标值不值得打"变成一个可读的单一数字。本项目不需要凭空造一套等级，**已有的数据可以直接算出来**——`commanderies.json` 每条都带 `households` / `population` / `counties`，`terrain-grid.json` 给得出地形与起伏。

```
郡国等级 = f(户口数, 属县数, 是否州治, 地形防御加成, 关隘数)  → 归一化到 1–10
```

于是"南阳郡（户 528551，口 2439618，37 县）是 10 级，而朔方郡（户 1987）是 1 级"这件事，是**从《郡国志》的真实数据里算出来的**，不是编的。这比任何游戏的数值表都有说服力，且零版权风险。

**中价值：攻坚的时间窗（耐久恢复）。**

原样是"60 分钟内未破则回满"，依赖真实时间。转译成回合制：**围城若干旬内未能攻破，守军补修完成、防御值回升**。保留了"必须集中兵力于一个窗口"的核心张力，去掉了真实时间依赖。这是一道很好的资源权衡题：把兵力摊在三条战线上慢慢磨，还是集中砸一个点？

**中价值：多前置条件的战略建筑。**

分城的"名声 + 连地形状 + 土地等级 + 资源 + 时间"是一个五条件与门。对模型来说，**多前置条件的长期项目是长期规划能力的直接考题**——你得在十几回合前就开始攒条件。本项目可以做成史实感更强的东西：屯田、修渠（如曹操的枣祗屯田、邓艾开渠）、迎奉天子（需要：与洛阳/长安方向连地 + 声望阈值 + 特定人物在位 + 若干旬护送），达成后解锁新的合法动作集（以天子名义发号、册封、讨伐诏）。

**明确拒绝清单：** 体力、真实时间行军、付费加速、抽卡、战法养成、跨赛季继承、几百人同盟的社交层。

## 四、《三国志曹操传》（光荣，1998）与战棋类

*说明：曹操传是光荣出品，但属"英杰传"系列而非主线《三国志》，任务书将其单列，本文按此处理。*

### 4.1 它解决了什么问题

大战略游戏的通病是**每场仗都长得一样**：兵力对比 + 地形 + 掷骰。战棋游戏用"每一关有自己的胜利与败北条件"解决了这个问题——同一套战斗规则，靠目标设计造出几十种完全不同的战术情境。同时它要解决另一个问题：**一款线性剧本游戏怎么给玩家真正的选择**。

### 4.2 用了什么机制

**（1）成对的胜利条件 / 败北条件**

每一关都明写两条：怎样算赢、怎样算输。常见的目标类型（跨越战棋类通例）：

- 全歼敌军 / 击破指定敌将
- 坚守 N 回合
- 保护某单位不死（败北条件常是"曹操战死"或"某人撤退"）
- 抵达指定格
- 限回合内达成上述之一

配合固定的敌军行动模式（主动出击 / 只打武将 / 原地防守）和仇恨值，同一张地图能玩出完全不同的解法。

**（2）红蓝条：一个隐藏标量决定剧本分支**

界面上有一条红蓝相间的条棒，表示曹操的思考倾向：**红色代表"霸者之道"（史实线），蓝色代表"英雄之道"（虚构线）**。玩家在剧情选择、对话、战场行为中不断把这个比例往两头推；剧情推进到某一章时，按红蓝比例分歧成两条完全不同的后续剧本。

这是"用一个隐藏累积量决定分支"的最简结构：玩家从来看不到确切数值，只能从条棒的长短感觉趋势。

**（3）兵种相克三角**

枪兵与弓兵克骑兵 → 骑兵克步兵 → 步兵克枪兵与弓兵，构成三角循环。
**数值来源须标清楚**：查到的"克制方 +30% 伤害 / 被克方 -25% 伤害"是 2017 年手游《新三国志曹操传》的数据，**不是 1998 年原作的**。原作的具体倍率我未能核实，本文只取"三角循环"这个结构。

**（4）宝物、单挑事件、经验成长**

每关有战利品（例如某关胜利得"双鞭"），有穿插的单挑事件，角色打仗涨经验升级。这一层是 SRPG 的养成骨架。

### 4.3 对 LLM 对战的迁移价值

**最高价值：把"一场会战"做成带成对胜负条件的独立任务。命中 C4、C5、C6。**

这是本项目战斗层最该抄的东西。现状是"一行公式比大小定城池归属"，既不可读也不可评。改成：

```ts
// 会战在生成时从模板库抽一对目标，双方各自知道自己的目标
interface BattleObjective {
  win:  { kind: "rout" | "holdTurns" | "captureNode" | "killCommander" | "breakSiege"; param?: number | string };
  lose: { kind: "commanderLost" | "supplyCut" | "turnLimit" | "moraleCollapse"; param?: number | string };
}
```

三个好处，逐一对应约束：

1. **决策变成从有限方略里选一个**（强攻 / 围而不打 / 断粮道 / 诱敌出城 / 撤围转进），完全可枚举（C4）。
2. **评测粒度从"最后谁赢"细化到"每场会战是否达成自定目标"**。这对模型能力测量极其重要：一局只有一个最终胜负，样本量太小，噪声压过信号；而一局里有二三十场会战，每场都有明确的成败判据，就有了统计功效（C5）。
3. **会战有独立的败北条件（比如"主将阵亡"）**，意味着高风险打法可能一次崩盘。这是"风险判断"能力的直接考题。

**并且，成对的胜负条件等于把效用函数明写给模型**。LLM 最怕的是"这仗打成什么样算赢"要靠猜——目标写死之后，模型的表现差异就纯粹来自规划质量，而不是来自对目标的误解。这一条对可比性的贡献被严重低估了。

**中价值：隐藏倾向标量 → 分支。**

红蓝条可以转译成**势力的路线值**。本项目的天然候选是史实中真实存在的政治路线分歧：

```
尊汉  ←─────────────→  自立
（奉迎天子、以汉臣自居）   （自建名号、称公称王）
```

模型的每一次决策（是否奉诏、是否接受册封、是否讨伐"逆臣"、是否僭号）都往两头推。跨过阈值后**解锁不同的合法动作集与事件池**：尊汉线能用"奉天子以令不臣"（外交加成、招揽名士），自立线能用"开府建牙"（内政效率、军权集中）但招致联合讨伐。

这对 C5 的价值在于：**早期的小选择在几十回合后改变可选项**——这正是"长期规划能力"的定义，而且它是可测的（比较各模型在路线一致性与时机把握上的差异）。

注意：这一条同时也是史实素材最扎实的地方（曹操迎献帝、袁术称帝、袁绍不受大将军、刘备领豫州牧），不需要编。

**低价值：**

- 格子级战棋微操：违反 C1。会战应当只暴露"方略"级决策，格子层由本地执行层跑。
- 宝物收集与角色升级：养成向，滚雪球，违反 C5。

## 五、《三国杀》（游卡桌游，2008；国战 2013）

### 5.1 它解决了什么问题

桌游要在极少的信息与极短的时长里制造推理压力。三国杀的答案是**身份隐藏**：把"谁是敌人"本身变成需要推理的对象。同时它还要解决一个多人局的老问题——**如何防止大家一起打领先者导致游戏变成群殴，或者反过来，某一方滚雪球滚到无人能挡**。

### 5.2 用了什么机制

**（1）身份局：四种身份，四套不同的胜利条件**

开局发身份牌，**只有主公亮明，其余人暗置**。

| 身份 | 胜利条件 |
| --- | --- |
| 主公 | 消灭所有反贼和内奸 |
| 忠臣 | 保护主公，与主公同胜（击杀所有反贼与内奸） |
| 反贼 | 击杀主公即胜 |
| **内奸** | 先消灭除主公外的所有角色，最后与主公单挑并取胜 |

关键在于这是一个**非零和的多方局**：忠臣与反贼直接对立，而内奸希望两边互耗到最后。内奸的存在让"简单结盟"变得危险。

**（2）国战：亮明是一个有代价的动作**

- 不发身份牌，每人选**同势力的两张武将牌**。
- 武将牌**暗置时没有任何技能、性别与势力**；只有两个时机可以明置：回合开始时、或发动该武将技能时。
- 也就是说：**要用技能就得暴露自己属于哪一方**。信息公开是玩家主动作出的、有明确代价的选择。
- 胜利条件：消灭所有与自己势力不同的角色。

**（3）野心家：一条自动触发的反滚雪球规则**

一名角色明置武将、确定势力时，**若该势力的角色数已超过总人数的一半，他立刻变成"野心家"**，拿专属身份牌。野心家视为独立势力，**必须杀光所有其他角色（包括其他野心家）才能胜利**。

这条规则的效果是：**一旦某一方明显做大，规则会自动把新加入者变成它的敌人**。领先方越大，它的"盟友"越可能被规则强制转化成对手。

**（4）出牌本身就是严格枚举的合法动作集**

三国杀的规则引擎必须在每个时机算出"你现在能出什么牌、能指定谁"。这是桌游规则数字化的通例，开源实现（QSanguosha / noname，见 §6）都是这个架构。

### 5.3 对 LLM 对战的迁移价值

**最高价值：野心家式的反滚雪球规则。同时命中 C5 与 C6。**

大战略游戏后半段最常见的失败模式是：某方先滚起来，之后每回合都在扩大优势，剩下的对局既没有悬念也没有信息量。对模型竞技场来说这更糟——**后半局的所有回合都不再区分模型能力**，等于白烧 token。

三国杀国战的解法非常优雅，而且它有真实的史实对应物（讨董联军、衣带诏、赤壁前的孙刘联合都是"合力抗最强者"）：

```
当任一势力（或同盟）控制的郡国数超过全图的 X% 时：
  - 该势力被标记为"僭越"，此标记全局可见
  - 其余所有势力自动获得一条追加胜利条件："共同削弱僭越者至阈值以下"
  - 与僭越者结盟的一方，声望持续流失
```

三重收益：
1. **治滚雪球**：领先者越领先，敌意越集中，优势曲线被压平（C5）。
2. **控局长**：既然做大就会招致围攻，跑到"一家统一天下"需要的回合数被结构性地限制住（C6）。
3. **造真实两难**：要不要当出头鸟？什么时候才该露头？这本身就是一道很好的风险判断题，而且是**LLM 之间会互相猜测的那种题**——大家都在算"谁会先被推出去当靶子"。

**高价值："亮明"作为一个有代价的动作。**

国战里"用技能就得亮势力"这个设计，本质是把**信息公开变成可枚举的博弈动作**。这在 mind-arena 里有直接对应物：

```ts
type DeclareAction =
  | { type: "declare"; kind: "intent"; target: string }        // 公开宣示战略意图（如"我讨伐吕布"）
  | { type: "declare"; kind: "oath"; with: FactionId; terms: Clause[] }  // 公开盟约
  | { type: "declare"; kind: "title"; title: string };         // 公开称号主张
```

公开宣示能换来实际收益（招揽人才、争取盟友、获得合法性、让第三方不来插手），但同时暴露自己的下一步。**这让"要不要让别人知道我在想什么"成为一个显式决策**，而不是隐性的博弈氛围。对多模型局特别合适，因为它把模型间的心理博弈落成了可记录、可回放、可分析的动作序列。

**中价值：非对称胜利条件。**

给不同席位不同的胜利条件（霸主 / 存续 / 复汉 / 割据一方），可以在同一局里测多种能力，也避免所有模型都往同一条最优线上挤。它还有史实依据：194 年的士燮、张鲁、公孙度，其现实目标本来就不是"统一天下"。

但要小心一个坑：**非对称会让排名口径变复杂**。解法是排名按"是否达成自身目标 + 达成的档位"计，而不是按"是否统一天下"计；并且要保证不同目标的难度经过校准（这需要跑大量自对局来标定，是一笔实打实的工程成本）。因此评为中而非高——方向对，但成本不低。

**低价值 / 建议改造：完全的身份隐藏。**

三国杀的核心乐趣是"猜谁是反贼"。但在模型竞技场里，**席位必须能归因到具体模型，否则排名无从谈起**——你得知道是 Model A 拿了曹操还是 Model B 拿了曹操。完全隐藏身份会让归因和复盘都变得极其困难。

建议改造为：**身份公开，意图隐藏**。

- 谁在操纵哪个势力：公开（可归因）。
- 各势力的兵力部署、战略计划、外交承诺是否会兑现：不完全信息。

这恰恰保留了"模型间互相猜测"里最有价值的部分——**从公开的行动序列去反推对方的方略**，而这是一种可以被客观评估的能力（可以在回放里比对"模型 A 对 B 意图的预测"与"B 实际做了什么"）。**如果要专门测欺骗与识破，那应该是一个独立的实验模式，不是主竞技模式。**

不可移植的部分：牌堆、武将技能的具体设计——那是版权表达，也是为 4–8 人一小时桌游调的平衡，与沙盘战略无关。

## 六、独立与开源作品

### 6.1 CtxPilot/Late-Eastern-Han-Dynasty（MIT，约 14 星）

<https://github.com/CtxPilot/Late-Eastern-Han-Dynasty>

技术栈 React 18 + TypeScript + Vite + Konva.js + Zustand + Tailwind，与本项目高度相近（本项目是 React 19 + PixiJS）。作者自述是"公有领域史料 + 原创，不复刻任何商业游戏"，MIT 许可。当前是 0-A 原型：223 武将 / 30 城 / 9 兵种 / 7 阵型，宣称有 27 个互锁系统；暂停中的 0-B 目标是 1000+ 武将 / 105 城 / 27 阵 / 21 兵种。

**它的方向与本项目相反**：它要做**深**（给人玩的完整大战略，六角战棋微操、族谱联姻、20 级功绩、朝堂霸府），本项目要做**宽而浅**（105 郡国全收，但决策必须是模型能消费的高层战略）。所以它的**系统设计不值得抄，但它的数据结构值得抄**——而且它的数据结构解决的恰好是本项目已经遇到或即将遇到的问题。

**（1）用 schema 把"史料依据"变成硬约束**（`shared/data/historical-geography/schema.ts`，zod）

```ts
HistoricalConfidenceSchema = z.enum(['attested', 'approximate', 'inferred'])
SourceRefsSchema = z.array(StableIdSchema).min(1)          // 每条记录至少一个来源引用
// 且：approximate / inferred 的记录必须写 locationNote
.refine((v) => v.confidence === 'attested' || v.locationNote !== undefined)
```

对照本项目：`commanderies.json` 已经有 `certainty: "attested"` 与 `seatCorrected` 字段，`scenario-194.json` 每条归属带 `basis` 文字说明——**方向完全一致，做得也不差**。缺的是两样：**结构化的 `sourceRefs`（引用 id 数组，指向一张来源表）**，以及**用 zod 把这些约束写成可执行的校验**。目前"有依据"靠人写在字符串里，没有任何东西阻止下一次数据修改把依据写丢。建议补一个 `tools/validate-data.mjs`。

**（2）政区沿革的表达**

```ts
validFromYear?: number
validToYear?: number
variantOf?: string        // 指向"同一实体的另一年份变体"
```

本项目现在只有 194 年一个剧本，暂时用不上。但 `THREE_KINGDOMS_RESEARCH.md` 已经写明后续要做 208/209 年剧本——**到那时郡国建置、州治、势力归属全都要按年份分叉**，届时会直接撞上这个问题。现在就把字段留出来，成本几乎为零。

**（3）情报条目带精度档与过期时间**（`shared/types/intel.ts`）——**这是本次调研中对 C2 最直接有用的一条**

```ts
interface CityIntelEntry {
  depth: 'surface' | 'detailed';    // surface=兵力档位+势力；detailed=兵力精确+经济约数
  expireYear: number;
  expireMonth: number;
  source: 'scout' | 'spy' | 'battle' | 'recon';
}
```

它把"信息不完全"做成了**两个正交的维度：精度（depth）与新鲜度（expire）**，而不是简单的"看得见/看不见"。对本项目的意义极大：

- **observe 层的裁剪有了原则性依据**。己方郡国给全量数据；接壤的敌方郡国给 `surface`（"兵力：约万余；势力：袁绍"）；远处只给"归属 + 是否有变动"。状态体积因此从"105 个郡国的全量字段"降到"少数几个郡国的全量 + 其余的一行摘要"。
- **情报会过期**，逼模型处理"我这条消息是三个月前的"这类推理——这是"信息不完全下的决策"最真实的形态，比"迷雾"这种非黑即白的模型好得多。
- 而且它**几乎免费地制造了侦察动作的价值**：派出斥候 = 把某个郡国的 intel 从 surface 升到 detailed 并刷新过期时间。这是一个干净的、可枚举的动作。

**（4）外交存为稀疏边而非矩阵**（`shared/types/diplomacy.ts`）

```ts
interface DiplomacyLink { factionA; factionB; relation; favorability: number; marriageBond?: boolean }
```

31 个势力的全矩阵是 465 条关系；实际有意义的关系边可能只有二三十条。稀疏存储对上下文预算是实打实的节省（C2）。

**（5）显示属性与隐藏属性分离**（`shared/types/officer.ts`）

`OfficerStatic.stats` 是公开五维，`OfficerHidden` 里则有 compatibility / righteousness / ambition / valor / composure / lifespan / growth / personality / ideal 等一大堆。

值得借鉴的是**这个分层本身**：给模型看的字段和引擎结算用的字段可以是两套。这天然支持"信息不完全"，也让 observe 的裁剪有了清晰的边界——**隐藏属性永远不进 observe，只通过后果间接显现**。（不值得抄的是它那十几个隐藏属性的具体清单，那是给深度养成服务的。）

### 6.2 llr104/slgserver（Apache-2.0，约 684 星，Go）

<https://github.com/llr104/slgserver>

一个率土类 SLG 的服务端 demo。值得看两点：

- **全数值外置为 JSON 配置表**：`data/conf/json/` 下有 `facility/*.json`（按建筑类型一表一文件）、`general/general.json`、`skill/{主动,被动,指挥,追击}/*.json`、`map_build.json`、`basic.json`。逻辑代码里不写数字。这是可以直接照搬的工程习惯——对本项目尤其重要，因为**平衡性调参会非常频繁，而且需要能 diff、能回滚、能标注"这次改了什么导致胜率变化"**。
- **同盟（union / coalition）是一等实体**：`logic/mgr/coalition_mgr.go`、`logic/union/union_logic.go` 是独立模块，不是挂在玩家身上的字段。多模型对局同样需要"同盟"作为可被引用、可被观测、可被背叛的对象。

不值得抄的是它的实时行军与体力模型（同 §3.3 的理由）。

### 6.3 Mogara/QSanguosha（GPL-3.0，约 1011 星）与 libnoname/noname（GPL-3.0，约 4931 星）

卡牌规则引擎。**真正值得读的是它们的触发式技能架构**：技能注册在"时机（trigger event）"上；引擎推进到某个时机时，收集所有可响应的技能与可用牌，算出一个**合法选项集合**，再询问决策者从中选一个（典型接口形如 `askForUseCard(filter)`）。

这正是 C4 要的东西的成熟工程范式，可以直接指导本项目 validate 层的形态：

> **不要让模型自由生成动作再去校验，而是由引擎先生成 `legalActions[]`，模型只返回索引（或索引 + 理由）。**

```ts
// observe 阶段就把合法动作算好，一起交给模型
interface Observation {
  summary: StrategicSummary;      // 分层摘要
  legalActions: LegalAction[];    // 引擎枚举，模型只从中选
}
// decide 返回 { actionIndex: number, reason: string }
// validate 退化成一次边界检查，几乎不可能失败
```

这样做的连带好处：validate 从"解析自然语言 + 语义校验"退化成"检查索引范围"，失败率趋近于零，回放（replay）也变得完全确定。

**授权警告，务必注意：**

- 两者均为 **GPL-3.0**，代码**不可**并入非 GPL 项目。只读架构思想，不复制代码。
- **noname 仓库打包了大量《三国杀》的音频与美术资源**（`apps/core/audio/` 下有成百个武将台词 mp3）。那些是游卡的版权内容，**绝对不能取用**，连临时占位都不行。

### 6.4 这个赛道的开源现状

按 star 排序检索 GitHub 上的三国战略游戏项目，结论是：**没有现成可抄的成熟数据模型**。除 Late-Eastern-Han-Dynasty（14 星）外，其余（`Embraccce/Wisdom-and-Valor-Three-Kingdoms` 5 星、`cancleeric/three-kingdoms-strategy` 1 星、`zhubby/Shogun` 1 星、`IvanWang-code-lab/open-sanguo-strategy` 0 星等）普遍停在原型阶段，多数是课程作业或个人练手，star 个位数，无完整数据集。

这反过来是个好消息：**本项目已有的 105 郡国（带户口、属县、坐标、certainty）+ 194 年 31 势力归属（每条带史料依据）+ 61 个战略节点 + 东汉故道水系 + 330×270 地形网格，在开源三国项目里已经是最完整的一份公有领域数据集**。数据不是短板，玩法才是。

## 八、建议吸收的最小集合

如果只能做一部分，按下面的顺序做——每一项都直接对应一条硬约束，且彼此不冲突。

**第一批（重做玩法的地基，缺一不可）**

1. **引擎枚举 legalActions[]，模型返回索引**（§6.3）→ C4。这是协议层的地基，先做这个，后面所有机制都挂在它上面。
2. **连地出征约束**（§3.4）→ C4 + C2。动作集与观测裁剪同时收敛。
3. **情报精度档 + 过期时间**（§6.1）→ C2。observe 分层的实现依据。
4. **内政年度批处理 + 事件驱动的军事窗口**（§1.3）→ C3。把调用成本压下来。
5. **分级终局判据**（§3.4）→ C6。替换掉 `maxTurns: 20` 这个外挂截断。

**第二批（让对局有博弈内容）**

6. **结构化外交提案 + 逐项估值**（§2.3）→ 补上完全空白的外交层。
7. **背信全局可见**（§2.3）→ 让 `FactionState.trust` 真正生效。
8. **反滚雪球的僭越规则**（§5.3）→ 保住后半局的区分度与局长。
9. **成对的会战胜负条件**（§4.3）→ 把评测粒度从"一局一胜负"细化到"每场会战"。
10. **兵种三系循环 + 地形修正**（§1.3）→ 最小可测的元博弈结构。

**第三批（有余力再做）**

11. 史实档 / 演义档双轨（§2.3）
12. 郡国 1–10 分级（从已有户口数据自算，§3.4）
13. 尊汉 ↔ 自立路线值与分支（§4.3）
14. 5–8 名将领 + satisfaction 标量（§2.3）
15. `sourceRefs` + zod 数据校验、`validFrom/To` 字段（§6.1）

## 九、不确定与待核实

按纪律，明确标出本文中不敢打包票的地方：

1. **《三国群英传》兵种相克的循环方向。** 查到的两处中文资料说法相反（"远克长→长克短→短克远" vs "长克短→短克远程→远程克长"）。**"三系单循环"的结构是确定的，方向未核实**。对本项目无影响（我们要自定义为弩阵/长戟/突骑）。
2. **《三国志曹操传》1998 原作的兵种克制倍率。** 本文引用的"+30% / -25%"来自 2017 年手游《新三国志曹操传》，**不是原作数据**。原作倍率未核实。
3. **《三国群英传》各代内政频率的精确演变。** 一代到三代"每年一次"、五代起"季内政"有资料支持；四、六、七、八代的具体频率未逐代核实。
4. **《三国群英传》武将带兵上限**：查到的攻略未给出具体数值。
5. **《全面战争：三国》五职业与五行的对应**：Vanguard=火、Sentinel=金、Strategist=水、Commander=土、Champion=木，来自二手 wiki 与攻略站，未在官方手册中直接确认（fandom wiki 在调研时返回 402，无法直接核对）。相生相克的具体规则同样未在官方文档中确认。
6. **《率土之滨》各级土地的守军兵力数值**：来自玩家问答站，非官方，且必然随版本变化。本文只用它说明量级。
7. **Late-Eastern-Han-Dynasty 的实际完成度**：README 自述的 27 大系统与功能清单未逐项验证，只验证了本文引用的那几个 schema 文件确实存在且内容如引述。
8. **《三国杀》国战"野心家"判定的精确条件**（"超过总人数一半"是否含等于、多个野心家如何互相判定胜负）：不同版本规则有差异，本文只取其设计意图。
