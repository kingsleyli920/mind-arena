## M0 · 数据补齐

一切的前置。三件事都要求**可复现**——同样的史料与规则，任何人跑一遍得到同样结果，
不能凭印象打分。

### M0.1 邻接图

从 105 郡治 + 61 关津生成通行图。

- Delaunay 三角化得候选边（审查已验证：305 条边、平均度 5.81，落在合理区间）
- 按地形网格采样每条边的地形档位（平原/丘陵/山地/关隘/大河/沼泽）
- 跨河判定：与 `hydrology.json` 的主干河道相交且无渡口 → 不可通行
- 关隘挂载：关津落在哪条边上，该边即受其控制
- 剔除跨海、跨青藏高原的伪邻接

**验收**：手工核对十条史实要道——虎牢关必须卡在洛阳与陈留之间、
剑门必须卡在汉中入蜀路上、濡须口必须卡在江淮之间。

### M0.2 郡级初始状态

从户口、地形、史实地位推导，规则写死在脚本里，不手工调值。

- 产出档：户数 + 地形产出系数 → 1–10
- 守军档：口数 × 2% 与郡粮上限取小 → 13 档等比 1.4
- 民心档：194 年该郡是否经战乱（可从 `scenario-194.json` 的 `basis` 与 `control` 推）→ 1–5
- 城防：`30 + 郡等 × 5`
- 无主郡：守军档与产出档同向（MERS R3）

**验收**：南阳、汝南、颍川必须是最高产出档（史载户口最多）；
凉州诸郡必须是低产出高守军（地贫而兵强）。

### M0.3 武将数值

按 `research/OFFICER-STATS-DESIGN.md` 的可复现规则，从史料字段推导，不凭印象。

- 三维（统率/谋略/政务）各 5 档：由 `roles` 标签、`prominence`、传记中的战功/谋议/治绩记载推导
- 适性标签 1–2 个：山地/水战/攻城/守城/治民/说客，由籍贯与事迹推
- 忠诚三档：安/疑/危，由 194 年归属的稳定性推

**验收**：关羽张飞统率必须顶档；诸葛亮此时 14 岁，不应有任何数值（未仕）；
甘宁孙策必须有水战适性。

### M0.4 内容包按 MERS 重写

现有 `pack-194.json` 是按首轮方案写的，两处要改：

- **一律 1 令**，征伐 2 令。删掉差别定价（MERS R10 推翻了首轮的定价表）
- **候选预筛**：动作参数不再自由填，引擎生成 5–15 条具体候选，模型做选择题（R13）

## M1 · 引擎核心

纯函数，无 UI，测试驱动。

```
observe(state, factionId)      → 分层观测，硬 token 预算
listActions(state, factionId)  → 预筛后的具体候选，5–15 条
validate(state, action)        → 合法性校验
resolve(state, orders[])       → 确定性同时裁决
```

- **确定性随机**：`H(seed, 年, 季, 势力, 事件类, 序号)` 派生，与裁决顺序无关，可逐位重放（R33）
- **野战**：有效战力比值 → 一合溃退 / 两合 / 相持（R21–22）
- **攻城**：缺口数 vs 可防守数（R23–27）
- **补给**：每季末算连通分量，不可达者产出归零、军团下季溃散（R28）
- **胜负**：按本局曾达到过的最高档记（R39–43）

**验收**：`resolve` 对同一 seed 与同一命令集，逐位可重放；
裁决顺序打乱后结果不变（这是 R6 的硬要求）。

## M2 · 自对局验证

写一个确定性规则 AI，让它自己打自己，跑 100 局。

**这一步是为了在接模型之前就发现玩法本身的病**。审查用真实数据算出首轮方案会
「六家谁都攻不下谁的城」——这类问题必须在自对局里暴露，不能等花钱调模型时才发现。

**验收**：
- 不出现地图冻结（每局至少 N 次郡国易主）
- 不出现苟活最优（纯守成策略的得分显著低于进攻策略）
- 局长稳定在 16 季
- 胜负分布不等于开局国力排序

---

## M3 · 模型接入

- OpenRouter 适配：`observe` → 提示词，模型输出 → `validate`
- 规则摘要走 KV 缓存，每季不重发（R37）
- **实测 token**：审查判定首轮方案低估 1.7–3 倍，这里必须实测而非估算
- 先单模型 vs 规则 AI，跑通再上多模型

**验收**：观测 ≤4000 token（MERS R34 的预算）；非法动作率可测量；一局成本可核算。

---

## M4 · 观战与复盘

- 地图叠加对局状态：势力疆域随占领变化、军团位置、补给线
- 时间线：每季的观测 / 决策 / 校验 / 裁决四段，可回放
- 战报逐项归因（R38）：哪个维度、哪个适性、哪个地形分别贡献了多少

---

## M5 · 评测

- 多模型对战、席位轮换、TrueSkill、多局中位数
- 过程指标：无效动作率、补给断裂次数、盟约背弃率、归隐时机
- 「归隐」调用即记入指标（R20）——什么时候认输是可测量的判断力

## 顺序与依赖

```
M0.1 邻接图 ─┐
M0.2 郡级状态├→ M0.4 内容包 → M1 引擎 → M2 自对局 → M3 模型接入 → M4 观战 → M5 评测
M0.3 武将数值┘
```

M0 三项彼此独立，可并行。M2 是关键闸门：**自对局跑不出健康的胜负分布，
就不要往下走**——玩法的病在这一步不解决，后面每一步都是在错误的基础上加码。

## 不做

- 武将个人成长、科技树、单挑、部队微操、城内建筑槽位
- 大义名分（天子/爵位）线：认同其价值，但 MERS 已 43 条，加进去破坏「一页纸」，留到后续
- 战法连锁：schema 现在就留 `precondition`/`effect` 两个字段，实现推迟
