### M0.2 郡级初始状态 ✅ 已完成

`tools/build-commandery-state.mjs` → `lib/game/data/commandery-state.json`
5/5 定点验收通过。

**关键发现：《郡国志》户口是永和五年（140）的数字，剧本却是 194 年。**
中间隔着黄巾之乱（184）、董卓之乱（190）、凉州羌乱、青州黄巾、
曹操屠徐州。直接用会让中原诸郡强得离谱，而史实恰恰相反——
本年曹操「蝗旱大饥，仅保三城」。

因此引入战乱衰减系数，按州与郡两级指定，**每条附史料依据**：
司隶 ×0.30（雒阳被焚，二百里内无烟火）、兖徐 ×0.45、豫州 ×0.55、
荆州 ×1.05、益州 ×1.10（南阳三辅民数万户流入益州）、交州 ×1.05。
这也正好造出 194 年真实的战略不对称：**中原户口多而残破，
荆益户口少而完好且纳流民**。

**未经调参的交叉验证**（兵力由户口 × 衰减 × 2% 自然算出，非拟合）：
- 刘表 107,189 兵 ↔《刘表传》「地方数千里，带甲十余万」
- 袁绍 99,644 兵 ↔ 官渡「简精卒十万，骑万匹」

从户口、地形、史实地位推导，规则写死在脚本里，不手工调值。

- 产出档：户数 + 地形产出系数 → 1–10
- 守军档：口数 × 2% 与郡粮上限取小 → 13 档等比 1.4
- 民心档：194 年该郡是否经战乱（可从 `scenario-194.json` 的 `basis` 与 `control` 推）→ 1–5
- 城防：`30 + 郡等 × 5`
- 无主郡：守军档与产出档同向（MERS R3）

**验收**：南阳汝南产出 8（最高档），河南尹民心 1（雒阳被焚），
蜀郡产出 8（纳流民），敦煌产出 1，凉州诸郡产出 1–4。全部通过。

**待议**：曹操开局仅济阴一郡、6576 兵，而吕布六郡 26,011 兵。
这符合史实（本年仅保鄄城、范、东阿三城），但作为可玩席位极其艰难。
MERS 用「相对开局的增量」计分，理论上不影响公平，
但自对局阶段要重点观察曹操席位是否必然出局。

## M1 · 引擎核心

纯函数，无 UI，测试驱动。

```
observe(state, factionId)      → 分层观测，硬 token 预算
listActions(state, factionId)  → 预筛后的具体候选，5–15 条
validate(state, action)        → 合法性校验
resolve(state, orders[])       → 确定性同时裁决
```

- **确定性随机**：`H(seed, 年, 季, 势力, 事件类, 序号)` 派生，与裁决顺序无关，可逐位重放（R33）
- **野战**：有效战力比值 → 一合溃退 / 两合 / 相持（R21–22）
- **攻城**：缺口数 vs 可防守数（R23–27）
- **补给**：每季末算连通分量，不可达者产出归零、军团下季溃散（R28）
- **胜负**：按本局曾达到过的最高档记（R39–43）

**验收**：`resolve` 对同一 seed 与同一命令集，逐位可重放；
裁决顺序打乱后结果不变（这是 R6 的硬要求）。

## M2 · 自对局验证 ✅ 已完成

`lib/game/engine/bot.ts` + `tools/selfplay.mjs`（`npm run selfplay`）
四条验收全部通过，判据已固化为回归测试 `tests/selfplay.test.mjs`。

**实测结果（60 局，席位轮换四种画像）**

| 画像 | 均分 | 疆域倍数 | 出局率 |
| --- | --- | --- | --- |
| balanced 均衡 | 213 | 1.71 | 0% |
| opportunist 投机 | 200 | 2.14 | 0% |
| aggressive 进攻 | 188 | 1.28 | 20% |
| **turtle 苟活** | **83** | 0.95 | 0% |

苟活流出局率最低却得分垫底——「存续本身不得分」在数值上真的成立。

**开局郡数 ↔ 实际得分 Spearman ρ = −0.09**。这是最关键的一项：
得分与开局国力无关。刘表七郡均分 250，袁绍十三郡只有 187，
刘璋九郡垫底 75（益州被秦岭巴山围死，扩张不出去）。

**过程中修掉一个真 bug**：`城防` 根本没参与守方判定，
`hold` 只看守军数，30–100 的城防数值等于白算，「修城」这条内政毫无用处。
后果是攻城易如反掌——首轮实测第一季就有 17 个郡易主，96% 是势力互夺。
把城防纳入后：每局易主 136 → 77，曹操出局率 53% → 1.7%。

**曹操席位的疑虑已解除**：一郡六千兵开局，60 局中出局 1 次，
拿到甲档 14 次。一郡起家能打成霸业，这正是该席位应有的样子。

**待观察的平衡问题**（不阻塞，留待模型对战时复核）：
- 刘表 45/60 局拿甲档，荆州富庶且无强邻，该席位偏易
- 刘璋均分 75 垫底，益州封闭导致增量上不去，该席位偏难

写一个确定性规则 AI，让它自己打自己，跑 100 局。

**这一步是为了在接模型之前就发现玩法本身的病**。审查用真实数据算出首轮方案会
「六家谁都攻不下谁的城」——这类问题必须在自对局里暴露，不能等花钱调模型时才发现。

**验收**：
- 不出现地图冻结（每局至少 N 次郡国易主）
- 不出现苟活最优（纯守成策略的得分显著低于进攻策略）
- 局长稳定在 16 季
- 胜负分布不等于开局国力排序

## 顺序与依赖

```
M0.1 邻接图 ─┐
M0.2 郡级状态├→ M0.4 内容包 → M1 引擎 → M2 自对局 → M3 模型接入 → M4 观战 → M5 评测
M0.3 武将数值┘
```

M0 三项彼此独立，可并行。M2 是关键闸门：**自对局跑不出健康的胜负分布，
就不要往下走**——玩法的病在这一步不解决，后面每一步都是在错误的基础上加码。
