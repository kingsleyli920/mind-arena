## 零、这份文档的写法与边界

### 0.1 唯一的设计目标

这不是给人玩的三国游戏，是**多个大语言模型同场对局的竞技场**。
下面每一条规则都要能回答一个问题：**它对区分模型能力有什么用？**
答不出来的规则一律不进第一版，无论它多有三国味。

六条硬约束（沿用 `GAMEPLAY-OTHER-SANGUO.md` §0.3 的编号，全文引用）：

| 编号 | 约束 |
| --- | --- |
| **C1** | 决策是高层战略，不是微操 |
| **C2** | 状态可序列化，可分层摘要、按相关性裁剪后塞进上下文 |
| **C3** | 决策频率与模型调用成本解耦 |
| **C4** | 合法动作集可枚举，模型从中选择而非自由生成 |
| **C5** | 更强的推理稳定转化为更好的结果，不被随机性淹没 |
| **C6** | 局长可控 |

### 0.2 三类来源必须分开

- **【史实】**：传世文献或考古依据。例：《续汉书·郡国志》的 105 郡国户口；虎牢关东汉时称成皋关；曹操"奉天子以令不臣"。
- **【演义】**：小说创作。例：汜水关虎牢关分作两处；单挑定胜负。**默认不生效**，只进演义档。
- **【游戏原创】**：某作品的设计发明。例：光荣的五维数值表；EU4 的侵略性扩张点数；率土之滨的土地等级。
  **可借鉴的是机制思路，不可复制的是具体数值表与美术表达。**
- **【本文原创】**：下文所有公式与常数。它们**不抄任何作品的数值表**，而是从《郡国志》户口与汉代廪给量级反推的，推导过程写在正文里。

### 0.3 本文的数字是什么性质

正文里的每个常数分三档标记：

| 标记 | 含义 |
| --- | --- |
| **【锚定】** | 由史料量级反推得出，改动需要重新走推导（如粮产系数 K_grain） |
| **【首版取值】** | 结构确定，数值待自对局标定，可以改（如姿态修正 ±20%） |
| **【待验证】** | 连结构都可能错，标注了验证方法（如胜利阈值 40%） |

## 一、时间与回合结构

### 1.1 三层时间

| 层 | 长度 | 谁在动 | 一局多少 |
| --- | --- | --- | --- |
| **旬** | 10 日 | 引擎。行军、围城、生产、消耗、事件全在这一层推进 | 540（15 年 × 36） |
| **季议（council）** | 9 旬 = 3 月 | 模型下令的窗口 | **60**（194 春 → 208 冬） |
| **岁首大议** | 每年第一次季议 | 额外开放国策、爵位、私有目标复核 | 15 |

**来源**：旬作为推进单位取自《三国志》9 / 11 / 14 三代的共识（一年 36 回合），也是汉代实际的行政节奏（旬报、上计）【史实】。
季议的双层节奏取自《三国志 8 REMAKE》的"月度个人回合 + 1/4/7/10 月评定"，
但**删掉个人回合层只留评定**——个人回合是微操从侧门溜回来的入口（C1）。
60 这个数字锚定 Diplomacy 的 60 轮（DSGBench 实测），也对齐 `GAMEPLAY-AI-FRIENDLY.md` §7.3 的推荐区间 48–60。

### 1.2 一次季议的六个阶段

```
① 报告      引擎生成分层观测（见 §8），推送给需要唤醒的势力
② 谈判      同时提交私信 + 公开声明竞价；公开声明按竞价顺序广播
③ 密封下令   各方同时提交命令，互不可见            ← WEGO
④ 裁决      resolve(state, orders[]) → state'，纯函数，无副作用
⑤ 推进      引擎连跑 9 旬；命中中断条件则提前结束本季
⑥ 结算      收支、事件、情报老化、中断检测 → 回到 ①
```

**来源**：②③④ 的结构取自 Diplomacy 的"命令秘密提交 → 同时揭示 → 确定性裁决"；
①⑥ 的显式报告阶段取自《三国志 14》的三阶段（战略 / 进行 / 报告）——
14 代把报告单列出来，正好对应"给模型的观测该在什么时刻生成"；
⑤ 的"进行中不可改令"取自《三国志 9》的两阶段推进，这是防微操的关键闸门。

**为什么是 WEGO 而不是轮流行动**：轮流行动里座次本身是优势，基准评测必须做座位轮换才能去偏；
WEGO 从机制上消掉这一整类噪声，而且 N 个模型可并行调用，一季的墙钟时间等于最慢的那个模型，不是 N 倍。

### 1.3 一旬内的裁决顺序（确定性）

```
1. 月首（每季第 1、4、7 旬）：郡国产出入库；军团口粮扣除
2. 行军：所有在途军团同时推进；通行容量不足则按主将统率降序分配，余者滞留
3. 遭遇：同格或对穿的敌对军团触发野战（§5.4）
4. 攻城：处于围城状态的军团结算（§5.5）
5. 内政推进：垦田、商度、城防、工程进度
6. 计略生效：断粮、离间、伏火的判定（确定性，见 §5.7）
7. 民心与忠诚更新；叛乱与出走判定
8. 情报老化：所有非本方观测的 staleness +1
9. 事件与中断检测
```

**同时性冲突的裁决**：两支敌对军团同一旬进入同一空郡 → 触发遭遇战，胜方占领。
两支友军同时进入 → 合并为联军（主将取统率高者）。
**永不使用"先手方胜"这类座次相关的裁决。**

### 1.4 无重大变化时如何不调用模型

这是 C3 的核心，也是整套设计里成本模型的关键。三件事叠加实现：

**（一）命令是持续指令（directive），不是单次动作。**

每条命令带 `until` 字段，取值：`{ councils: N }`（持续 N 季）或 `{ untilGoal: true }`（直到达成中间目标）或 `{ standing: true }`（常驻，直到改令）。
方针类命令默认 `standing`，军事类命令默认 `untilGoal`。
未被显式改令的据点一律按方针由本地执行层跑（见 §6.2）。

**来源**：HOI4 的 Battle Plan——玩家画战线、按执行键、AI 接管师级调度，
部队推进到中间目标后自动暂停等待重新激活。这是"高层意图 + 自动执行 + 阶段性中断"的教科书实现。
**但 HOI4 的教训也要吸取**：社群实测"步兵交给计划、装甲手动微操"，因为手动能跑赢委托。
所以本项目**根本不提供手动通道**，而不是靠惩罚劝退。

**（二）唤醒条件表（公开写进系统提示）。**

某势力在第 k 次季议被调用，当且仅当满足任一条：

| # | 条件 | 说明 |
| --- | --- | --- |
| W1 | k 是岁首大议 | 保底每年 1 次 |
| W2 | 上季结束时已无任何进行中的 directive | 无事可做才问 |
| W3 | 命中中断条件（下表） | 出大事了 |
| W4 | 上次提交时显式声明 `requestWakeAt: k` | 模型自己排的闹钟 |
| W5 | 收到需要回应的外交提案，且本方未预设自动回应 | — |

中断条件表（同样公开）：

| 类别 | 条件 |
| --- | --- |
| 领土 | 本方郡国易主（得或失）；本方战略节点易主 |
| 军事 | 军团野战失利；主将阵亡或被俘；围城破城或撤围 |
| 补给 | 任一军团补给线断绝满 1 旬 |
| 财政 | 势力总仓储 < 全军 2 旬消耗 |
| 人事 | 任一将忠诚跌破 30 |
| 外交 | 被宣战；盟约被单方面废止；被标记僭越；他方被标记僭越 |
| 目标 | directive 的中间目标达成 |
| 事件 | 重大历史事件（天子东归、蝗旱大饥、黄河决溢、瘟疫） |

**中断预算：每势力每季最多 2 次中断唤醒。**超出的中断不丢弃，压进下一次正常季议的报告里。
这条硬预算是为了让最坏情况的调用数可算——否则一场混战能把成本打上天。

**（三）默认令。**

模型超时、返回不可解析、或连续两次校验失败 → 引擎套用 `继续上季`（所有 directive 原样延续）。
这一次记入 **IAR（无效动作率）** 指标，不中断对局。
**绝不因为模型失败而随机代打**——那会污染基准。

### 1.5 调用量估算

| 项 | 数量 | 依据 |
| --- | --- | --- |
| 季议总数 | 60 | 15 年 × 4 |
| 模型控制的势力 | **6** | SPIN-Bench 发现 agent 数增加会拖垮推理；Diplomacy 7 家。取 6 |
| 每势力实际唤醒次数 | 约 28–34 | 15 次岁首 + 约 13–19 次中断/无令/自请 |
| decide 调用 | 6 × ~31 ≈ **186** | — |
| 谈判调用 | 岁首 2 轮 + 有提案的季议 1 轮，约 20 轮 × 6 ≈ **120** | AI_Diplomacy 实测每阶段 0–3 轮 |
| **单局总调用** | **约 300** | — |
| 单局 token | 约 1.8M in / 0.9M out | 300 × (6k in / 3k out) |

对照：若每季全量调用 6 家，是 360 次 decide + 360 次谈判 = 720 次，成本翻 2.4 倍且大量季议无事可决。

### 1.6 提前终局

除 §9 的胜利条件外，两条防拖沓：

- **僵局判定**：连续 8 次季议无郡国易主、无盟约变更、无宣战 → 判僵局，按当时综合分排名。
- **消灭判定**：模型控制的势力只剩 1 家未被消灭或从属 → 立即结算。

**来源**：《三国志 9》的"空白城与异民族城不必占领"。系列通病是后期作业化，
大势已定后还要打几十上百回合——对模型竞技场这是纯粹烧 token 而不产生区分度。

## 二、动作空间

### 2.1 协议：两级枚举

`GAMEPLAY-AI-FRIENDLY.md` 原则 3 要求"合法动作集必须显式枚举后随观测一起给出，规模控制在 O(10)–O(10²)"。
但一个 `campaign` 命令若把主将、目标、兵力档、兵种、姿态、战役目标全做笛卡尔积，
单是它一项就有 `6 主将 × 5 目标 × 4 兵力 × 3 兵种 × 6 姿态 × 5 目标类型 = 10,800` 条。
完全展开必然爆炸。

**解法：枚举到"条目 × 参数域"，而不是全笛卡尔积。**

```jsonc
// 第一级：带稳定 id 的条目 = (模板, 主目标)。这是"我要做什么"
{
  "id": "a17",
  "t": "campaign",
  "target": "濮阳",                       // 主目标，已过连地与可达校验
  "cost": 3,                              // 战略点
  "params": {                             // 第二级：每个字段的合法取值域
    "leader":    ["夏侯惇","曹仁","于禁","乐进","典韦","曹洪"],
    "deputies":  { "from": ["...同上..."], "max": 2 },
    "strength":  ["三成","五成","七成","全军"],
    "arm":       ["弩阵","长戟","突骑"],
    "posture":   ["强攻","持重","急行","掠食","固守","佯动"],
    "objective": ["破城","击溃野战主力","占领节点","解围","迫降"]
  }
}
```

模型返回 `{ actionId, params }`。校验 = 条目 id 在集合内 + 每个参数在其域内 + 跨字段前置条件。
**所有参数域都是有限枚举，没有任何连续量**，所以校验仍然是 100% 可判定的，
`validate` 退化为索引与集合成员检查。

**来源**：AI_Diplomacy 让模型从引擎给出的 possible orders 里选而非自由生成；
QSanguosha / noname 的触发式技能引擎也是"引擎先枚举合法响应，玩家只选索引"（仅读架构，GPL 代码不可用）。
两级化是本项目的改动，理由是 105 郡国的目标空间比 Diplomacy 的 34 个补给中心大一个量级。

### 2.2 战略点预算

每次季议给每势力一个硬预算，命令按类型计价。

```
SP = 5 + floor(√控制郡国数) + 爵位加成(0–2) + 上季结转(≤4)
```

| 势力规模 | 郡国 | SP |
| --- | --- | --- |
| 曹操（194 开局） | 1 | 6 |
| 吕布 / 刘备 | 6 | 7 |
| 袁绍 | 13 | 8 |
| 中期强权 | 30 | 10 |
| 接近胜利 | 55 | 12 |

（表中未计爵位加成与结转，两项合计最多再 +6。）

**来源**：《三国志 8 REMAKE》的战略点（按身分分配，决定这次评定能下几条命令）
+ 《三国志 13》的任务状（数量由身分与能力决定）。
**为什么用 √ 而不是线性**：线性会让后期命令数爆炸，与上下文预算和局长都冲突（9 代范式的已知风险）。
√ 让大势力有优势但不成比例——这本身就是一道题：家底越厚，决策带宽越是稀缺资源。

预算逼出优先级判断，这是考题不是限制。典型一季提交 **4–7 条命令**，
符合"同一类决策在一个回合内不超过 5 次"的硬规则。

### 2.4 合法动作数量估算与论证

以**中期一个 8 郡势力**为例（12 名在册武将、4 个边境郡、2 支在外军团、5 家已接触势力、3 个战区）：

| 模板 | 第一级条目数 | 算法 |
| --- | --- | --- |
| campaign | 5 | 连地可达的敌方/中立据点数 |
| reinforce | 2 | 在外军团数 |
| siege_plan | 1 | 围城中的军团数 |
| fortify | 8 | 己方郡国数 |
| recall | 2 | 在外军团数 |
| directive | 3 | 战区数（policy 走参数域） |
| levy | 8 | 己方郡国数 |
| project | 6 | 满足前置的工程条目 |
| appoint | 9 | 空缺或可换的职位 |
| enlist | 5 | 可征辟名单（在野 + 俘虏） |
| reward | 4 | 忠诚 < 70 的在册武将 |
| propose | 5 | 已接触势力数 |
| respond | 1 | 待回应提案 |
| declare | 8 | 5 类 × 合法目标 |
| abrogate | 2 | 生效盟约数 |
| vassalage | 3 | 合法对象 |
| scheme | 12 | 6 类 × 合法目标（受谋略与特技收敛） |
| scout | 9 | 情报陈旧的连地郡国与已知军团 |
| court | 4 | 合法朝廷动作 |
| pass | 1 | — |
| **合计** | **≈ 98** | |

**这个量级是刻意选的，理由有四条：**

1. **上限来自 token 预算。** 每条约 25 token（id、模板、目标、代价、参数域），98 条 ≈ 2,450 token，
   落在 `OFFICER-STATS-DESIGN.md` §6.2 的"单势力单季合法动作枚举文本 ≤ 3000 token"硬预算内。
   超过 160 条就会撑破预算。
2. **下限来自区分度。** 现有实现只有 4 个动作类型（develop / recruit / appease / march），
   一个势力的合法动作总数不到 20，"派谁去哪"退化成两次排序，绝大多数局面有唯一最优解。
   动作太少，强模型和弱模型选的是同一个。
3. **真正的深度不在单步宽度，在组合与序列。** SP 预算让模型每季从 ~98 条里选 4–7 条，
   组合数 C(98,5) ≈ 6.7×10⁷；再乘以第二级参数域（campaign 一条就有 10³ 量级的填法），
   再乘以 60 季的序列。深度完全够，而每一步都可枚举可校验。
4. **SPIN-Bench 的定量发现支持这个取法**：准确率与**总状态-动作空间**的相关性，
   强于与平均合法动作数的相关性。所以该压的是总空间（靠连地约束、委任、模板固定），
   不是单步的候选条数。CivRealm 的 10^166 动作空间是反面教材。

**超预算时的裁剪规则**（必须写死，不能临场发挥）：
第一级超过 140 条时，按 `威胁度 × 收益估值` 降序保留 140 条，
并在观测里注明 `truncated: N`，模型可用 `queryActions(category)` 拉回被裁的那一类全集（消耗一次查询配额）。

### 2.5 收敛动作空间的三个结构性手段

| 手段 | 来源 | 收敛效果 |
| --- | --- | --- |
| **连地出征**：目标必须与本方领地相邻 | 率土之滨 / 三国志·战略版的连地规则【游戏原创】，但地缘约束本身是【史实】 | campaign 目标从 O(105) 降到 O(3–8)；同时给观测裁剪提供原则性依据（C2） |
| **委任兜底**：未被显式下令的郡国按方针自动跑 | 《三国志 8 REMAKE》的军团/都市方针 + 《三国志 14》的地区委任 | 内政条目从 O(郡国数) 降到 O(战区数)≈3–5 |
| **模板固定 + 特技只改参数域** | 本文原创纪律，源自 `OFFICER-STATS-DESIGN.md` §6.2 | 特技从 24 条增长到 40 条也不会增加模板数 |

## 三、势力属性

### 3.1 取舍原则

`RESEARCH-2026-08-31.md` §四列的候选是"金、兵粮、兵力、都市数、名声/威信、爵位、外交关系、技术"。
本文的筛选判据只有一条：**这个标量有没有一条命令直接作用于它，并且它有没有反过来卡住某条命令？**
两边都不成立的标量是死字段——它只吃 token，不产生决策。

于是砍掉：文化、宗教、稳定度、腐败、科技点数池、人口满意度。

### 3.2 保留的九项

| 属性 | 量纲 | 产出 | 消耗 | 为什么要 |
| --- | --- | --- | --- | --- |
| **粮** grain | 石，按势力汇总，但**分郡储存** | 郡国农产 | 军团口粮、戍兵廪给、工程 | 汉末战争的第一约束【史实：官渡败于乌巢】。它让"断粮"成为真战略而不是台词 |
| **钱** coin | 钱 | 郡国商税 | 募兵、工程、赏赐、使者礼、器械 | 与粮分开才有"屯田 vs 通商"这条真实路线分歧；一种资源做不出权衡 |
| **兵** troops | 人，**分据点/军团存放，不是势力池** | 募兵、招降、流民 | 战损、逃亡、断粮减员 | 不设全局池是为了让地理生效——兵不能瞬移 |
| **民心** morale | 0–100，**按郡** | 安民方针、赈济、抚民特技 | 强征、掠食、战祸、屠城 | 它是"竭泽而渔"的价码。没有它，`levy` 就是免费收入 |
| **威望** renown | 0–100，势力级，**公开** | 战胜、奉诏、赈灾、举贤、宗室 | 屠城、背盟、掠食、僭号 | 门槛型资源：开启招贤、招降、高阶外交提案 |
| **名分** legitimacy | −100（自立）… +100（尊汉），**公开** | 见 §3.5 | — | **不是强弱，是路线。**它决定可选动作集不同，不决定谁强 |
| **信义** credit | 0–100，**公开** | 守约到期、履行条款 | 背盟、袭击盟友、毁诺 | 让背叛的一次性收益变成长期成本 |
| **众怒** ire | 0–100，**公开且可由任何人算出** | 见 §7.5 | 时间衰减、降温动作 | 反滚雪球的旋钮 |
| **爵位** rank | 枚举阶梯 | `court` 动作 | — | 一次罕见、高风险、长周期、可枚举的决策 |

另加一个 4×3 的**国策**向量（见 §6.5），不是标量。

**兵力不设势力池这一条要单独强调。** 它看似只是存储方式，实际决定了整个军事层的形状：
一旦有全局兵池，"从哪出兵"就不是问题，地形、关隘、补给线全部失效。

### 3.3 产出与消耗的公式框架

**记号**：`H` = 郡户数（`commanderies.json` 的 `households`），`P` = 郡口数，
`垦` / `商` / `防` = 0–100 的郡级开发度，`民` = 民心，`政` = 太守政务，`α` = 季节系数。

#### 粮

```
郡粮产/旬 = H × K_grain × (0.4 + 0.6×垦/100) × (0.78 + 政/230) × (0.6 + 0.4×民/100) × α
```

`K_grain = 0.09 石/户/旬` **【锚定】**。推导：
汉制田租三十税一，一户年产粟约 50–100 石，田租约 1.7–3.3 石/年；
加算赋口赋折粮与郡县自筹，取年可支配约 3.2 石/户 → 每旬 0.09 石。

**用真实数据验算**（这是选这个常数的理由，不是事后合理化）：

| 势力 | 户 | 修正后粮产/旬 | 可长期供养行伍 | 史实对照 |
| --- | --- | --- | --- | --- |
| 曹操（东郡 1 郡） | 133,715 | ≈ 7,000 石 | ≈ 7,000 | 194 年曹操兵力万余，且当年蝗旱大饥 |
| 袁绍（13 郡） | 1,280,952 | ≈ 81,600 石 | ≈ 81,600 | 官渡号十万 |

量级对得上，所以这个常数不是拍的。

`α` 季节系数【首版取值】：春 0.7 / 夏 0.9 / 秋 1.6 / 冬 0.8。秋收占大头，这让"什么季节动兵"成为真问题。

#### 钱

```
郡钱产/旬 = H × K_coin × (0.4 + 0.6×商/100) × (0.78 + 政/230) × (0.6 + 0.4×民/100)
```

`K_coin = 4 钱/户/旬` **【锚定】**。推导：算赋 120 钱/人/年，一户约 5 口 → 600 钱/年 ≈ 16.7 钱/旬；
扣官俸、驿传、工徒等本地开支，取四分之一入库。

#### 兵

```
兵役池上限 = P × 2%                                   // 该郡能供养的常备兵总量，含戍兵与在外行伍
每季可募   = (池上限 − 现有) × 12% × (0.8 + 政/260) × (民/100)
募兵成本   = 1,200 钱/人 + 3 石/人（甲兵器械与初程口粮）
```

**【锚定】**：袁绍 830 万口 → 池 166,000，与"官渡号十万"的量级相容；
曹操 65.7 万口 → 池 13,151，194 年民心低（战祸）时季募不足 500 人——
这正是 `OFFICER-STATS-DESIGN.md` §9 说的"人才过剩、土地极度稀缺"那道题，它是从数据里自然长出来的，不是编的。

#### 消耗

| 项 | 数量 |
| --- | --- |
| 行伍口粮 | **1.0 石/人/旬**【锚定：汉代士卒月廪约 3 石】 |
| 戍兵廪给 | 0.5 石/人/旬（屯戍半自给） |
| 补给线加成 | × (1 + 0.15 × 补给路径旬数) |
| 掠食姿态 | 粮耗 × 0.4，代价见 §5.3 |
| 官俸 | 在册武将 × 40 钱/旬 |

### 3.4 威望

0–100，**公开**。门槛型，不是加法型——它开启动作，不给百分比加成。

| 阈值 | 开启 |
| --- | --- |
| ≥ 30 | `enlist` 可用"举荐" |
| ≥ 45 | `propose` 可用同盟类条款；可纳降中立势力 |
| ≥ 60 | `court` 可上表请封州牧；`declare` 可发檄文 |
| ≥ 75 | `propose` 可用"倡合纵"（多方同盟）；可招降敌方在押武将 |

变动【首版取值】：破一城 +2；奉诏出兵 +4；赈灾 +3；举贤（征辟到高名望在野）+2；
屠城 −15；背盟 −12；掠食姿态每季 −2；僭号 −20。

**红线**（`OFFICER-STATS-DESIGN.md` §3.3）：威望**绝不**提高"对方模型接受同盟"的概率。
任何"我威望高所以你必须答应"的机制，都是在用数值覆盖对手的推理。
威望只作用于引擎裁决的对象：NPC 势力、在野人物、俘虏、流民、以及动作的可用性与成本。

### 3.5 名分：一条路线值，不是一条好坏轴

```
尊汉 +100  ←──────────────────  0  ──────────────────→  −100 自立
（奉迎、以汉臣自居、受诏）                        （开府建牙、自建名号）
```

**来源**：《三国志曹操传》的红蓝路线值（霸道 / 王道分支）【游戏原创】，
但本项目的两端有扎实【史实】对应：曹操迎献帝、袁术称帝、袁绍不受大将军、刘备领豫州牧。

两端解锁**不同的合法动作集**，而不是不同的强弱：

| 尊汉线（≥ +40） | 自立线（≤ −40） |
| --- | --- |
| `court:奉诏` 可用：奉诏讨伐产生的众怒仅计 40% | `court:僭号` 可用：爵位可自升两级 |
| `declare:檄文` 可用：号召多方共讨某方 | `directive` 的征兵方针效率 +20%（军权集中） |
| `propose` 开放"承认名号"条款 | 内政类命令 SP 成本 −1（不必走朝廷程序） |
| 招揽高名望在野者成功阈值降低 | 高名望在野者拒绝概率上升；宗室特技者拒绝 |
| **代价**：受诏出兵是义务，拒诏 −威望 | **代价**：众怒基线 +15；他方 `court:檄文` 可点名你 |

中间地带（−40 ~ +40）两边都不开，但没有惩罚——**割据自守是一条合法路线**（士燮、张鲁在 194 年确实如此）。

变动由动作驱动，确定性：奉诏 +12、拒诏 −8、上表请封 +5、僭号 −40、
攻击持天子的势力 −10、迎奉天子 +30。

### 3.6 爵位

`无 → 县令/长 → 太守/相 → 刺史 → 州牧 → 将军号 → 三公 → 王 → 帝`

每升一级：SP +0.5（取整后体现）、`propose` 开放更高档条款、麾下武将忠诚基线 +2。
获得途径两条：**朝廷授予**（需名分 ≥ +20 且威望阈值，`court:上表请封`）
或 **自升**（`court:僭号`，名分 −40、众怒 +25、信义不变）。
王与帝只能自升，且触发全局 `declare:檄文` 的合法目标。

### 3.7 众怒：反滚雪球的唯一旋钮

```
众怒 = clamp( 60 × min(1, max(0, 国力指数 − 0.15) / 0.15)  // 体量项：PI 15% 起算，30% 时满 60
            + 侵略行为累计分                              // 行为项，见下
            + 名分惩罚（自立线 +15）
            − 已衰减量
          , 0, 100 )
```

侵略行为累计分【首版取值】：夺取他方郡国 +4/郡（若为奉诏讨伐则 +1.6）、
背盟 +10、屠城 +12、僭号 +25、攻击已请附于第三方的势力 +6。
**衰减 −3/季**，无上限地持续衰减到行为项归零——所以"停手降温"永远是一个可用的战略选项。

**来源**：EU4 的侵略性扩张（AE）【游戏原创】三条可迁移思路——围殴有窗口期、
扩张方式影响仇恨、地理与文化折扣；本项目把第三条换成【史实】的"名分"：
奉天子讨不臣的兼并仇恨低，擅杀朝廷命官、屠城的仇恨高。这一层有史料支持，不是硬造。

众怒 ≥ 70 → 标记**僭越**，全局可见，效果见 §7.5。

### 3.8 郡国分级（派生值，不是新属性）

```
郡等 = 归一化到 1–10 ( 0.45×log(户口) + 0.20×属县数 + 0.15×是否州治 + 0.12×关隘数 + 0.08×地形防御 )
```

**来源**：率土之滨的 1–10 级土地【游戏原创的数值分层】，但**分层这件事本身**对模型很有用——
它把"这个目标值不值得打"压成一个可读的单数。
本项目不凭空造等级表，全部从 `commanderies.json` 的真实户口、属县数和 `terrain-grid.json` 算出来，
零版权风险且有《郡国志》背书。南阳郡（户 528,551，37 县）是 10 级、朔方郡是 1 级，这是算出来的不是编的。

## 四、武将系统

### 4.1 数据来源与规模

`lib/game/data/officers.json` 已有 578 人（含 `affiliation194`、`roles`、`prominence`、`sources`），
但**尚无五维数值**。数值由 `OFFICER-STATS-DESIGN.md` 的五步管线从史料证据推导，本文不重复。

首版入局池：**A 级 60 人（全量属性 + 特技，常驻观测）**，
B 级 120 人（全量属性，按需进观测），C 级 60 人（太守与补充兵将）。合计约 240。

维度：**统率 / 武勇 / 谋略 / 政务 / 名望** 五能力 + **义理** 一倾向，0–100。
它们不是抄光荣，是从下面的岗位表数出来的。

### 4.2 岗位：先有岗位，才有维度

| 岗位 | 每季要做的决策 | 主用维 | 作用面（公式取自 `OFFICER-STATS-DESIGN.md` §3.2） |
| --- | --- | --- | --- |
| **主帅** | 谁带主力、带多少 | 统率 | 部队上限 `4000 + 统率×300`；非战斗减员 `× (1.35 − 统率/145)`；断粮可撑旬数 `1 + ⌊统率/25⌋` |
| **先锋/副将** | 谁去破垒、抢关 | 武勇 | 野战首合冲击 `0.85 + 武勇/330`；强攻折损 `× (1.3 − 武勇/160)` |
| **军师** | 断粮、伏火、离间派谁；情报信到什么程度 | 谋略 | 计略成功 `基础 + (己谋 − 敌主将谋)/220`，钳在 [0.05, 0.9]；情报带宽 `× (1.5 − 谋略/140)` |
| **太守** | 谁治哪个郡 | 政务 | 产出 `× (0.78 + 政务/230)`；可募兵 `× (0.8 + 政务/260)`；城防修筑速度 |
| **都督** | 谁统一个战区 | 统率 + 政务 | 战区内方针执行效率；跨郡调度不消耗 SP |
| **使者** | 谁出使、招降、征辟 | 名望 | 开启外交动作档次；招降 NPC 与在野的成功率 |

六个岗位，五个互不重叠的能力需求（都督是统率与政务的复合）。
**五维是数出来的，不是抄来的。**与光荣重合是收敛的结果。

**幅度上限**：任何单一属性在其全区间（6→99）上，对任一系数的影响不超过 **±35%**。
理由：若一维能造成 3 倍差距，牌面直接决定胜负，模型的决策被淹没，基准失效。

### 4.3 忠诚：把叛变从掷骰改成确定性资源

```
忠诚 = clamp( 50
            + (义理 − 50) × 0.6           // 本性
            + 待遇分                       // 官职、封赏、驻地是否本乡 —— 模型可操作
            + 战绩分                       // 势力近 12 旬胜负、是否连败弃地
            + 君臣纽带分                   // 同乡 / 姻亲 / 故吏 / 举主（可查证的硬史料）
            − 猜忌分                       // 君主「猜忌」特技、同僚被诛
          , 0, 100 )
```

**规则：忠诚 < 30 且持续 3 旬 → 该武将必然出走或叛变（带走驻地部曲的 40%），
且这个状态在观测里对其主公完全可见，从跌破那一刻就可见。**

为什么不掷骰：随机叛变用运气淹没推理（违反 C5）。做成确定性阈值 + 完全可见，
它就变成一道资源管理题——在"把好将放在前线"和"忠诚正在掉"之间权衡，考的是长期规划与风险判断。

**194 年这条规则天然有戏**：袁术麾下同时挂着孙策、周瑜与孙坚旧部（程普、黄盖、韩当、朱治），
按 `scenario-194.json` 的判定孙策本年尚未独立。孙氏一系对袁术的君臣纽带分为负，忠诚天然低位。
接管袁术的模型第一道题就是"这支不属于我的精锐要怎么用、什么时候必须放弃"。
这是史料落到规则上的自然结果，不是设计师编的剧情。

### 4.4 在野与俘虏

**在野池**：按史实登场年入池。`enlist` 的判定是确定性的：

```
可招 ⟺ 势力威望 ≥ 目标名望 × 0.6 + 阈值(method)
      且（同州 或 有举主在册 或 method=厚币且钱足 或 目标为流亡无所依）
      且 目标不因名分路线拒绝（宗室特技者拒绝名分 ≤ −40 的势力）
```

不满足则拒绝，并在回执里给出**缺哪一条**——让模型知道下次该补什么。
`GAMEPLAY-AI-FRIENDLY.md` 原则 7：人才招揽若"投了才知道"就是输出随机；
先公布可招名单与判定条件，它就变成输入随机。

**俘虏**：战败被俘的武将进入对方在押名单，三条处置（`enlist:招降` / 释放 / 斩）。
斩：威望 −6，其旧主势力全员忠诚 +3（同仇），若为汉室名臣则名分 −10。
释放：威望 +2，该将对你的义理关系加一条正向边。
招降：需威望阈值 + 该将义理 < 70 + 其旧主近 12 旬连败。**确定性判定，不掷骰。**

### 4.5 特技

全局 24 条，每人 0–2 条，**全池 ≥ 60% 的人一条也没有**。
特技若人人都有，就从"区分信号"变成"背景噪声"，还白吃 token。

24 条的完整表在 `OFFICER-STATS-DESIGN.md` §6.3，本文不复制。
只重申**唯一一条纪律**：24 条里只有 5 条（断粮 / 举贤 / 说客 / 招降 / 宗室）影响合法动作集，
且都是"在既有模板上放开一个取值"。模板总数永远不变。

**不做战法。** 战法是逐队、逐回合的战斗内选择，一旦引入模型每场仗要做几十次微观决策，
直接违反 C1。战斗由引擎确定性结算，模型的决策点全部在**出兵前**。

### 4.6 姿态：代替战法的那把闸门

`campaign` 的 `posture` 字段，固定 6 个取值（`OFFICER-STATS-DESIGN.md` §6.2 规矩三）：

| 姿态 | 效果 | 代价 |
| --- | --- | --- |
| 强攻 | 攻击 +20% | 折损 +30% |
| 持重 | 折损 −25% | 推进速度 −30% |
| 急行 | 速度 +40% | 遭遇战首合 −20%，粮耗 +30% |
| 掠食 | 就地征粮，粮耗 −60% | 该郡民心 −15，威望 −2/季 |
| 固守 | 防御 +30% | 不推进 |
| 佯动 | 敌方对本军团情报误差 +50% | 无实际推进 |

姿态是 `campaign` 上的**一个字段**，不是六个新模板。特技通过"某姿态对该主将是否可用 /
代价是否减免"发挥作用（如「疾行」使急行的遭遇战惩罚减半）。

### 4.7 成长与死亡

| 项 | 规则 |
| --- | --- |
| 战功成长 | 每维每年最多 +1，终身累计 +6，需在该维绑定的岗位上取得明确战果 |
| 死亡 | **默认按史实卒年**；若史实卒因是战死而该战未在局内发生，改用按年龄的确定性寿命表；局内战死以局内为准 |
| 随机 | **成长与死亡不引入随机数。**随机寿命会给某些席位送运气，污染基准 |

### 4.8 观测里的武将

三档可见性（`OFFICER-STATS-DESIGN.md` §7.1）：

```
己方（精确 + 特技 + 忠诚 + 驻地，约 22 token/人）：
荀彧|41/14/88/93/86|义88|举贤,抚民|忠95|陈留|太守
张辽|72/86/61/38/55|义62|骁锐,骑锋|忠48|下邳|先锋

已接触敌方（区间，无特技无忠诚，约 15 token/人）：
夏侯惇|统65-78/武70-84/谋?/政?/望?|谯|主帅
```

属性效果说明表**只在系统提示里给一次**，不随每季观测重复。这是 token 预算上最划算的一刀。

引擎另附一组**确定性的角色适配分**（主帅/先锋/守将/太守/使者），并明写在观测里。
理由：这些分是属性的确定性函数，任何模型都能自己算，藏起来只会让基准在测心算。
真正要测的是**稀缺下怎么分配**——只有两个能打的人，四条战线，派谁去哪儿。

## 五、军事

### 5.1 空间：关系图，不是坐标

模型**永远看不到经纬度和 330×270 网格**。它看到的是一张预计算的关系图。

新增数据文件 `lib/game/data/adjacency.json`（由 `tools/build-adjacency.mjs` 生成）：

```jsonc
{
  "from": "南阳郡", "to": "京兆尹",
  "via": ["wuguan"],              // 途经的战略节点 id（可为空）
  "terrain": "山道",              // 由 terrain-grid.json 沿边采样得出
  "band": "中",                   // 近/中/远
  "xun": 2,                       // 基础行程旬数
  "bearing": "西北",              // 八方位
  "river": false,                 // 由 hydrology.json 判定是否跨大河
  "capacity": 20000               // 单旬通行兵力上限
}
```

**来源**：SAGA 的 Map-Semantic Scene Graph——论文识别出的第一种失败模式就叫 Scene Blindness，
"原始瓦片坐标缺乏关系语义，agent 在空间上迷失方向"；去掉场景图后最终得分掉 25%。
它们的解法是距离离散成三档、方位显式给出。本项目照做，坐标只留给 PixiJS 渲染层。

**通行容量**是本文的补充【首版取值】，它把地形从"修正系数"变成"结构约束"：

| 边的类型 | capacity（人/旬） |
| --- | --- |
| 平原、官道 | 无限 |
| 关隘（gate） | 20,000 |
| 渡口（ford） | 15,000 |
| 谷道栈道（pass） | **10,000** |

超出容量的兵力滞留一旬。后果：十万大军无法一次通过栈道入蜀——
这是【史实】的地缘约束（蜀道、武关道、井陉），也逼出"要不要分兵"这道题。

战略节点（`strategic-nodes.json`，61 个，其中 45 个 `capturable`）是边上的**独立据点**：
一条边若 `via` 非空，则通过该边必须控制这些节点，或先攻取它们。
关隘守军享 `城防 × 1.6` 且不受兵力规模上限约束地防守——一支小部队能卡住大军。

### 5.2 编成

一支军团（army）：

```jsonc
{
  "id": "a_cao_1",
  "leader": "夏侯惇", "deputies": ["李典"],         // 主将 + 副将 ≤ 2
  "troops": 12000,
  "arm": "长戟",                                    // 主兵种，三选一
  "morale": 78, "fatigue": 12,
  "carried": 24000,                                 // 携粮，上限 = 兵力 × 3 旬
  "at": { "kind": "edge", "from": "东郡", "to": "濮阳", "progress": 0.6 },
  "posture": "持重",
  "directive": { "objective": "破城", "target": "濮阳", "until": {"untilGoal": true} }
}
```

**兵力上限 = 4000 + 主将统率 × 300**。统率 20 → 1 万，统率 95 → 3.25 万。
所以一个十万兵的势力必须编成至少 4 支军团，"谁带哪一支"是真决策。

**出征即锁定**：主将、副将、兵种在 `campaign` 提交时定死，途中不可改。
姿态可以改（`siege_plan` 或下一季的新 `campaign` 覆盖），但要花 SP。

**来源**：《三国志 9》的"阵形出征前选定，出征后不可更改"——这条规则等于把整个战术层从决策集里删掉，
是防微操最有效的一道闸门。副将 ≤2（合计 3 人）取自《三国志 11》的主将 + 副将×2，
而不是 9 代的 5 人，理由纯粹是 token 预算。

### 5.3 行军与补给

**行军**：军团每旬沿边推进，边的 `xun` 为基础耗时，姿态修正：急行 ×0.7、持重 ×1.4、其余 ×1.0。
跨大河无渡口不可行；有渡口则 +1 旬。山道 / 栈道额外受 capacity 约束。

**补给线（兵站）**：军团到其**指定补给源**（己方或同盟控制的郡治或仓城）之间，
**全程经己方或同盟控制据点**的最短路。由引擎每旬重算，`queryPath` 可查。

| 状态 | 结算 |
| --- | --- |
| 连通 | 每旬从补给源扣 `兵力 × 1.0 石 × (1 + 0.15 × 路径旬数)` |
| 断绝 | 先吃携粮（上限 3 旬）；携粮尽后每旬 士气 −12、减员 3% |
| 断绝可撑 | `1 + ⌊主将统率/25⌋` 旬，超过则军团溃散，兵力散失 60%，主将有被俘判定 |
| 掠食姿态 | 无视补给线，粮耗 ×0.4；所在郡民心 −15/季，本方威望 −2/季 |

**来源**：《三国志 14》的兵站是系列里唯一把补给做成一等公民的设计——
"只经过自势力或同盟势力的土地，自动取最短路，连接断开则掉士气并附异常状态"。
由此产生的经典打法是一支缠住、一支绕后掐补给线。

**本项目的关键改动：保留判定，去掉涂色。**
14 代的领地是部队一格一格走过去涂出来的，1 武将 = 1 部队，后期几十支部队每回合都要下令，
玩家最集中的抱怨就是"点击到手累"。
但**补给线的战略价值来自领地连通性，而连通性不必由涂色产生**——
本项目的领地由据点控制权 + 地形加权最短路自动推导（`RESEARCH-2026-08-31.md` §十一已定）。
于是补给线依然是图上可掐的路径，依然是一句可推理可校验的自然语言
（"他在官渡的补给要经过陈留，我从白马插进去就能掐断"），**而涂色的指令量降到零**。
这是把 9 代和 14 代缝在一起的接缝。

### 5.4 野战结算（确定性）

```
效能 E = (士气/100)
       × (0.85 + 统率/280)                 // 主将统率
       × R(己方兵种, 对方兵种)              // 相克，见 5.6
       × T(地形, 己方兵种)                  // 地形对兵种
       × P(姿态)
       × F(特技)
战力 P = 兵力 × E
力量比 r = P_攻 / P_守
```

每合（round）结算，最多 3 合：

```
攻方本合损失率 = 0.06 × r^(−0.8)
守方本合损失率 = 0.06 × r^(+0.8)
各方士气 −= 150 × 本方损失率 + 5
任一方士气 < 30 → 该方溃退，结算追击：突骑追击额外造成 8% 损失，其余兵种 4%
3 合后双方士气均 ≥ 30 → 相持，攻方脱离接触，退回上一据点
```

**验算**（这个模型必须让模型自己能算得出来，否则 9 代范式就退化成掷骰子）：

| r | 攻方累计损失 | 守方累计损失 | 攻方残余士气 | 守方残余士气 | 结果（双方初始士气 80） |
| --- | --- | --- | --- | --- | --- |
| 1.2 | 15.6% | 20.8% | 42 | 34 | 相持，攻方脱离接触 |
| 1.5 | 13.0% | 24.9% | 45 | 28 | 守方第 3 合溃退 |
| 2.0 | 10.3% | 31.3% | 49 | 18 | 守方第 3 合溃退 |
| 3.0 | 5.0% | 28.9% | 63 | 27 | 守方**第 2 合**溃退 |

结论可以压成两句写进系统提示：
**1.5:1 的有效战力优势就足以在一场野战里击溃对手，代价约一成三兵力；
3:1 则两合结束，只折半成。1.2:1 打不动，会变成相持。**
模型据此能自己算"我该不该打"。这正是 §13.2 风险 1 要求验证的性质——
如果结算规则复杂到模型算不清，9 代范式就退化成了掷骰子。

**没有任何随机数。**不确定性全部来自"我不知道对方有多少兵、什么兵种、士气多少"——
这是认识论上的不确定，奖励侦察与推断；不是本体论上的，不奖励祈祷。

### 5.5 攻城结算（确定性）

```
攻方攻力 A = Σ 军团战力 × S(兵种攻城: 长戟 1.0 / 弩阵 1.1 / 突骑 0.6) × P(姿态)
守方守力 D = 戍兵 × (0.82 + 守将统率/280) × (1 + 城防/120) × (1 + 关隘加成)
```

每旬：

```
城防 −= max(0, A/D − 1) × 12
攻方折损 = 兵力 × 0.05 × (D/A) × (1.3 − 主将武勇/160) × P(姿态)
守方折损 = 戍兵 × 0.04 × (A/D)
城防 = 0 且 A > D → 次旬破城
```

**时间窗**：连续 6 旬未破 → 守方修缮完成，城防 += 15（不超原值），攻方疲劳 +20（效能 −10%）。
算下来 `A/D ≥ 2.2` 才能在窗口内破城，`A/D = 3` 约 2.5 旬破城。
与《三国志 9》"攻城通常需三倍兵力，强将可以压低这个倍率"的经验值一致，
但本项目的倍率是从公式推出来的，不是抄的常数。

**围困分支**（`siege_plan`）：

| 方略 | 结算 |
| --- | --- |
| 强攻 | 上面的公式 |
| 围困 | 双方无战损；城内仓储每旬 −戍兵×0.5 石；仓储尽后守军士气 −15/旬；士气 < 20 → 开城或溃散 |
| 断水 | 需控制该郡水系上游节点；守军士气 −8/旬，可与围困叠加 |
| 招降 | 需威望 ≥ 45 且守将忠诚 < 50；确定性判定，成则城与守将一并归附 |
| 撤围 | 解围回撤，攻方疲劳清零 |

**来源**：时间窗取自率土之滨的"城池耐久 60 分钟内未打到 0 则回满"【游戏原创】，
转译成回合制后去掉了真实时间依赖，保留了核心张力——
**必须集中兵力于一个窗口，零敲碎打无效**。这是一道干净的资源权衡题：
把兵摊在三条战线上慢慢磨，还是集中砸一个点？

### 5.6 兵种：三系循环 + 地形耦合

**长戟 > 突骑 > 弩阵 > 长戟**，克制系数 ×1.25 / ÷1.25。

| 地形 | 弩阵 | 长戟 | 突骑 |
| --- | --- | --- | --- |
| 平原 | 1.00 | 1.00 | **1.15** |
| 丘陵 | 1.05 | 1.00 | 0.90 |
| 山地 / 栈道 | **1.10** | 1.00 | **0.70** |
| 水泽 / 渡口 | 0.80 | 0.90 | **0.60** |
| 关隘（守方） | **1.20** | 1.10 | 0.75 |

**来源**：低维循环克制的结构取自《三国群英传》（兵种 + 阵型双层循环）与《三国志曹操传》的三角克制【游戏原创】；
"一张小表就能完整描述"的干净程度取自《三国志 11》的枪 > 骑 > 戟 > 枪。
**数值全部原创**，且刻意不抄任何一作的命名与倍率。

三系是**最小的非平凡博弈结构**，对竞技场有三重价值：
① 动作集 3 选 1，完全可枚举；
② 它是可测的元博弈能力——模型能不能从对手历史选择里推断偏好再做反制，胜率本身就是指标；
③ 天然抗堆数值——没有绝对最优兵种，纯靠资源领先无法碾压。

**叠加地形后，克制从"猜拳"升级成"读地图"**：在栈道上出突骑是自杀，
在关隘前不带弩阵是浪费。而地形数据本项目已经有了。

### 5.7 计略：确定性成功率，随机只在决策之前

```
P = 基础(kind) + (己方军师谋略 − 对方主将谋略) / 220     钳在 [0.05, 0.9]
```

**但 P 不是掷骰的概率，是效果强度的系数。**这是本文对 `OFFICER-STATS-DESIGN.md` §3.2 的收紧：
`GAMEPLAY-AI-FRIENDLY.md` 原则 7 明确禁止"计略随机成功"。所以：

| 计略 | 效果（按 P 线性缩放，无掷骰） |
| --- | --- |
| 断粮 | 目标军团补给线中断 `⌈P × 4⌉` 旬（需「断粮」特技或控制路径上任一节点） |
| 伏火 | 目标军团 士气 −`P×40`、兵力 −`P×12%`（需「火攻」特技，且目标处于林/泽地形或围城中） |
| 离间 | 目标势力指定武将忠诚 −`P×25`（需该武将与其主公无「同乡/姻亲/举主」纽带） |
| 流言 | 目标郡民心 −`P×20`，治安下降 |
| 反间 | 己方被敌方计略的效果减半，持续 4 旬 |
| 诱降 | 目标郡守将忠诚 < 40 时，忠诚再 −`P×30`；跌破 30 则按 §4.3 处理 |

**被计略方在结算后的观测里能看到"我被用了什么计"**，但看不到是谁用的（除非有反间或情报）。
这让计略成为意图雾的一部分，而不是地图黑区。

### 5.8 会战目标：把效用函数明写给模型

每条 `campaign` 必须声明一个 `objective`，引擎自动配上对应的败北条件：

| objective（模型选） | 达成 | 引擎配的败北条件 |
| --- | --- | --- |
| 破城 | 目标据点易主 | 主将阵亡/被俘 · 补给断 3 旬 · 12 旬未达成 |
| 击溃野战主力 | 击溃目标势力在该战区最大军团 | 本方军团溃退 · 主将阵亡 |
| 占领节点 | 拿下指定战略节点 | 8 旬未达成 · 补给断 3 旬 |
| 解围 | 己方被围据点解除围困 | 该据点陷落 |
| 迫降 | 目标势力接受从属或割让 | 12 旬未达成 |

**来源**：《三国志曹操传》的关卡成对胜负条件【游戏原创】。三个好处逐条对应约束：
① 决策变成从有限方略里选一个（C4）；
② **评测粒度从"一局一胜负"细化到"一局二三十场会战"**——一局只有一个最终胜负，
   样本量太小噪声压过信号；有了会战级判据就有了统计功效（C5）；
③ 独立的败北条件意味着高风险打法可能一次崩盘，这是风险判断能力的直接考题。

还有一个被严重低估的贡献：**成对条件等于把效用函数明写给模型**。
LLM 最怕"这仗打成什么样算赢"要靠猜——目标写死之后，表现差异就纯粹来自规划质量，
不再来自对目标的误解。这条直接服务于可比性。

**并且它产出评测指标**：`战役达成率 = 达成的 objective 数 / 声明的 objective 数`。

### 5.9 不做的

| 不做 | 原因 |
| --- | --- |
| 一骑讨 | 【演义】味重，但它是"个人对决裁决集团军胜负"，方差极大且与战略推理无关 |
| 战法 / 心得 / 气力槽 | 逐队逐回合的微观选择，直接违反 C1 |
| 逐格移动、卡位、集火 | 动作空间不可枚举；测的是网格几何不是战略推理 |
| 阵形（9 种 / 13 种） | 与兵种功能重叠；三系循环已经提供了元博弈结构，再加一层只增 token |
| 运输部队 | 补给线自动结算已覆盖，单开运输部队等于逼出微操 |
| 城外建设施（箱庭内政） | 状态爆炸，决策粒度过细 |

## 六、内政

### 6.1 问题的形状

105 个郡国。若照《三国志》系列逐城下令，一个 30 郡的势力每季要点 30 次，
这是"同一决策重复 N 次"的典型形态——N 小的时候有趣，N 大的时候是税。
《三国志 14》玩家最集中的抱怨就是"信息量与武将数暴增难以管理""频繁点击导致手累"，
那还只是 46 城。

**硬规则**（`GAMEPLAY-AI-FRIENDLY.md` §2.3）：
凡是"同一类决策在一个季议内需要做超过 5 次"的机制，
**必须要么合并成一条策略性命令，要么交给确定性引擎自动处理**。

### 6.2 三层委任

```
势力级：国策（4 系 × 3 级）              ← 岁首大议，罕见决策
   ↓
战区级：方针 directive                   ← 每势力 3–5 个战区，standing 常驻
   ↓
郡级：太守按方针自动执行                 ← 引擎跑，模型完全不接触
```

**战区（theater）**：新增 `lib/game/data/theaters.json`，把 13 州归并为 8 个战区：
河北（冀幽并）· 中原（兖豫司隶东）· 关陇（司隶西凉）· 青徐 · 荆襄 · 江淮江东 · 巴蜀汉中 · 交广南中。
一个势力的战区 = 它有郡国的那些战区，通常 1–4 个，上限 5。

**方针 5 档**，每档决定太守把本郡的产能往哪偏：

| 方针 | 郡级自动行为 |
| --- | --- |
| 劝农 | 垦田 +2/旬；粮产偏向；民心 +0.3/旬 |
| 通商 | 商度 +2/旬；钱产偏向 |
| 征兵 | 每季自动募兵至上限的 60%；民心 −0.4/旬 |
| 安民 | 民心 +1.2/旬；治安上升；产出 −10% |
| 修武 | 城防 +2/旬；器械储备 |

**输送策略 3 档**（`transfer`）：不输 / 余粮（超过本郡 6 旬消耗的部分上交） / 全力（留 2 旬）。
战区内自动调度，跨战区需 `reinforce` 或都督在任。

**来源**：《三国志 8 REMAKE》的军团方针 / 都市方针——不消耗战略点，
能分别设定内政优先项、是否补修、金粮兵输送策略。
这就是一套**给 AI 下属的行为指导语**，正是本项目需要的高层命令原语。
《三国志 14》的"地区委任 + 都市内政方针（商业/农业/兵舍/交由官员自行判断）"是同一思路的另一实现。
Stellaris 星区 / EU4 属国是这个模式在 4X 里的通用形态。

### 6.3 保留的单郡动作，以及为什么只保留这三个

| 动作 | 为什么必须留在郡级 |
| --- | --- |
| `levy` 征发 | 它是一次性、高杠杆、有明确代价的赌注（民心换即时资源）。摊到战区级就失去了"在哪个郡竭泽而渔"的判断 |
| `fortify` 修城 | 防御投资的价值高度依赖具体位置（要塞化的是前线还是纵深）。这正是要测的空间判断 |
| `project` 兴修 | 长周期、多前置、罕见。它是长期规划的直接考题 |

这三个都是**低频高杠杆**，不构成重复劳动。其余全部委任。

### 6.4 工程：多前置条件的与门

**来源**：《三国志·战略版》的分城需要同时满足"名声 6000 + 11 块连地呈 H 形 +
中心格 6 级以上 + 木铁石粮各 10 万 + 建造 5 小时"【游戏原创】——
这是一个五条件与门，每一项都要提前很久规划。
本项目把它换成史实感更强的工程，并去掉真实时间依赖。

| 工程 | 前置条件 | 周期 | 效果 |
| --- | --- | --- | --- |
| 屯田 | 该郡民心 ≥ 40、垦田 ≤ 70、太守政务 ≥ 60 或有「屯田」特技、钱 | 4 季 | 该郡粮产 +25%，且不再受民心系数惩罚【史实：枣祗、任峻建议曹操许下屯田】 |
| 修渠 | 郡内有 `hydrology` 干流、政务 ≥ 55、钱、粮 | 6 季 | 该郡及下游郡垦田上限 +20，水患事件损失减半 |
| 盐铁 | 郡在盐铁官所在地（数据可标）、钱 | 4 季 | 该郡钱产 +35% |
| 驿传 | 连接两个己方战区、沿途全部己方控制 | 5 季 | 两战区间跨区调度不消耗 SP；情报老化速度减半 |
| 造船 | 郡临大江大河或海、有港口节点 | 5 季 | 解锁水路行军边；水战地形惩罚减半 |
| 筑关 | 郡内有未占据的天然隘口位（数据可标）、粮钱 | 8 季 | 新增一个己方 `capturable` 关隘节点 |
| 兴学 | 民心 ≥ 60、政务 ≥ 65、名分 ≥ 0 | 6 季 | 该州在野人才每年 +1 名入池；招揽阈值 −10 |

工程一旦开工，**每季自动推进，不需要重复下令**；被攻破或民心 < 25 则中断，已投入不退。

### 6.5 国策：4 系 × 3 级

岁首大议才能推进，每年最多推进 1 级，需要钱粮与前置。

| 系 | 一级 | 二级 | 三级 |
| --- | --- | --- | --- |
| 农战 | 粮产 +8% | 屯田工程周期 −1 季 | 断粮可撑旬数 +2 |
| 通商 | 钱产 +8% | 募兵成本 −15% | 工程周期 −1 季 |
| 兵甲 | 器械：攻城 A +10% | 兵种克制系数 1.25 → 1.32 | 军团兵力上限 +15% |
| 文教 | 招揽阈值 −8 | 情报带宽 −15% | 忠诚基线 +5 |

**来源**：《三国志 11》的技巧研究（8 系 × 4 级，低级不点满高级不开）与
《三国志 14》的"主义 → 政策槽位"【游戏原创】。
砍成 4×3 的理由是 token 与决策频率：11 代的 8 系 32 项对模型是纯记账负担，
而"一年一次、不可逆、影响 10 年后"这个**形状**才是要测的东西——它是长期规划能力的天然测试点。

三级需要"其余任一系已达二级"，逼出取舍而不是全点满。

### 6.6 不做的

| 不做 | 原因 |
| --- | --- |
| 生产队列、建筑队列 | 同一决策重复 N 次的典型形态 |
| 城外摆设施、设施合并升级 | 11 代箱庭内政，状态爆炸 |
| 税率滑条一类连续量 | 连续量对 LLM 是双重问题：不可枚举，且算术不可靠。要么离散成档，要么删掉 |
| 逐郡指定内政项 | 见 §6.1 硬规则 |
| 1180 县作为可操作层 | 推迟。它是次级据点层（对标 13 代的集落），首版不做，见 §10 |

## 七、外交

### 7.1 两个独立通道

```
通道 A：谈判（自由文本 + 结构化承诺）   ← 说什么，不产生状态变更
通道 B：命令（propose / respond / declare / abrogate / vassalage）  ← 做什么，产生状态变更
```

**来源**：Cicero 的意图条件化对话——用计划标注消息，从而能"给定计划生成消息"；
AI_Diplomacy 通过比对谈判内容与实际命令来自动检测背叛。

**分成两通道的理由**：如果承诺只存在于自由文本里，外交能力就只能靠人工阅读评价，无法规模化。
结构化之后，守约率 / 背叛率 / 联盟稳定率全部可以自动算。
**自由文本仍然保留（那是说服力的载体），但评分只认结构化部分。**

### 7.2 条款集（可枚举）

```ts
type Clause =
  | { kind: "ceasefire";      untilCouncil: number }
  | { kind: "nonAggression";  untilCouncil: number }
  | { kind: "alliance";       untilCouncil: number }
  | { kind: "passage";        through: CommanderyId[]; untilCouncil: number }
  | { kind: "cede";           commandery: CommanderyId; byCouncil: number }
  | { kind: "tribute";        grain: number; coin: number; perCouncil: boolean; untilCouncil: number }
  | { kind: "jointAttack";    against: FactionId; onCouncil: number; minForce: TroopBand }
  | { kind: "hostage";        officer: OfficerId }        // 纳质
  | { kind: "marriage";       ourOfficer: OfficerId; theirOfficer: OfficerId }
  | { kind: "recognize";      title: string }             // 承认名号
  | { kind: "vassal";         overlord: FactionId };
```

11 种条款，一份提案最多 4 条。提案 = 有限集合的组合，因此**可枚举可校验**。

**引擎返回逐项估值，而不是黑箱的 yes/no**：

```jsonc
{ "perClause": [ { "clause": {...}, "valueToYou": -180, "valueToThem": +240 } ],
  "net": +60, "hint": "对方近 8 季与你无接壤冲突；其众怒 41 且上升" }
```

估值是**给接收方模型的参考信息**，不是裁决。
**接受与否永远由模型自己决定**——`OFFICER-STATS-DESIGN.md` §3.3 的红线：
任何属性都不得裁决另一个模型的选择。

**来源**：《全面战争：三国》的外交面板【游戏原创】。条款种类有限 → 动作集可枚举（C4）；
逐项估值返回给模型 → 模型可以学着做"最小让步"的反提案，这是能稳定区分强弱推理的任务（C5）；
而且外交状态极小，几十字节就能描述一条盟约（C2）。

**盟约有明确到期回合，续约要重新谈。**这是防止"一次结盟管到底"退化的关键。

### 7.3 谈判轮

| 项 | 规则 |
| --- | --- |
| 轮数 | 岁首大议 2 轮，其余季议 1 轮；若无势力请求谈判则 0 轮 |
| 私信 | 每方每轮 ≤ (N−1) 条，每条 ≤ 300 token，可附结构化承诺 |
| 公开声明 | 每方每轮 1 条，≤ 200 token |
| 发言顺序 | **竞价**：每方出价 0–5 点威望，高者先发言，出价从威望实扣 |
| 可见性 | 私信只对收件方可见；公开声明按竞价顺序依次广播，全部广播完才进入密封下令 |

**来源**：竞价发言取自 Werewolf Arena（Google, 2024）——模型出价决定谁说话，
解决了多方谈判"谁先说"的公平问题。本项目把出价的代价定成威望，让"抢话"有真实价格。

### 7.4 从属：非零和的中间态

`vassalage` 的三种形态：

| 形态 | 条件 | 效果 |
| --- | --- | --- |
| 请附 | 请附方国力指数 < 宗主方 40% | 请附方每季上缴 1/10 粮钱；宗主方获其国力指数的 **40%** 计入自身；请附方保留全部命令权与私有目标 |
| 纳附 | 对方已请附 | 宗主方须为请附方提供"被攻击时 8 旬内出兵"的义务，违约则信义 −20 |
| 解除 | 任一方发起 | 发起方信义 −10；若由宗主方发起则众怒 +5 |

**来源**：《三国志 10》的从属——不灭其国而使其臣服，属国上缴 1/10 收入【游戏原创】。
它给"赢"一个非零和的中间态，让"打不下来但可以吃掉产出"成为真实选项。
对模型竞技场特别有价值：它给弱势席位一条**不是投降也不是灭亡**的路，
这条路本身要求判断（什么时候该低头、向谁低头），而不是躺平。

**40% 的折算比例是刻意低于 100% 的**：从属带来的收益低于直接吞并，
所以从属不是万能解，"要不要打下来"仍是问题。

### 7.5 防止退化为全员围殴领先者

先把问题说准（`GAMEPLAY-AI-FRIENDLY.md` §4.1）：

- **策略性联合**：多方为不输而联合压制领先者。**这是正确的博弈，不该消除。**
- **结构性退化**：只要数值领先就被无条件围殴，最优策略变成"永远做第二名"。**这才是要消除的。**

对基准而言这个区分尤其重要：如果围殴是无成本、自动触发的，
那么"识别领先者"这个零难度任务就主导了结果，基准测的是会不会数数。

六条对策，缺一不可：

**（一）绝对阈值，不是相对排名。**
胜利靠越过绝对线（§9.1），不靠比第二名多。被压到过不了线时结局是和局而非输——
所以领先者有动机接受和局，围殴方也有动机在拿下和局后停手。
**没有 kingmaker**：末位方无法把胜利送给某人，只能影响"有没有人达线"。

**（二）众怒有窗口期。**
众怒 −3/季持续衰减到行为项归零。忍一忍围攻就散了 → 领先者永远有"降温"这个战略选项。
**降温动作是明写的**：停战、释俘、割地、奉诏、罢兵宣示，各降 5–15 点。

**（三）扩张方式影响仇恨。**
奉诏讨伐的兼并仇恨只计 40%；从属代替吞并的仇恨只计 25%；屠城与背盟仇恨最高。
这给模型提供了"低仇恨扩张"的推理空间。

**（四）结盟要付真实资源。**
盟约必须携带至少一条有代价的条款（质子、岁币、割让、联姻、承认名号），
不能是空头的 `alliance` 单条款。免费点击的联盟才会导致自动围殴。

**（五）僭越标记，但留一条投靠强者的路。**
众怒 ≥ 70 → 标记僭越，全局可见。其余势力解锁 `declare:檄文` 指向该方，
且对该方的 `campaign` 众怒计 0。
**但与僭越者结盟并不被禁止**，只是盟友每季威望 −3。
留这条路是刻意的：如果围殴是唯一选项，就又变回结构性退化了。
"是当靶子还是抱大腿"必须是一道真题。

**来源**：僭越取自《三国杀·国战》的野心家（超过总人数一半时其余人的胜利条件改变）【游戏原创】，
史实对应物是讨董联军、衣带诏、赤壁前孙刘联合。
众怒的衰减与折扣取自 EU4 的侵略性扩张【游戏原创】。

**（六）把围殴当指标测量，而不是消除。**
一个模型能否组织起有效的反霸联盟、能否维持它、能否在联盟里不被出卖，本身就是要评的能力。
指标见 §9.3。

### 7.6 背信的全局可见性

```jsonc
"treacheryLog": [
  { "council": 14, "actor": "lubu", "victim": "caocao", "kind": "abrogate|surpriseAttack|clauseBreach", "clause": {...} }
]
```

这条日志**进所有人的观测**，永不删除。信义值随之下降且公开。

**来源**：《全面战争：三国》把背信标记做成对所有势力生效，而不是只被受害者记住。
这是让背叛在博弈论上真正成立的最小机制——如果背叛只被受害者记住，
那么在多方局里背叛几乎总是正收益（打完就换目标）。

`clauseBreach` 由引擎**自动检测**：比对结构化承诺与后续实际命令。
例如承诺 `{kind:"nonAggression", target:"sun", untilCouncil:12}` 而在第 9 季对孙氏发起 `campaign`，
即刻记为背信。这条自动化直接产出"守约率"指标（AI_Diplomacy 的做法）。

现有 `FactionState.trust` 字段已经存在但没有任何机制去动它——这一节正好把它填实。

## 八、信息与视野

### 8.1 三种雾，只选两种

| 类型 | 定义 | 序列化成本 | 博弈深度 | 本项目 |
| --- | --- | --- | --- | --- |
| **意图雾** | 棋盘公开，但不知道对方这季下什么令、许诺算不算数 | 近乎为零 | 极高 | **主力** |
| **棋盘雾** | 看不到对方兵力、位置 | 高 | 中 | **弱化保留**（时效 + 精度分级，不做布尔黑区） |
| **结果雾** | 信息全知但结算随机 | 低 | **负** | **禁止** |

Diplomacy 的设计是这条轴上的最优点：棋盘对所有人完全公开，
不完全信息全部集中在"这一回合别人写了什么命令"和"私聊里的承诺是真是假"上，
所以它的状态序列化非常廉价。
Hanabi 走另一个极端但同样成功：状态极小（一副 50 张牌），推理负担全在信念上。
**共同规律：状态小 + 信念空间大 = 对 LLM 最友好的不完全信息。**

三国题材里"细作"是重要元素，所以棋盘雾保留，但用**时效 + 精度分级**代替能见/不能见的布尔黑区。

### 8.2 可见性矩阵

| 内容 | 可见性 |
| --- | --- |
| 郡国归属、州级版图、各方郡国数与户口总和 | **永远公开且准确** |
| 战略节点归属 | 永远公开且准确 |
| 威望、名分、信义、众怒、爵位、国力指数、僭越标记 | **永远公开且准确**（模型必须能自己算出谁在领先） |
| 公开盟约、宣战、背信日志、公开声明 | 永远公开 |
| 已发生的战报（时间、地点、双方主将、大致规模、结果） | 永远公开 |
| 敌方郡国的戍兵、仓储、民心、城防 | **区间 + 情报时间戳 + staleness** |
| 敌方军团的位置、兵力、兵种、主将 | 区间 + staleness；位置分三档精度 |
| 敌方武将属性 | 区间（带宽由己方军师谋略与情报等级决定） |
| 敌方武将忠诚、精确粮储、国策进度 | **不可见**（除非计略或高级情报） |
| **各方当季命令** | **完全不可观测** |
| **私下承诺是否会兑现** | **完全不可观测** |
| **各方私有目标** | 不可观测，局终全揭示 |

### 8.3 区间档与时效

**兵力档**（固定阶梯，写进系统提示一次）：

```
无 · <1千 · 1–3千 · 3–8千 · 8千–2万 · 2万–5万 · >5万
```

**仓储档**：`匮 · 少 · 足 · 充 · 溢`
**民心/城防档**：`溃 · 弱 · 平 · 固 · 坚`
**位置精度**：`精确据点 · 所在战区 · 未知`

```jsonc
{ "id": "南阳郡", "owner": "liubiao",
  "troops": { "band": "2万-5万", "asOf": "195春", "stale": 3 },
  "granary": { "band": "充", "asOf": "194冬", "stale": 5 },
  "intent": null }
```

**带宽公式**（`OFFICER-STATS-DESIGN.md` §7.2）：

```
档位跨度 = 基础跨度 × (1.5 − 我方军师谋略/140) × 情报等级系数 × (1 + unstable 惩罚)
```

`scout` 动作把目标的 `stale` 归零并把档位跨度收窄一级（`探`）或两级（`细作`，需谋略 ≥ 65）。
每季所有非本方观测 `stale += 1`；`stale > 6` 的条目降为"陈"，档位跨度扩一级。

**这样做的四个好处**：
① 可序列化——每方的观测是同一张表的不同投影，不需要维护平行世界；
② 可复盘——能精确算出某方决策时相信什么，这是评测"信息不完全下决策质量"的前提；
③ 可判定——能算出谁的猜测更接近真相，变成一个独立能力指标；
④ token 友好——区间 + 时间戳比精确数值更短，且强制模型做区间推理。

### 8.5 token 预算

| 段 | 估计 token | 上限 |
| --- | --- | --- |
| council + you | 380 | 500 |
| standings（≤12 行） | 260 | 350 |
| events + lastOutcome | 380 | 500 |
| theaters（≤28 个郡国行 × ~35 token） | 1,050 | 1,500 |
| armies（己方 ≤6 + 已知敌方 ≤10） | 490 | 700 |
| officers（己方 ≤20 + 已知 ≤12 + 可招 ≤6） | 620 | 800 |
| diplomacy | 300 | 450 |
| legalActions（≈98 条 × 25 token） | 2,450 | **3,000** |
| queries | 60 | 80 |
| **合计** | **≈ 5,990** | **硬上限 7,880** |

**依据**：SAGA 的 Context Overflow 失败模式触发线是整包状态倾倒超过每回合 15,000 token；
本项目取其一半以下（6,000）作安全边界，硬上限 8,000。
系统提示（规则说明、公式表、属性效果表、档位阶梯、唤醒条件表）另计约 3,500 token，
**只在对局开始时给一次，全程 KV 缓存**，不随季议重复。

超预算时的降级顺序（写死）：
`known officers → armies(敌方) → theaters(非相邻战区) → standings(聚合成行) → legalActions(按 §2.4 裁剪)`。
**legalActions 永远最后才裁**，因为它是可校验性的根基。

### 8.6 工具化拉取

每次决策给 **8 次查询配额**。查询本身是被测的能力——会不会查、查什么、是不是乱查。

| 工具 | 参数 | 返回 |
| --- | --- | --- |
| `queryCommandery` | id | 该郡全部可见字段 + 邻接全表 + 历史归属 |
| `queryArmy` | id | 该军团可见字段 + 推定补给路径 |
| `queryOfficer` | id | 该武将可见字段 + 关系边 |
| `queryRelation` | a, b | 两势力间全部盟约、交战史、承诺与履约记录 |
| `queryNode` | id | 战略节点归属、守军、控制该节点封锁的边 |
| `queryPath` | from, to | 最短路径、途经节点、通行容量瓶颈、是否全程己方控制 |
| `queryProject` | — | 本方可启动工程与各自缺哪一条前置 |
| `queryActions` | category | 被裁剪掉的那一类动作全集 |
| `queryHistory` | councils | 最近 N 季的战报与外交事件 |

**来源**：SAGA 的 Tool-Augmented Strategic Pipeline——消融显示去掉工具化查询最终得分掉 49%，
采用后输出 token 反而降 27%（109k vs 149k）。这是整份调研里投入产出比最高的工程手段之一。

```jsonc

  "orders": [ { "actionId": "a17", "params": { "leader":"夏侯惇","strength":"七成",
                                               "arm":"长戟","posture":"持重","objective":"破城" } } ],
```

`beliefs` 与 `intent.milestones` **不影响结算**，纯粹是为了让"情报准确度"和"计划兑现度"
两个指标可算。它们是必填字段（可以为空数组，空则该指标不计分也不扣分）。

**来源**：Cicero 用自动标注把消息与计划动作关联起来，从而能"给定计划生成消息"。
反过来用在评测上：既然消息可以被计划条件化，那么消息与实际命令的一致性就可以被自动测量。

### 8.8 去三国化对照组

三国题材的**数据污染风险极高**——所有模型都读过《三国演义》和大量三国攻略，
可能不是在推理，而是在回忆"曹操该打吕布"。

必须准备一个同构变体：势力改名（甲乙丙丁）、郡国改编号、武将改代号，
**地形、邻接、户口、属性、初始归属完全不变**。
有名版与无名版的分差本身就是一个有价值的指标——差得多说明测的是记忆不是推理。

实现上这是一个纯粹的 **id → 显示名映射层**，不动任何规则，成本极低。
必须在第一版就留出这个接口，否则后期改会牵动全部序列化代码。

**来源**：lmgame-Bench 的污染干预（实体遮蔽、改写、去元数据）。

## 九、胜负与评分

### 9.1 国力指数：唯一的公开进度条

```
汉地 = 105 郡国 − 15 个异民族控制郡（鲜卑 5、乌桓 3、匈奴 2、羌胡 3、南中夷 2）= 90 郡国
```

**来源**：《三国志 9》的"空白城与异民族城不必占领"。这一条被低估——
它把"统一"从"清空地图"改成"消灭对手"，直接砍掉一局末尾几十回合的收尾作业（C6）。
异民族郡仍可攻取，但只按 0.3 权重计入，且攻取产生众怒。

```
国力指数 PI = 0.50 × (本方汉地户口 / 汉地总户口)
            + 0.30 × (本方汉地郡国数 / 90)
            + 0.20 × (本方可占战略节点数 / 45)
从属方按其 PI 的 40% 计入宗主方
```

**为什么不是单看郡国数**（`GAMEPLAY-AI-FRIENDLY.md` §10 自己标了这条待验证）：
用真实数据一算就知道单一口径都不成立——

| 势力 | 郡国 | 户口 | 户口份额 |
| --- | --- | --- | --- |
| 刘表 | 7 | 1,399,394 | 15.1% |
| 袁绍 | 13 | 1,280,952 | 13.8% |
| **李傕** | **8** | **113,883** | **1.2%** |

李傕据三辅八郡但户口只有 1.2%（凉州与三辅诸郡本就户少，且经董卓之乱残破），
只看郡国数会把他算成第三强；只看户口又会漏掉他挟天子据关中要害这件事。
三项加权，加上名分与爵位另算，才勉强对得上直觉。**这个权重必须靠自对局标定。**

### 9.2 胜利条件

| 档 | 条件 | 结算 |
| --- | --- | --- |
| **克定**（单独获胜） | PI ≥ **40%** 且控制 ≥ 4 个州治 | 立即结束，该方独胜 |
| **一等霸业** | 控制 ≥ 3 个州的过半郡国，且据有河北或关中其一的州治 | 60 季结束时按此排名 |
| **二等霸业** | 控制 ≥ 2 个州的过半郡国 | 同上 |
| **三等霸业** | 控制 ≥ 1 个州的过半郡国 | 同上 |
| **和局** | 60 季结束无人克定；或全体同意"共尊天子" | 按综合分排名，第一名记"优势和局"，评分权重低于单独获胜 |
| **僵局** | 连续 8 季无领土与盟约变动 | 按综合分排名 |

**PI ≥ 40% 是【待验证】的。**它对齐 Diplomacy 的 18/34 ≈ 53%（那是纯计数），
换成加权指数后 40% 大致相当于"独占中原 + 河北"或"荆益 + 江东"。
必须用固定脚本策略跑 ≥ 200 局仿真，看这条线的达成率落在 15%–35% 之间（太低则永远和局，太高则围殴机制失效）。

**综合分**（用于和局与僵局排名）：

```
综合分 = 0.45 × PI
       + 0.15 × 威望/100
       + 0.15 × 存续度（未失郡国比例 × 未被从属）
       + 0.25 × 私有目标达成率
```

**私有目标**：每方开局从 12 条的公开池里抽 2 条，内容对己方可见、对他方不可见，局终全揭示。
例：`据有河北四州` · `迎奉天子` · `三年不失一郡` · `与两家结盟且皆未背盟` ·
`控制敖仓与黎阳仓` · `使某方从属而不灭之` · `名分始终 ≥ +50` · `不使用掠食姿态而胜`。

**来源**：绝对阈值 + 允许和局取自 Diplomacy；分级档位取自率土之滨 / 三国志·战略版的赛季结算
（占 1 州府 = 三等，占州府 + 洛阳 = 二等，占 3 州府 + 洛阳 = 一等）【游戏原创】。
**但本项目不设洛阳为终局目标点**——194 年洛阳已被董卓焚毁、朝廷西迁长安，
照抄率土的洛阳目标与本剧本冲突。改用州治数判据。
私有目标取自 Root / COIN 系列的非对称胜利路径与 Ankh-Morpork / Argent 的秘密胜利条件。

**部分隐藏与可复盘的张力**（`GAMEPLAY-AI-FRIENDLY.md` §10 第 4 条）：私有目标让第三方观众
难以实时判断谁下得好。解法是**赛后全揭示 + 回放视图逐季重放每方当时的观测**，
而不是减少隐藏信息。

### 9.3 用于比较模型强弱的多维评分

只有胜率的话，一局 = 1 bit，统计功效极低。所以除排名外必须有过程指标。

| # | 指标 | 定义 | 测什么 |
| --- | --- | --- | --- |
| 1 | **TrueSkill 分** | 由每局名次更新（一局多人、非二元结果，Elo 不适用） | 综合强弱 |
| 2 | **IAR 无效动作率** | 通不过 schema 或规则校验的命令 / 提交总数 | 可靠性。**模型间差距最先显现的地方** |
| 3 | **落地准确率 GA** | 校验通过且产生预期效果的命令比例 | 对规则的理解 |
| 4 | **守约率** | 履行的结构化承诺 / 承诺总数（引擎自动比对） | 外交可信度 |
| 5 | **主动背叛数 / 被背叛数** | 背信日志计数 | 博弈风格画像 |
| 6 | **联盟一致性 CCC / 稳定率 ASR / 持续时长 AD / 双边互动率 BIR** | DSGBench 的 Diplomacy 指标 | 组织与维持联盟的能力 |
| 7 | **情报准确度** | `beliefs` 中兵力档与真值的档距、`nextTarget` 命中率 | 信息不完全下的推断质量 |
| 8 | **计划兑现度** | `intent.milestones` 按期达成比例 | 长期规划 |
| 9 | **战役达成率** | 达成的 `objective` / 声明的 `objective`（§5.8） | 战术层规划。**一局有二三十场会战，统计功效远高于一个最终胜负** |
| 10 | **资源效率** | ΔPI / 消耗的粮钱 | 资源权衡 |
| 11 | **风险画像** | 高风险 objective 的选择频率 × 达成率 | 风险判断 |
| 12 | **决策成本** | token/季、查询配额使用率、墙钟 | 性价比 |
| 13 | **去三国化分差** | 有名版分数 − 无名版分数 | 是不是在背书而不是推理 |
| 14 | **对手泛化** | 对固定规则型 AI 的成绩 vs 对模型的成绩 | 是否只在特定对手风格下有效 |

**赛制**：
- **席位轮换**：同一批模型跑 N 局，每局轮换势力分配，保证每个模型在每个势力上都跑过。
  这条比调数值更重要——`OFFICER-STATS-DESIGN.md` §9 的结论是
  **"牌面不平衡不该靠改数值来修，该靠赛制修"**，一旦接受这条，
  就不必为了平衡去动从史料推出来的数字。
- **多局中位数**，不是均值。
- **prompt 标准化**：所有模型用完全相同的系统提示与观测格式，禁止针对性调优。
- **排名只认史实档**（见 §10.5），演义档用于对外展示。

**来源**：DSGBench 的过程指标体系；MINDGAMES 的 TrueSkill + 席位轮换；
lmgame-Bench 的 prompt 标准化与污染干预；Melting Pot 的 focal / background population 泛化思路。

### 9.4 让推理而非运气主导：随机性的放置表

| 位置 | 放不放 | 理由 |
| --- | --- | --- |
| 开局势力分配 | **放**（且强制轮换） | 输入随机；同时是去座位偏置的必要手段 |
| 每季天时 / 灾异（**先公布再决策**） | **放** | 输入随机；制造"同一局面不同应对"的可比较场景 |
| 情报的时效与精度 | **放** | 输入随机；制造信息不完全的深度 |
| 可招揽人才名单的刷新 | **放**（先公布名单与判定条件） | 若"投了才知道"就变成输出随机 |
| 私有目标的抽取 | **放** | 输入随机 |
| **战斗结算** | **不放** | 输出随机的最典型形态，直接掩盖战略判断 |
| **命令是否执行成功** | **不放** | 会让"我的推理对不对"变成无法复盘的问题 |
| **计略是否成功** | **不放** | 改为效果强度按 P 线性缩放（§5.7） |
| **谈判是否被接受** | **不放** | 应由对方模型决定，不该由骰子决定 |
| **叛变、寿命、成长** | **不放** | 确定性阈值 + 完全可见（§4.3、§4.7） |

Diplomacy 全程无随机仍有极高深度，这证明战略游戏并不需要输出随机。

### 10.1 判据

其余一律推迟。

### 10.3 M1 —— 可玩切片：中原六家

**范围收缩到能跑通全链路的最小规模，但每个子系统都是最终形态而不是占位。**

| 维度 | M1 | 完整版 |
| --- | --- | --- |
| 地图 | 兖·豫·徐·青·冀南·荆北，约 **40 郡国** + 20 个战略节点 | 105 + 45 |
| 席位 | 曹操 · 吕布 · 袁绍 · 袁术 · 刘备 · 刘表，**6 家由模型控制** | 6 模型 + 25 NPC |
| NPC | 该范围内的其余势力冻结为静态守军 | 规则驱动的完整行为 |
| 局长 | **24 季（6 年，194–200）** | 60 季 |
| 武将 | A 级 **60 人** | 240 |
| 动作模板 | **13 个**：campaign · reinforce · siege_plan · fortify · recall · directive · levy · appoint · propose · respond · declare · scout · pass | 20 |
| 资源 | 粮 · 钱 · 兵 · 民心 · 威望 · 信义 | + 名分 · 众怒 · 爵位 · 国策 |
| 战斗 | 野战 + 攻城全公式（§5.4、§5.5），三兵种 + 地形 | 同 |
| 补给 | 完整兵站判定 | 同 |
| 外交 | 结构化条款 + 逐项估值；**不做自由文本谈判轮** | + 谈判轮 + 竞价发言 |
| 情报 | 区间 + staleness + scout | + 计略影响情报 |
| 终局 | 分级判据（州过半） | + 克定阈值 + 私有目标 |
| 评分 | TrueSkill · IAR · 守约率 · 战役达成率 · 情报准确度 · 决策成本 | 全部 14 项 |

**为什么是中原六家**：
① 六家彼此接壤，连地约束下每家的边界郡国 3–8 个，动作集规模正好落在设计值上；
② 牌面差异极端且都有史料支撑——曹操人才过剩而无地、袁绍资源过剩而决策带宽稀缺、
   吕布是一把锤子、袁术攥着不属于自己的孙氏精锐（`OFFICER-STATS-DESIGN.md` §9 的七道考题里的五道）；
③ 6 年 24 季足够打完两三轮兼并，能验证"更强推理是否稳定转化为更好结果"，又不至于一局跑一整天；
④ 这块地形有平原、有大河（黄河故道）、有关隘（虎牢、白马、延津），三兵种与地形耦合能真正生效。

**M1 的验收标准**（不是"能跑"，是"能测出东西"）：

1. 同一批模型跑 12 局（席位轮换 2 轮），TrueSkill 排名的置信区间不重叠的模型对 ≥ 50%。
2. IAR < 5%（若高于此，说明动作枚举或校验反馈有问题，不是模型的问题）。
3. 用中等能力模型做人工抽查：给它 §5.4 的公式和一个具体局面，
   它能正确预测野战胜负方向 ≥ 80%。**这条不过就说明 9 代范式退化成了掷骰子，必须回头改结算。**
4. 单局总 token < 400k，墙钟 < 40 分钟。
5. 属性解释力：固定脚本策略 200 局，初始属性优势对胜负的解释方差落在 25%–40%。

### 10.4 M2 —— 博弈层

按价值排序，全部是"让对局有博弈内容"的东西：

1. **自由文本谈判轮 + 竞价发言 + 结构化承诺自动比对**（守约率、背叛率、联盟指标）
2. **名分路线值 + 爵位阶梯 + `court` 动作**（长期规划的分支考题）
3. **众怒与僭越标记**（反滚雪球）
4. **`scheme` 计略六种**（意图雾的第二层）
5. **`vassalage` 从属**（非零和中间态）
6. **私有目标**（让"谁在领先"成为需要推理的问题）
7. **`project` 工程 + 国策 4×3**（多前置与门）

### 10.5 M3 —— 全图与全势力

1. 扩到 105 郡国 / 45 节点 / 60 季 / 240 武将
2. 25 家 NPC 势力的**确定性规则行为**（不调模型）。这是全图版最大的未知：
   NPC 太弱则模型碾压，太强则噪声压过推理差距
3. 异民族势力与羁縻规则
4. **史实档 / 演义档双轨**：同一状态两套 resolve，`observe / decide / validate` 完全不变。
   史实档低方差用于排名，演义档保留戏剧性事件用于展示

**来源**：双轨结构取自《全面战争：三国》的 Records / Romance【游戏原创的架构，不是它的语义】。
TW3K 的双轨是"武将要不要超人化"，本项目重新定义为**随机性与信息量的两档**。

### 10.6 M4 —— 竞技场化

1. 去三国化对照组（id → 显示名映射层，M0 就要留接口）
2. 席位轮换调度器 + TrueSkill + 多局中位数
3. 回放视图：逐季重放每方**当时的观测**（这是私有目标可复盘的前提）
4. 对手泛化组：模型 vs 固定规则型 AI
5. A/B：有谈判 vs 无谈判（SPIN-Bench 发现引入谈判后 o1 表现反而下降，本项目规则下是否同样，未知）

## 十二、主动舍弃的机制，以及舍弃理由

分四类。**这一节和上一节同等重要**——没做什么和做了什么一样定义这个设计。

### 12.1 与"高层战略"冲突（C1）

| 舍弃 | 出处 | 理由 |
| --- | --- | --- |
| 逐部队在格子上移动、卡位、集火 | 《三国志 11 / 14》 | 动作空间是"部队数 × 可达格数 × 指令类型"的笛卡尔积，不可枚举。而且赢下 11 代靠的是空间战术微操——既不是要测的能力，又恰是 LLM 最弱的能力。**真按 11 代做，测出来的排名是"哪个模型更擅长网格几何"** |
| 地区涂色作为操作 | 《三国志 14》 | 只保留其结算含义（领地连通性），不保留其操作形式。14 代玩家最集中的抱怨就是"点击到手累" |
| 箱庭内政（在图上摆设施、合并升级） | 《三国志 11》 | 状态爆炸，决策粒度过细 |

### 13.2 结构性风险（可能整块设计是错的）

1. **自动战斗的可推演性。** 9 代范式的价值全押在"模型能预判结算结果"上。
   §5.4 给了验算表，但**必须在 M1 用真实模型验证 §10.3 验收标准第 3 条**。
   若中等模型预测胜负方向准确率低于 80%，说明结算太复杂，9 代范式退化成掷骰子，C5 直接失败。
   届时的退路是进一步简化公式（比如去掉疲劳与特技项），而不是加随机。

2. **方针语言的表达力。** 8 REMAKE 的都市方针只有寥寥几档。
   本项目 5 档方针 × 3 档输送，覆盖 105 郡国够不够，未知。
   若模型频繁抱怨"我想让这个郡做别的但没有选项"，说明档位不够。

3. **NPC 势力的行为质量。** 25 家 NPC 用确定性规则驱动。
   太弱则模型碾压（噪声），太强则压过推理差距（也是噪声）。这是 M3 最大的未知。

4. **谈判是否反而拖垮战略表现。** SPIN-Bench 发现引入谈判后 o1 的各类命令表现反而下降，
   补给中心增长显著变差，归因于"延展推理链与实时结盟的认知开销之间的张力"。
   本项目规则下是否同样，未知。**M4 必须做 A/B。**

5. **私有目标与可复盘的张力。** 隐藏信息越多，第三方观众越难判断谁下得好。
   靠"赛后全揭示 + 逐季重放当时观测"缓解，但这条能否真的成立需要实测。

6. **两级枚举是否会让模型在第二级出错。** 第一级选对了但参数填错（比如派了不在该据点的主将），
   会体现为 IAR 上升。若 IAR 主要来自第二级，说明参数域的呈现方式有问题，
   可能要把高频组合（如 campaign 的主将 × 兵力）也展开到第一级。

### 13.3 事实层面的不确定

1. **`K_grain = 0.09` 与 `K_coin = 4` 的史料依据是量级估算，不是精确考证。**
   汉代一户年产粟、田租实际征收率、算赋的实际入库比例，学界都有分歧。
   这两个常数的价值在于"能让 194 年各势力的兵力上限对得上史料记载的量级"，
   不在于它们是准确的经济史数字。

2. **`commanderies.json` 的户口是《续汉书·郡国志》永和五年（140 年）断面**，
   与 194 年的实况差异极大（河南尹已被焚毁、关中残破、荆益相对完好）。
   本设计把它当作**相对量级参照**而非绝对值。
   若要更准，需要给每郡加一个 194 年的"残破系数"，但那个系数没有可靠史料，只能是设计判断——
   **首版不做，宁可承认误差也不编数据。**

3. **`officers.json` 目前 578 人只有 `roles` 与 `prominence`，没有五维数值。**
   本文的所有武将相关公式在 `tools/build-officers.mjs` 产出前都无法实跑。

4. **战区归并（13 州 → 8 战区）的分界是设计判断，不是史料。**
   并州归河北还是关陇尤其可争议——太行以西但通过井陉、壶关与河北相连。
   首版归河北，理由是 194 年并州南部实际受制于河北与关中两方。

5. **通行容量的具体数值（栈道 1 万、关隘 2 万、渡口 1.5 万）没有史料依据。**
   "蜀道难以通过大军"是史实共识，但具体到人数是纯设计取值。

6. **《三国志 9》"一回合可行动次数 ≈ 麾下武将数"这个说法未从官方手册核实**
   （`GAMEPLAY-RTK-SERIES.md` §十一已标）。本项目的 SP 公式不依赖它，只借"有预算"这个思路。
