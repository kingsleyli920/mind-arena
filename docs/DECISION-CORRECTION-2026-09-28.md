# 命令收据后的模型纠错实测（2026-09-28）

## 测试约定（在付费请求前固定）

问题：模型能否结合上季命令收据，修正已观察到的计划错误？

从此前真实响应结算后的自然状态继续，每例只调用原模型一季；其他势力仍由免费机器人控制。
旧计划是模型自身上一季的产物；其更早一季来自原对照试验的人工预设冲突计划，不能视为长期自然模型对局。

每例两个独立分支，使用相同模型、提供方、战局、旧计划、system、候选 schema 和推理设置：

- `legacy`：保留原有 `droppedLastSeason`，不传新收据。
- `receipt`：使用产品当前的 `decisionLastSeason`，包含采纳、拒绝及客观核对提示。

去掉这两个反馈字段后，输入必须完全一致。两组都使用当前 prompt 1.19.0；这不是新旧提示词的整体比较。
固定三个局面，共六次决策，不因结果不理想追加样本。交替先后顺序；每例每条件仅一次，不能推出统计可靠性或模型排名。

| 局面 | 模型 | 决策前事实 | 人工核对重点 |
|---|---|---|---|
| 公孙度多线战局下一季 | GPT-5 Nano | 辽西已属己方；前季主力进攻采纳、同源倾国进攻拒绝 | 是否停止声称辽西未得；是否调整目标/状态；是否再出同源冲突命令 |
| 刘备围城战局下一季 | GPT-5 Nano | 前季攻东海及建官府被令数上限拒绝；本季已无己方野战军；任城已取得 | 是否把未采纳的出兵或建设当作已完成；是否仍安排超额命令；状态和实际动作是否一致 |
| 刘备失治所战局下一季 | Gemini 2.5 Flash-Lite | 上季已迁治广陵，广陵仍在；东海仍属敌方；刘备调任命令未采纳 | 是否正确承认现治所；是否虚构上季调任或命令成功；是否更新计划/状态 |

同时记录准入数、丢令原因、客观核对提示和实际一季结算。没有重复警告不等于策略正确；不提某事实也不等于承认或否认。
对可自由选择的目标、止损条件等做人工说明，不通过关键词自动给棋力打分。

费用：只允许 OpenAI 的 Nano 和 Google 的 Flash-Lite，先查询端点价格并检查白名单。
单决策最多两次传输尝试，输出最多 8000 tokens，输入最多 70 KB，整批预留费用上限 $0.20。
无响应时保留整笔预留并停止整批；不触发额外的付费纠错循环。

## 运行方法

默认预检及重放均不请求模型；输出目录必须不存在既有 `report.json`，防止覆盖结果并重复消费。

```bash
node --experimental-strip-types tools/decision-correction.mjs --out /tmp/correction-preflight
node --env-file-if-exists=.env.local --experimental-strip-types tools/decision-correction.mjs --live --out /tmp/correction-live
node --experimental-strip-types tools/decision-correction.mjs --replay /tmp/correction-live/report.json --out /tmp/correction-replay
```

## 实测结果

**收据进入真实请求，但这轮没有证明低成本模型能稳定纠错。** 没有修改产品提示词、引擎规则、默认模型或触发自动重试。

六次决策均成功，八次传输尝试（Nano 前两次各发生一次去 temperature 降级），全部结构化输出、正常 stop。
Nano 最终均为 `schema-notemp`，Flash-Lite 为 `schema`，同一对的档位相同。
上报费用 **$0.01073378**，计入未知失败尝试后的保守占用 **$0.02283123**，均低于 $0.20。
端点价格在调用前确认，实际提供方分别为 OpenAI、Google。

| 局面 | legacy 采纳/拒绝 | receipt 采纳/拒绝 | 读完原文后的结论 |
|---|---:|---:|---|
| Nano 多线 | 3 / 2 | 4 / 1 | 两组都仍把自己的辽西当作进攻目标；收据组再次选择同源主力和倾国命令，并声称“完成两条并行征伐”，实际只有一条获采纳。错误未纠正。 |
| Nano 围城 | 5 / 0 | 5 / 0 | 两组都让此前被拒的东海征伐获采纳，无法归因于新收据。两组仍写“巩固东莱围城后方补给”，但决策时已无己方野战军；收据组还写在下邳兴建已存在的仓廪/铁官，实际选择的是彭城铁官。 |
| Flash-Lite 迁治 | 6 / 1 | 6 / 2 | 收据组明确写“广陵郡（我方治所）”，对照组仍用东海失守解释当前全境断供。收据组仍把更早的东海失守写成“上季”，并选择两个超出令数的内政命令。两组最后获采纳的动作相同，完整结算状态也相同。 |

逐例人工判读的边界：

- 多线收据组从辽西出兵至辽东属国，计划却描述“对辽西郡发起两路并进攻”。这既有地点不一致，也有采纳数量不一致。对照组原样重复“辽西尚未取得”。
- 围城两组都没有明确复核上季的拒令、任城新得和围城军消失。不能仅因本季攻击获采纳，就判定模型理解了上季拒令原因。两组本季最终都失去九江、任城；这是短期结果，不是棋力排名。
- 迁治决策前，结构化事实为治所在广陵、广陵仍属己方，只有琅邪 `supplyCut=true`。上季文字战报中同时保留了结算途中旧治所失守及季末迁治成功的消息；收据组认出了现治所，但时间叙述仍有混淆。
- 全部六份状态仍为 `continue`；这一轮每例的结构化 target/stance 都没有改变，因此不能把六个 `continue` 全算作状态错误。收据组 Flash-Lite 的原文又写“本季以守势为主”，而 stance 仍为 attack，需结合准备反攻的上下文人工理解。
- 两份 Flash-Lite 原始 review 分别 183、188 字，存储按既有协议截到 160 字。上述人工审阅使用完整原文；不能把被截掉的结尾说成下一季模型已能看到。

总计对照组采纳 14、拒绝 3；收据组采纳 15、拒绝 3。拒令未归零。
收据组有两个分支没有客观警告，但上述计划文字仍有问题；**无警告不代表计划正确**。
所有采纳命令进入实际一季结算，结算再次拒绝为 0。观测估算峰值 8715；不含 system/schema 的完整请求 tokens，不能与提供方总输入 token 混用。

- 默认免费预检：六个分支通过；每对规范化输入完全一致，只移除 `decisionLastSeason` / `droppedLastSeason` 两字段后比较。

## 对项目的判断

命令校验可以守住游戏规则，收据也能让人看出哪些指令没执行；但便宜模型的计划文字仍不能当作可信的战略复盘。
本轮最明确的剩余问题是：**模型没有稳定地把当前事实、过去的结果和本季实际下令对应起来。**
后续优化应围绕这三者的对应关系与计划更新做有限实验，再用固定局面对照验收；当前证据不足以支持扩大为全 AI 长局或直接宣布提高棋力。
